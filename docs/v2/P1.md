# P1　最小对话回合：可持久的浏览器对话

> **已迁移（2026-10-21）：** 现行版本在 [YUVI_NEXT](https://github.com/Ruichen-0079/YUVI_NEXT)（`docs/`）。本文件保留为历史，不再更新。

> 周期 C1 的第一个工作包。实施：Sol。验收：Claude。背景只需读本文件；架构背景见[蓝图](YUVI_V2_BLUEPRINT.md) §3.2 与附录 C.1、C.2、C.5（只作参考，以本文件为准）。

## 1. 目标

P1 完成后，V2 第一次成为一个能用的东西：

- 一个常驻进程，在浏览器里与 YUVI 文字对话，回复流式出现；
- 每一句话（你的与它的）按时间写入一个只追加的 SQLite 档案；
- 进程重启后对话不丢，而且模型能看到之前的对话；
- 模型调用失败或进程中途崩溃时，系统如实记录，不伪造回复，也不伪装成沉默。

## 2. 范围

### 必须完成

1. **进程。** 一个 Node.js（≥ 22）+ TypeScript 的常驻进程。所有状态在 `YUVI_DATA_DIR` 下的一个 SQLite 文件里。
2. **档案。**
   - 一张只追加的事件表，至少包含 §3.2 列出的字段。
   - 在数据库层面拒绝对已有事件的 `UPDATE` 与 `DELETE`（例如用触发器）。
3. **一个回合：**
   1. 收到消息后，**先**写入一条 `experience/heard` 事件，再调用模型；
   2. 用人设文件和本场景最近的事件组装上下文（§3.3）；
   3. 以流式调用一个 OpenAI 兼容的 Chat Completions 接口，把增量实时推给客户端；
   4. 完整生成后，写入一条 `act/said` 事件，`reply_to` 指向对应的 `heard`。
4. **失败与中断。**
   - **模型调用失败**（HTTP 错误、超时、流中断）：写一条 `control/error`，客户端收到明确的错误，不写 `said`。
   - **进程在生成中被杀死：** 重启时，对每条“没有 `said` 也没有 `error`”的 `heard`，补写一条 `control/error`（`meta.reason = "interrupted"`）。不重新生成，也不补发回复。
5. **顺序。** 同一场景的消息按到达顺序串行处理；生成期间到达的消息排队，不丢弃，也不并发生成。
6. **网页。**
   - 进程在 `/` 提供一个最小的单页：输入框、对话列表、流式显示。
   - 打开页面时显示已有历史。
   - 不需要框架和样式工作。
7. **测试。** `npm test` 离线可运行，不需要网络和真实模型。测试中的假模型服务由 Sol 自己实现。
8. **说明。** `v2/README.md` 写明怎样启动、配置和测试；`v2/NOTES.md` 写明重要的实现选择与对本文件的偏离（不超过一页）。

### 明确不做

记忆整理与回忆、`recall` / `check`、任何工具调用、沉默工具、主动开口、心意、QQ、语音、Live2D、看图、V1 数据导入、潜在组织、多用户与登录、Tauri、打包、systemd 部署、备份（P3 做）、费用计（P2 做）、上下文压缩或摘要、任何语义标注（情绪、意图、重要性）。

## 3. 接口与约束

以下是 Claude 验收要用到的**对外约定**，必须照此实现。其余一律由 Sol 决定。

### 3.1 配置（环境变量）

| 变量                      | 含义                                | 默认                 |
| ------------------------- | ----------------------------------- | -------------------- |
| `YUVI_DATA_DIR`           | 数据目录，SQLite 文件放在其中       | 必填                 |
| `YUVI_MODEL_BASE_URL`     | OpenAI 兼容接口的基地址（含 `/v1`） | 必填                 |
| `YUVI_MODEL_API_KEY`      | 密钥                                | 必填（假服务可任意） |
| `YUVI_MODEL`              | 模型名                              | 必填                 |
| `YUVI_PERSONA_FILE`       | 人设文本文件路径                    | 必填                 |
| `YUVI_HOST` / `YUVI_PORT` | 监听地址                            | `127.0.0.1` / `8787` |
| `YUVI_CONTEXT_EVENTS`     | 上下文中最多包含的最近事件数        | `200`                |

### 3.2 事件字段（`GET /api/events` 返回的 JSON 中必须出现）

`seq`（整数，递增）、`id`（字符串，唯一）、`branch`（P1 恒为 `"dev:v2-dev"`）、`class`（`experience` / `act` / `inner` / `control`）、`kind`、`scene`（P1 恒为 `"web"`）、`actor`（你的消息为 `"owner"`，它的回复为 `"yuvi"`，错误为 `"system"`）、`t_recorded`（毫秒）、`reply_to`、`content`、`model`（`said` 必填）、`meta`（对象）。

P1 用到的 `class/kind` 组合：`experience/heard`、`act/said`、`control/error`。

### 3.3 上下文

- 发给模型的请求是：一条 system 消息（人设文件的全文），加上本场景最近事件按时间排列、带作者的原文。
- 原文的具体格式由 Sol 决定，可以用 user / assistant 消息，也可以用一条带时间与作者前缀的文本。但两点必须满足：
  - 每条内容的作者和先后可以辨认；
  - 不加入任何程序生成的语义标注或 JSON 摘要。
- `control/error` 不进入上下文；它对应的未回复 `heard` 要进入上下文。

### 3.4 HTTP 接口

| 方法与路径                    | 行为                                                                                                                                                                                                                                                                         |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /health`                 | 200，`{"ok":true}`                                                                                                                                                                                                                                                           |
| `POST /api/messages`          | 请求体 `{"text": string}`。响应为 `text/event-stream`，依次发送：`event: heard`（`data` 为该事件的 `id`）、若干 `event: delta`（`data` 为 `{"text": ...}`）、最后 `event: done`（`data` 为 `said` 的 `id`）或 `event: error`（`data` 为 `{"message": ...}`）。空文本返回 400 |
| `GET /api/events?after=<seq>` | 返回 `seq > after` 的全部事件，按 `seq` 升序                                                                                                                                                                                                                                 |
| `GET /`                       | 网页                                                                                                                                                                                                                                                                         |

### 3.5 必须遵守的边界

- 代码放在仓库根目录的 `v2/` 下，有自己的 `package.json`。不加入 V1 的 pnpm workspace，不 import V1 的任何包，不修改 `v2/` 之外的任何文件（除非负责人另行决定放到新仓库）。
- 可以参考或复制 V1 中 OpenAI 兼容流式传输的写法（`packages/providers/src/openai-compatible-stream.ts`），但复制过来的代码归 V2 所有。
- 密钥不写入数据库、日志和错误信息。
- 默认只监听 `127.0.0.1`。
- 不新增本文件以外的设计文档；`NOTES.md` 以一页为限。

### 3.6 由 Sol 决定

SQLite 驱动（`node:sqlite` 或 `better-sqlite3`）、HTTP 框架、模块结构、表结构中的其他字段与索引、上下文的具体排版、网页实现、测试框架、日志格式、超时数值（须在 `NOTES.md` 写明）。

## 4. 验收标准

Claude 使用**自己编写**的 OpenAI 兼容假模型服务和脚本执行以下检查。假服务能够：

- 返回指定文本的流式响应（按块、可设置间隔）；
- 返回 500；
- 在流的中途挂起；
- 记录收到的请求体。

所有检查在一台没有其他网络的 Linux 机器上，用 Node 22 运行。

| #   | 检查       | 步骤                                                            | 通过条件                                                                                                                                                             |
| --- | ---------- | --------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A1  | 构建与测试 | 新克隆分支，在 `v2/` 中 `npm ci && npm test`                    | 全部通过，过程中没有网络请求                                                                                                                                         |
| A2  | 启动       | 按 §3.1 设置变量后按 README 启动                                | 5 秒内 `/health` 返回 200；进程只监听 `127.0.0.1:8787`                                                                                                               |
| A3  | 正常回合   | `POST /api/messages {"text":"你好"}`，假服务分 5 块返回“我在。” | SSE 依次为 heard、delta…、done；delta 拼接等于“我在。”；`/api/events` 中按序出现 `heard`（actor=owner）与 `said`（actor=yuvi，`reply_to`=heard 的 id，`model` 非空） |
| A4  | 上下文     | 在 A3 之后再发“第二句”，检查假服务收到的请求                    | system 消息等于人设文件全文；其余部分按顺序包含“你好”“我在。”“第二句”，且能辨认作者；不含 JSON 摘要或语义标注                                                        |
| A5  | 重启持久   | 停止进程后重启，再发一句                                        | `/api/events` 包含重启前的全部事件，`seq` 连续递增；新请求的上下文包含重启前的对话                                                                                   |
| A6  | 只追加     | 用 `sqlite3` 直接对事件表执行 `UPDATE` 与 `DELETE`              | 两者都失败，数据不变                                                                                                                                                 |
| A7  | 模型错误   | 假服务返回 500                                                  | SSE 收到 `event: error`；档案中有该 `heard` 与一条 `control/error`（`reply_to` 或 `meta` 指向该 heard），没有 `said`；随后一条正常消息正常完成                       |
| A8  | 生成中崩溃 | 假服务流到一半挂起；对进程 `kill -9`；重启                      | 重启后，该 `heard` 有一条 `control/error`（`meta.reason="interrupted"`），没有 `said`；再发一句时，上下文包含那条未回复的消息；不会自动重发或补回复                  |
| A9  | 串行       | 间隔 100 ms 连发两条消息，假服务每次回复耗时 1 秒               | 两条都得到回复；两条 `said` 的顺序与各自的 `reply_to` 正确；第二次模型请求开始于第一次结束之后                                                                       |
| A10 | 空输入     | `POST {"text":""}`                                              | 400；档案无新事件                                                                                                                                                    |
| A11 | 密钥卫生   | 用一个独特的密钥字符串跑完 A3–A9                                | 该字符串不出现在数据目录的任何文件和进程的全部输出中                                                                                                                 |
| A12 | 网页       | 用无头 Chromium 打开 `/`，输入一句并提交                        | 回复逐步出现在页面上；刷新后历史仍在                                                                                                                                 |
| A13 | 边界       | 查看 PR 的文件变更                                              | 只有 `v2/` 下的文件；不依赖 V1 的包                                                                                                                                  |
