### Journal AMENDMENT rule

There is no new production AMENDMENT producer in these atoms. RECEIPT/CONTROL acknowledges an admitted explicit command. A9 owns the logical command and its execution accounting. The native domain owner commits the new revision/correction. Current derived readers invalidate against that revision. None of those steps rewrites the original receipt.

The protocol's INTENT/ATTEMPT/OUTCOME/DERIVATION/AMENDMENT shapes remain reserved unless a separately accepted producer exists. Do not append duplicate Journal events merely to mirror authoritative A9 rows or manifests. No production Journal effective-root/amendment authority is invented; A10.1's documented root-retirement and Mem0 limitations remain unchanged.

## 3. A10.2 frozen design

### 3.1 Static command families and admission

Use fixed host contracts; no plugin/model-provided authority or generic command DSL.

| Family | Semantic command | Native precondition / effect |
| --- | --- | --- |
| Person | Create, update authored fields, select primary Person | Exact target ID; create-absent or expected Person/primary-selection revision; Product owner commit |
| Voice binding | Assign, replace, remove | Exact `(voiceProfileId, personaId)` and current binding revision; Person exists; acoustic profile exists when assigning |
| Acoustic profile | Enroll, delete; controlled replacement workflow | Host-owned sample reference and allocated profile ID; native acoustic revision/command receipt |
| P8 | Append existing REVISE or RETRACT correction | Existing correctionReference, address/scope, parent and provenance rules unchanged |

This covers mutations already present in Product/voice/P8 routes. It does not migrate general configuration/provider secrets into effect payloads, create a Person deletion feature, change proactive consent ownership, or add broad principal-binding commands. Operational configuration remains its existing owner; actual provider invocations arising from it are classified under A9.3.

The host facade returns the exact committed JournalEventRef, not `void`. It freezes command family, scope, target, expected revision, policy/authorization version, native payload reference/digest and causal receipt. Fields absent from the original receipt remain absent. Person notes/display names and raw audio are not copied into receipt summaries. A command does not manufacture a USER_ASSERTION or an authenticated principal.

For a new control command, commit its minimal CONTROL receipt, protected command payload descriptor and A9 admission/pending work in one shared PostgreSQL transaction. Extend the existing host Journal/admission ports to accept the same transaction; do not introduce another append gate or raw route SQL authority. Within that transaction the A9 causal resolver sees the exact staged receipt; nothing may dispatch until the whole transaction commits. Preserve the A9.1 synchronous currentness check at COMMIT submission. Acquire the owner/key admission lock before the Journal namespace append lock, then the intent row, in that fixed order. Keep staged references transaction-private; they become committed causal evidence only when COMMIT succeeds. A rollback leaves neither the new receipt nor admitted command/work. Existing unrelated receipt-only paths keep their accepted semantics.

The immutable command instruction may contain the minimum private authored fields needed for execution in a protected payload store. It is not current Product/P8/binding truth. Keep credentials, raw audio, embeddings and hidden reasoning out. Raw enrollment samples stay in the existing bounded private review/volatile class, with availability references only. Missing/expired command payload prevents execution and is diagnosed explicitly; it is never reconstructed from current domain state.

### 3.2 Logical keys, replay and domain revision

A command handle is allocated once for an explicit user action and reused across transport retries. It is not a fresh request UUID per retry, a content-similarity key, authentication or a transport source-dedup assertion. The host binds the handle to one command family, target, scope and immutable requested body. Concurrent first admissions serialize on that owner/key within the shared transaction; the loser resolves the committed exact replay or conflict and does not append a second receipt; Person create allocates its target ID once with that handle.

Use owner-qualified keys containing contract kind/version, installation namespace, domain scope, target and command handle. P8 uses its existing correctionReference as the stable command handle. Existing `ei1` identity hashes **owner plus logicalKey**, while the durable store also constrains `(contract_ref, logical_key)`; therefore kind/version must be included in future keys for owners with multiple contracts. Preserve old IDs and old intent JSON.

Before allocating another receipt, expiry or payload reference, resolve the owner-qualified command key. Rebuild a retry envelope from its original frozen references and compare the requested semantic body; do not allocate new causal metadata on replay. Same key and exact semantic request, including frozen causal/expiry/payload references, returns the original intent/receipt/decision. Different semantic request conflicts. Replay lookup occurs before re-running current-state mutation preflight; an already-applied command is returned, not denied because its expected revision is now old. New admission still requires current authorization. Never refresh an expired request or mint another key automatically to escape UNKNOWN.

Native command adapters use the existing generic claim → dispatch-start → invocation worker, exclusively replacing old direct owner mutations for the migrated command. At dispatch, recheck local permission, owner availability and native expected revision. The native owner serializes the compare-and-set and commits its state with `{commandHandle, intentId, attemptId, fence, payloadDigest, causalRefs, priorRevision, resultingRevision}` in the same durable generation. A stale expected revision is definitive rejection only if the owner establishes no command effect was applied. Admission remains historically valid; a later refusal is not retroactive denial.

Person revision identifies the exact authored field version. Primary selection has its own revision. The global settings revision continues to order configuration but cannot stand in for either. Store opaque revision IDs and protected content digests/descriptors in the owner's envelope. Historical body retention follows existing permitted retention; a revision reference alone does not guarantee old notes can be reconstructed.

### 3.3 Native persistence and reconciliation

Keep Product, controller binding and P8 native files as their domain authorities. Upgrade each envelope to atomically include current revision and immutable command-application receipts. Write temporary data, fsync, rename/activate, then fsync the containing directory. Use the existing host lifetime/serialization owner. A separately written receipt side file is insufficient.

SpeakerStore's metadata and vectors must form one coherent generation: write and fsync both generation files, then atomically activate a manifest referencing their matching revisions/digests. Its command receipt belongs to that activated generation. An incomplete temporary generation is not current acoustic state. Staging is not a historical template archive: retire unreferenced generations after activation/in-flight readers release under the existing acoustic retention policy. Cleanup failure is separately visible and does not restore a deleted current profile or prove full erasure. Do not place authoritative templates or Person bindings in PostgreSQL.

Reconciliation returns APPLIED only from an exact native command receipt matching payload/intent/attempt identity and permitted evidence layer. It may return PROVEN_NOT_APPLIED only from a COMPLETE owner lookup **and** a barrier proving the old invocation can no longer commit (serialized owner queue plus current command fence; for the sidecar, its command barrier/receipt protocol). Mere absence from a file/list, changed settings, expired lease or process timeout is UNKNOWN. If the old writer cannot be quiesced/fenced, withhold retry. Owner receipts record actual attempts and replay the same logical command without applying it twice.

Domain commit and PostgreSQL observation commit are separate boundaries. Lost response/DB failure after native commit is reconciled by that native receipt. A Product native commit is APPLIED at NATIVE_OWNER_COMMIT even if Runtime reload fails. Mark dependent Runtime/config projections behind and withhold affected current use until revision verification/reload succeeds; a retry of the saved command returns the original application instead of resaving. Native state must not roll back to make the A9 queue look clean. A9 does not authorize a second native mutation based on a missing outcome.

### 3.4 Product profile-evidence semantics

`profile-evidence.ts` is frozen as a **derived Product projection**. Person state is authored by Product; repeating it through Memory does not establish another witness. Replace the current ordinary Memory write with a read projection carrying Product Person ID/revision, projection version and availability. No new grounded Memory root, Journal evidence selector, P8 invariant or Profile source is created.

If a compatibility record must remain readable, mark it NON_EVIDENCE and point to the Product revision. Exclude it from EvidenceAdmission, Dream source evidence, Profile source sets and independent confirmation counts. Existing unlineaged mirrored records remain unsupported/non-evidence; do not retroactively attach receipts. `LocalControllerEvidenceProvider` voice assignments have a different role and are not these Product mirrors.

This does not introduce authored Person notes into A4 or redesign Profile synthesis. Existing scope selection can reference Product primaryPersonId without claiming principal binding. A10.3 records Person revision only when Product state was actually consumed, and records NOT_USED otherwise.

### 3.5 Voice assignment, replacement and removal

The binding owner maintains an append-only governed binding stream and current projection per `(voiceProfileId, personaId)`. Assignment requires no current assignment. Replacement explicitly names the current revision and replaces that binding; it is not another unconstrained claim. Removal explicitly retires the named current binding; an already-removed exact command replays. Conflicting current assignments fail closed. Different commands repeating the same Person do not count as independent identity confirmations.

Binding resolution consults the native owner's current state. VoiceBindingReferences is an index with a COMPLETE enumeration watermark; rebuild from the owner after missed writes/restart. Until verified/rebuilt it cannot positively resolve a Person. An indexed retired event stays retired. Ordinary Mem0/legacy records cannot be substituted when the binding owner is unavailable. Production removes the generic Memory fallback; compatibility readers cannot author or certify bindings.

P8 consumes a host-validated binding projection with native revision, explicit issuer policy, current eligibility and acoustic observation reference. SpeakerStore establishes only acoustic matching. Local controller evidence establishes explicit assignment. The index locates records. The pure P8 resolver combines those facts without creating a third assignment store. Whole-capture/mixed-speaker guards and unresolved status remain; similarity, profile label or SELF_REPORT metadata cannot bypass them.

Reassigning one acoustic profile is a binding replacement. Replacing the acoustic resource is a declared workflow: enroll new profile → atomically assign new/remove old in **one binding-owner generation** under expected old revision → retire old acoustic resource → update review projections. Before binding commit, old binding remains current and new acoustic profile is unbound. After it, the new binding is current even if old acoustic cleanup fails. Retained old acoustic data does not restore its retired binding. Each concrete owner mutation has its own child command/attempt; the workflow ID is correlation, not a second dispatcher. Persist only the immutable workflow plan and completed child references needed to resume decision-making. The coordinator may admit the next predeclared child after verifying predecessor evidence/current authorization; it never calls targets directly or repeats an UNKNOWN child. No no-op parent INTENT/ATTEMPT is created to stand for this plan.

If preconditions change mid-workflow, stop at the honest partial state. Cleanup/compensation requires its declared keyed command and current authority; it cannot rewrite previous APPLIED evidence. Review-buffer cleanup and privacy withdrawal remain governed by their existing privacy rules and must not become dependent on Journal availability. A10.2 does not promise cross-backend privacy erasure.

### 3.6 P8 corrections and historical records

Keep existing correctionReference replay/conflict, REVISE/RETRACT, address/scope, authored-invariant and parent-chain validation. Add exact CONTROL/A9/native revision lineage around the same append writer. The native correction receipt and new correction record commit together. Reconstruct from the exact correction set/revision read, not a loosely labeled latest relationship summary.

A correction invalidates current affected P8/context/binding projections through owner revisions. It does not amend original Journal events, rewrite Memory source authority/time or erase independent observations. Profile freshness remains f2 source verification; do not claim an unrelated Person edit created Mem0 tombstone/correction semantics.

Old Person/P8 records retain their existing authored ownership with `LEGACY_UNLINEAGED` causal status. Existing native controller binding evidence remains subject to its accepted compatibility validation, explicitly unlineaged; no new principal authentication is inferred. Old generic mirrored Memory is not promoted. Legacy acoustic generations can be observed but do not retroactively provide command reconciliation proof. Capture present revision descriptors where possible without inventing old revisions, receipts or operation outcomes. New commands cannot use a blanket legacy exception.

### 4.2 Logical reply, provider task and attempts

Allocate one Runtime reply identity for an admitted response slot, correlated with its committed cause and execution. It is a domain component identity, not a no-op A9 intent that falsely claims a dispatched effect. Generation, publication, speech generation and playback are separate logical effects related to this reply. Proactive output uses its admitted proposal/wake identity and current consent; NOOP is not a published assistant reply.

Provider task keys include owner, task kind, scope, reply/execution operation slot and frozen input snapshot descriptor. Payload identity binds the intended semantic input, policy, model constraints and permitted routing plan. Credentials/endpoints with secrets remain configuration refs. Attempt records identify the actual adapter/provider/model/contract version; routing/provider labels never become semantic ownership or evidence authority.

Move accounting inside provider-chain leaves. A readiness skip before transport invokes nothing and creates no dispatch attempt. Before each actual leaf call, claim and commit dispatch start. Fallback to another provider is allowed only after certified no-effect evidence and under the frozen routing contract/current authority. `ProviderError.fallbackEligible`, `retryable`, `effectState=unknown`, no visible delta and absence of a success record are insufficient. Unknown streaming/provider completion leaves that same attempt UNKNOWN; do not silently call the next provider. Certified pre-transport failure may permit another attempt; applied/unknown work may not.

A returned but malformed/semantically rejected model output is still provider-response evidence, not proof that generation did not occur. A bounded existing Cognition/Character repair round may be a new task only when its protocol slot and changed input (including validation feedback) were authorized by the host plan; record that distinct causal input/round. It is not a retry/fallback alias, cannot be used to escape an UNKNOWN predecessor, and cannot make generated feedback source authority. Generated content remains generated output, never USER_ASSERTION. A partial stream can retain published prefix facts while its generation attempt ends UNKNOWN. A complete provider response establishes provider response production at that layer, not delivery, factual correctness or human consumption.

### 4.3 Durable-before-visible streaming: exact rule

The persistence unit is **each nonempty Runtime-projected text delta**, after existing Chat/Character normalization and before Runtime yields it. It is not each vendor token, transport byte, hidden Character JSON field, reasoning fragment or a newly chosen timer/batch size. Preserve current delta boundaries; do not add batching semantics in this atom.

For each delta, in one transaction on the shared pool:

1. Append an immutable reply component with replyId, decimal bigint sequence, exact permitted normalized text, projection version, source attempt reference and digest.
2. Update the conversation text projection idempotently from that component.
3. Admit publication work for each currently authorized active target generation.
4. Commit before yielding the delta or writing/publishing any frame.

Same reply/sequence/content replays; different content conflicts. The component is generated-output history, not Memory evidence. Where an existing source/output retention rule forbids persistent text, commit the same sequence/digest/NOT_RETAINED descriptor and publication work with a transient payload reference instead of the text body; do not create an archive. Current invocation validates that exact transient payload before write. Payload loss withholds remaining publication and exposes a historical gap, never regenerates or substitutes current text. Ordinary retained conversation deltas keep their exact bodies under the existing conversation class. Conversation is a materialized read view of these components for new replies, not a second independently mutated text authority. Legacy conversation rows remain historical with explicit component gaps. Prefix consistency and final seal bind exact component sequence/digest; completion does not generate or replay another copy of the text.

The gateway performs claim → durable dispatch start → target write. Target identity includes authorized surface/connection generation and recipient namespace. SSE/WS/HTTP/EventBus owners are exclusive adapters for their respective target delivery. `agent.reply` and `assistant.message` are representation aliases of one reply, not separate assistant generations. Multi-recipient fanout creates distinct target delivery work for one component. Internal EventBus fanout is computation: account at the actual target transport boundary, not both the bus emit and the same downstream write. Target terminal/control frames also receive durable component descriptors before publication, even when they carry no text. A successful target write establishes only `LOCAL_GATEWAY_WRITE_ACCEPTED` (including accepted writes that signal backpressure), not peer receipt; a disconnect/lost acknowledgement after start is UNKNOWN, never automatic resend.

Commit failure stops new visible output. Already committed/visible prefixes remain honestly partial; a failed/canceled seal does not erase them. On restart never resume old generation or replay old deltas, audio or gestures. Pending publication tied to a dead connection generation is withheld. Passive history/subtitle refresh can read a retained current view under current disclosure policy; it is not an instruction to execute old actions and must not re-trigger TTS.

### 4.4 Speech generation, playback and subtitles

The existing client `SpeechSegmenter` remains the sole segmentation authority. Its queue-aware emitted segment is sealed by the server before TTS invocation, with reply identity, speech sequence, source component spans, exact prepared spoken text/digest and preparation/segmenter version. The server validates that spans correspond to committed text under the declared preparation transform; omitted markdown/nonspoken content is explicit. It does not run another segmenter. Duplicate submissions map to the same segment; conflicting text/span submissions fail closed. Restart never recreates decisions by rerunning adaptive segmentation.

Freeze one speech plan on the reply/request: `NONE`, `CLIENT_SEGMENTED` or `SERVER_WHOLE`. A standalone whole-text TTS request is its own component, with its existing minimal CONTROL receipt. Its private requested text remains a transient input/NOT_RETAINED descriptor unless an existing retention class explicitly permits retention; do not copy it into Journal or a new TTS text archive. Client speech segments can reference the already-retained assistant components instead of creating another copy of the reply. Client-segmented and server-whole generation cannot both own one utterance. TTS key binds sealed segment and voice/rendering policy; provider attempts obey the same unknown/fallback rule. Current TTS providers return one complete audio result; use one audio-result component per sealed speech component, not new audio chunk/packet persistence or a new streaming-audio mode. Commit its descriptor plus authorized target publication work before forwarding the result. Generated audio bytes retain existing volatile/private availability behavior; accounting stores only safe digest, format, bounded metadata and opaque availability reference, not a new audio archive. Lost audio availability does not authorize regenerating an already-applied effect automatically.

Before `audio.play`, the active client submits the sealed playback component/current playback generation to the server. Server claims and commits playback DISPATCH_STARTED, then returns one fenced, single-use permission naming intent/attempt/client generation. The client invokes only that permission once. Sending the permission is a progress fact only. Playback terminal evidence is APPLIED at `DEVICE_REPORTED_PLAYING` only after a valid current device PLAYING report; permission publication, audio attachment and `play()` promise resolution do not establish that predicate. Without that report the attempt is UNKNOWN, including a lost permission response, and is not automatically resent. The adapter persists/sends the permission and returns conservative UNKNOWN without occupying a worker slot waiting for human/device completion. The host may reconcile the same attempt against its durable validated report lookup; unsupported/lost reports leave UNKNOWN. Completion/interruption is later progress, not human-consumption proof. Client disconnect/restart invalidates local execution rights; it cannot resurrect a durable old permission. Record attachment/start/end/interruption reports with the same identities and current report fence. Do not treat successful TTS, `audio.play()` resolution, playback ended and human perception as equivalent.

Client playback reports are bounded device observations, not authentication. Subtitles display the same committed reply/speech components; a ready/latest snapshot refresh may repeat a read view without repeating speech. Lumi analysis/lipsync observes the single active playback stream and remains computation, not a second playback effect or an attempt per frame.

### 4.5 Embodied presentation and plugins

Preserve Runtime source-generation/currentness/expiry fences and existing semantic effect ID. The latter is correlation, distinct from intentId and attemptId.

Commit dispatch start before bridge request publication. Bridge accepted, device STARTED, device COMPLETED, interrupted and device error are separately typed observations. A bridge timeout/closed connection/callback failure after start cannot establish no effect. Add protocol-versioned UNKNOWN reporting/translation rather than converting it to definitive FAILED accounting. Reports bind attempt/fence/target generation; stale reports cannot mutate current work. Do not retrofit a human acknowledgement from device completion.

A7 local transformations remain internal. Any external plugin activation needs a fixed host-approved effect contract and adapter; untrusted registration metadata cannot claim idempotency/reconciliation. Inventory revocation stops new admissions; implementations remain alive while admitted calls drain. A9.3 does not build a generic external plugin DSL or enable unrelated capabilities. Pending work cannot be executed with a silently replaced adapter/configuration: bind adapter contract and configuration revision (safe reference, no secret values), recheck at start, and withhold if the recorded implementation is unavailable. Keep implementations through drain; do not treat reload as permission to replay started attempts.

### 4.6 Observation progression and dispatch accounting

Preserve immutable A9.1 intent bodies and A9.2 claim/start/lease rules. Extend observations with a versioned category `TERMINAL` or `PROGRESS`; all existing observations default to TERMINAL. Terminal certainty remains APPLIED, DEFINITIVE_REJECTION, PROVEN_NOT_APPLIED or UNKNOWN with a specific evidence layer. Progress records contain fixed typed facts and protected component refs, not another certainty/status machine.

Stream component production and later presentation reports may append progress facts without replacing an earlier terminal observation or reopening dispatch. Work openness/retry queries consider terminal evidence only. Exact fact replay is idempotent; conflicting evidence for the same fact key is an integrity conflict, not last-writer-wins. Progress never independently enables retry. Durable bridge/transport acceptance can close dispatch at its declared layer while later reports remain additional facts; missing completion is not upgraded to success.

Bound all outcome/progress writes to intent, attempt, adapter contract and current observation fence. Client report ingress uses an immutable registered attempt/target/report-generation capability, persists only valid typed reports, and does not directly bypass worker outcome fencing. A reconciler under the current claim fence can project that report as evidence on the same attempt. Reports for an expired/replaced target generation are withheld from current accounting; receipt of a report is never a replay permission. For asynchronous device reports use the registered report generation/fence, not an unbounded old worker lease. Reconciliation of one uncertain attempt does not mint another attempt. Any new attempt requires certified no-effect plus current authority. No parallel `intent status`, `worker status` and `presentation certainty` fields may compete with this decomposition.

### 4.7 Fixed delivery traits and bounded execution lanes

Current ordinary provider adapters have no authoritative remote lookup or effective semantic idempotency established by source. Freeze reconciliation as UNSUPPORTED and allow retry only for certified host-local/pre-transport no-effect evidence; an HTTP status/error flag alone does not certify it. Native control adapters reconcile through exact owner command receipts/barriers. Gateway publication and presentation have no automatic post-start retry. Playback lookup is only the validated device-report store described above, never a remote no-effect proof. Preserve accepted read-text lookup/retry traits and Finalized/Dream's separate keyed contracts.

Use one host generic facility/store, with reserved bounded lanes: up to four generation calls (including TTS/STT/Vision/embedding), two native-control/capability calls, and four short publication/permission/presentation submissions. These are scheduling limits, not authorities or extra queues. All lanes share one intent single-flight map and PostgreSQL claim fence. Do not allow long generation calls to consume the control/publication reserves; Cognition waiting for read-text must not deadlock behind its own generation tasks. Workflow coordinators do not hold an invocation slot while waiting for a child command.

Renew active worker leases only while the same attempt/fence/owner remains current; renewal is local processing authority, not effect certainty. Failed renewal/fence loss stops new components/publication from that invocation and requests cancellation; it cannot permit another worker to resend. Final outcome remains fenced/UNKNOWN if the old result cannot be committed. Adapter bodies may append committed progress through the host store while their generation attempt remains started; no direct target bypass is exposed. Test saturation, renewal loss and long-running streams explicitly.

## 5. A10.3 frozen context-use manifest

### 5.1 Capture and exposure boundary

Introduce one versioned immutable base manifest per execution/context assembly ordinal, plus immutable exposure records per actual consumer invocation. The base is the A4 snapshot and its exact consumed source descriptors. Exposures identify the actual Chat/Character/Cognition/provider/capability projection, ordering, truncation and input digest. A provider task with several safe attempts can reference distinct exact exposures if a declared adapter projection differs; the semantic request remains governed by its frozen task contract.

Owner read APIs return value plus captured revision/availability as one observation. Runtime composition captures the Product revision actually used for scope selection and carries it for that Runtime lifetime; a later settings read is not evidence of the earlier scope decision. The cross-owner snapshot is an observed revision vector, not a distributed atomic transaction; required dispatch-time authorization checks remain live and separate. Runtime carries that descriptor into A4 assembly. After projection but **before admitting/invoking the affected provider/capability**, commit base/exposure evidence and bind its ID to the A9 input snapshot reference. Failure prevents that use; no volatile bypass. Do not read current owners again afterward and label those revisions as historical input.

A9.3 reserves a typed input-snapshot reference and records the actual input descriptor/digest it already needs; it does not implement a second full context manifest. A10.3 supplies the canonical manifest through that seam. Old intents remain immutable with explicit legacy/no-manifest status, not retroactive injected IDs.

### 5.2 Required exact descriptors

| Descriptor | Historical content / rule |
| --- | --- |
| Execution | executionId, assembly ordinal, trigger/cause refs, consumer/code/policy versions; no recreated A2 continuation |
| Committed input | Exact JournalEventRef and payload version/selectors actually read, with unresolved identity and original clock states preserved |
| Person | Product Person revision and primary-selection revision if actually consumed for fields/scope; NOT_USED otherwise |
| Binding / acoustic observation | Exact native binding revision used, acoustic profile generation/observation refs, resolver version and unresolved/conflict states; not latest assignment |
| P8 | Exact ordered correction references/set digest, address, reconstruction version, authored-invariant/code revision and reconstructed projection digest |
| Memory | Actual backend row/source descriptors, captured source-state fingerprints, lineage/root identities and selectors; candidate, selected and excluded states separate |
| Profile | profileRevision, sourceSetDigest and actual f2 live-verification observation if consumed; otherwise NOT_USED; UNCHECKED never labeled current |
| Conversation | Exact consumed message IDs/sequences/content versions/statuses and bounded checkpoint/list digest, not an invented complete/global snapshot; legacy mutable rows use an OBSERVED_LEGACY_SNAPSHOT descriptor of the actual read, not a fabricated native revision |
| Selection/exposure | Declared retrieval/selection policy, available candidate refs, selected/omitted/redacted reasons, block/spans actually exposed after projection/budgeting |
| Stable/volatile context | A4/A5 serialization versions, section ordering and stability digests, capability/protocol versions, actual volatile time/situation values where permitted |
| Retention | Per-input state and protected reference; retained text only within existing permitted retention classes |

Runtime currently does not feed a synthesized Profile into A4 merely because AppContext has a People.Model reader. Record NOT_USED there. Do not use A10.3 to introduce a new Profile/Person prompt feature. Cognition reentry/capability observations create exposure records for the exact additional inputs actually sent, including NOT_RETAINED read-text results; they do not retroactively alter the prior base manifest.

Mem0 has no scope-wide revision/CAS/tombstone authority. Record exact observed IDs/content/lineage digests and bounded-enumeration proof only when the read actually provides it. Ordinary top-k search does not certify COMPLETE. Legacy Memory native lifecycle/validity revisions remain distinct. Root identities are ancestry, not row counts or guessed matching prose.

Manifest IDs are stable within `(executionId, assemblyOrdinal)` and exposure IDs within `(manifestId, consumerOperationSlot, exposureOrdinal)`, qualified by installation namespace; exact canonical digest replay returns the same record, a different digest conflicts. They are not just content hashes: identical content in two executions remains two historical uses. Captured source revisions may be reused; an exposure is not inferred merely because a candidate was selected.

### 5.3 Missingness, retention and reconstruction

Distinguish `NOT_USED`, `EMPTY`, `UNAVAILABLE`, `ERROR`, `NOT_RETAINED`, `REDACTED`, `DELETED` and `LEGACY_UNLINEAGED`. EMPTY means a successful applicable read had no items. Outage cannot manufacture EMPTY or a fresh empty Profile. Selection and exposure are separate: selected data may be truncated, withheld or fail before exposure; provider invocation records bound the actual submitted projection.

Retention default is references and safe revision/digest metadata, plus authorized normalized ordinary conversation text already permitted by its retention class. This does not mandate archives of Person notes, raw images/audio/embeddings, credentials, hidden reasoning or read-text file contents. Record ephemeral input's bounded modality/availability/version descriptors; do not hash guessable PII into a public identity. Private digests/descriptors require the same scoped read permissions as the source. A later deletion/redaction changes payload availability without rewriting the immutable fact that a historical exposure was recorded.

Reconstruction guarantees identities, causal links, consumed versions, selection/exposure decisions, declared projection/code versions, and explicit known gaps. Exact rendered context is reconstructible only if every required retained input and transformation version is available. Rebuild it from those versions, not current retrieval/Person/P8/binding/Profile. If input was ephemeral or deleted, report partial reconstruction; matching prose/model inference is never a replacement.

Reconstruction does not rerun providers, tools, TTS, publication or playback; guarantee vendor output repetition; establish world truth/Person authentication; or prove a human perceived output. Source snapshot metadata is historical evidence of use, not a new source authority. Preserving history is not a retention exemption.

### 5.4 Owner revisions, invalidation and historical immutability

A10.2 publishes owner revision invalidations after native commit; Memory/Profile use their existing mutation/freshness seams. Notifications are advisory. Current caches store dependency revision/checkpoint vectors and verify applicable owner revisions before exposure, including after restart or notification loss. A behind/unavailable reader withholds affected current data. Recompute to a new generation and atomically replace the current cache pointer; leave unrelated branches available.

Historical base manifests/exposures never change. New corrections/read generations append references to their causal commands and prior domain revisions; they do not amend the earlier input set. A voice reassignment cannot rewrite the principal/binding in an old Journal receipt or Memory parent snapshot. P8 retraction changes current interpretation, not what an old model saw. f2 observation-boundary freshness remains its documented guarantee, not a distributed transaction with arbitrary external writers.

## 8. Certainty and error vocabulary

| Vocabulary | Meaning |
| --- | --- |
| Invalid request / persistence failure before decision | No admission decision established; distinguish from durable DENIED |
| DENIED | Immutable admission refusal; no dispatchable work; not an external OUTCOME |
| WITHHELD / revoked / expired before start | No permitted invocation across that boundary; preserve the original admission and any prior attempt evidence |
| CLAIMED | Concrete opportunity allocated; not proof of invocation |
| DISPATCH_STARTED | Committed permission to invoke; subsequent missing result is possibly applied |
| APPLIED | Adapter-certified effect at the explicitly named layer, e.g. native revision committed/provider response/transport accepted |
| DEFINITIVE_REJECTION | Contract-certified rejection; only supports retry/no-effect conclusions to the degree actually certified |
| PROVEN_NOT_APPLIED | Certified no-effect evidence for the named attempt; retry additionally needs current authority/contract |
| UNKNOWN / RECONCILE_REQUIRED | May have dispatched; no definitive evidence; unsupported reconciliation may leave it UNKNOWN indefinitely |
| PROGRESS | Immutable factual component/device report; no independent retry permission |
| CONFLICT / INTEGRITY_FAILURE | Payload/evidence/fence mismatch; fail closed, preserve prior evidence, never last-writer-wins |
| PARTIAL | Workflow/output has known committed components and remaining failed/unavailable/unknown steps; not a competing global outcome certainty |

Cancellation/expiry after dispatch does not prove remote rollback. Provider latency, confidence, HTTP timeout, aborted signal and lease expiration are not no-effect evidence. Operator abandonment, if added later under a separately owned contract, cannot retroactively turn UNKNOWN into NOT_APPLIED.

## 9. Restart, shutdown and fault boundaries

Preserve A9.2 seal → drain worker → retain adapters through result accounting → plugin/service teardown → pool close. Stop accepting new generic work before disposing implementations. On deadline after dispatch, persist honest UNKNOWN if the pool is available; if process death prevents that commit, durable DISPATCH_STARTED still drives conservative recovery. No graceful-shutdown claim substitutes for fault testing.

| Boundary | Required recovery / certainty |
| --- | --- |
| Before/inside admission transaction | Rollback leaves no new receipt/intent/work for the atomic control family |
| Pending admitted work | Claim only if payload/current authorization/expiry permit; dead Runtime/connection rights are not revived |
| Claim committed, no dispatch start | Expired lease can be fenced/recovered as local no-effect; cancellation/expiry can win |
| Dispatch-start commit response lost | Resolve durable state; no invocation until final committed owner/fence read proves permission |
| Dispatch start committed, before call or lost response | UNKNOWN unless adapter proves no effect; never infer from absence of success |
| Native owner committed, observation missing | Exact owner receipt reconciliation on same attempt; no second domain application |
| Provider prefix produced, later lost response | Preserve component/progress history; terminal UNKNOWN; no fallback/replay |
| Component committed, target not started | Current live target may dispatch once; dead target withheld; history remains readable under policy |
| Target/playback permission sent, acknowledgement lost | UNKNOWN; no resend/replay on lease expiration/reconnect |
| Old worker/client reports after replacement | Fenced rejection of stale state writes; exact permitted replay only |
| Correction notification lost/cache worker failed | Live dependency verification withholds stale current projection; immutable history unaffected |
| Forced kill / restart | No old Cognition continuation, audio regeneration, playback, gestures or deltas are resumed |
