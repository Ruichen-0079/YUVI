> **Status:** CURRENT A8.2 LEAF EXECUTION AUTHORITY — aggregate **PLANNED ENGINEERING**; A8.2a–A8.2d and A8.2e1–A8.2e3 **IMPLEMENTED REALITY**; A8.2e aggregate **IMPLEMENTED REALITY**; A8.2f **PLANNED ENGINEERING**

> This document refines the aggregate A8.2 contract in [`09-v0.1.3-platform-completion.md`](09-v0.1.3-platform-completion.md). A8.2a implements durable PostgreSQL Journal storage; A8.2b–d gate conversational, speech and standalone vision inputs; A8.2e1/e2 gate Product and Runtime local controls; A8.2e3 closes proactive-consent authority. See validation records for [A8.2a](../validation/v0.1.3-a8.2a-journal-store.md), [A8.2b](../validation/v0.1.3-a8.2b-conversational-ingress.md), [A8.2c](../validation/v0.1.3-a8.2c-speech-ingress.md), [A8.2d](../validation/v0.1.3-a8.2d-vision-ingress.md), [A8.2e1](../validation/v0.1.3-a8.2e1-product-controls.md), [A8.2e2](../validation/v0.1.3-a8.2e2-runtime-controls.md) and [A8.2e3](../validation/v0.1.3-a8.2e3-proactive-consent.md). Source audit split the former A8.2e aggregate into these three implemented leaves. Aggregate A8.2 remains incomplete until **A8.2f** and its bypass audit close.

## Why A8.2 was split

The original aggregate atom required durable-before-processing admission for HTTP/SSE/WebSocket conversation input, finalized speech, standalone vision and local control/identity operations. Source inspection showed that these are independent production seams with different persistence, identity, audience and retention rules. There is no existing universal ingress owner that can be safely modified once to close all of them.

In particular:

- ordinary and streaming conversational input converge near Runtime, but WebSocket carries a different transport shape;
- finalized speech has capture-epoch/pending-turn fences and separate audio-retention rules;
- standalone vision can call the vision provider without entering Runtime;
- Product/Person writes, Runtime-governed controls, proactive consent and voice identity use separate owners, authorization and persistence paths;
- Runtime therefore remains the **single semantic execution authority**, but it is **not a universal transport-ingress gate**.

The split is source-driven, not an invitation to add six new managers. Each leaf must reuse the narrowest existing production seam and the same single Journal append authority.

## Non-negotiable aggregate invariant

For every in-scope accepted production input:

```text
transport / local control input
        ↓
host-owned normalization and available identity/audience facts
        ↓
durable RECEIPT append
        ↓ only after commit succeeds
existing semantic/domain processing
```

If the durable append fails, the affected input is not semantically accepted. There is no silent in-memory fallback.

A8.2 does **not** implement A9 outbox/effect dispatch or A10 lineage-bound Memory/Person writes. It creates durable receipts and admission boundaries only.

## Database ownership rule

Journal durability must not depend on the selected long-term Memory backend.

The required ownership shape is:

```text
DesktopSupervisor / deployment database lifecycle
        ↓
configured YUVI PostgreSQL infrastructure
        ├─ Journal repository / append authority
        ├─ conversation or other existing durable consumers where applicable
        └─ PostgreSQL Memory repository when that backend is selected

Mem0 Memory backend selection is orthogonal to Journal existence.
```

Therefore:

- do not make Journal availability conditional on `MEMORY_REPOSITORY=postgres`;
- `MEMORY_BACKEND=mem0` must not disable the durable Journal when the deployment provides YUVI PostgreSQL;
- do not make MemoryRepository the semantic owner of Journal;
- reuse the existing Supervisor-managed PostgreSQL process/configuration/migration lifecycle;
- do not start a second PostgreSQL daemon or create an independent database supervisor.

A8.2a establishes the concrete shared-pool/repository seam that satisfies this rule. AppContext owns one configured Pool and closes it once after its injected repositories; Journal does not depend on Memory repository selection.

## Default execution order

```text
A8.2a → A8.2b → A8.2c → A8.2d → A8.2e1 → A8.2e2 → A8.2e3 → A8.2f → A10.1
```

The leaves may become technically parallel after A8.2a, but the default coding-agent workflow is sequential. Earlier ingress leaves are expected to pressure-test the Journal API before more production paths depend on it.

A8.2 remains **PLANNED ENGINEERING** until A8.2f closes the aggregate bypass audit.

# A8.2a — PostgreSQL Journal Store Foundation

**Status:** IMPLEMENTED REALITY; [validation](../validation/v0.1.3-a8.2a-journal-store.md).

**Goal.** Implement the one durable Journal repository/append authority before wiring production ingress.

**Preconditions.** A8.1 implemented; current PostgreSQL/Supervisor/migration ownership audited; real PostgreSQL available for validation.

**Existing authority it must preserve.** A8.1 protocol contract; DesktopSupervisor/deployment database-process ownership; Runtime semantic authority; Memory remains an evidence/index subsystem, not Journal truth.

**Exact scope.**

- add Journal tables through the existing migration mechanism;
- create the narrow durable Journal repository/append interface;
- host-assign journal event identity, `recorded_at`, namespace and serialized `commit_seq`;
- transactionally validate parents and build the committed A8.1 envelope;
- implement scoped stable-source dedup where an adapter supplies an actual stable source identity;
- persist only the minimal payload representation required by the existing retention contract;
- reconstruct committed envelopes after repository/process reopen;
- establish a database connection seam that remains available when Mem0 is the active Memory backend.

**Serialized commit-order requirement.** `commit_seq` must represent actual serialized commit order in one journal namespace. A bare PostgreSQL `nextval()` before transaction commit is insufficient. Use a per-journal state row/lock/CAS or another source-backed transaction mechanism that prevents sequence 13 from becoming durably visible before sequence 12 commits.

**Explicit non-goals.** No production ingress wiring, provider call, outbox, dispatcher, A10 Memory lineage migration, second DB daemon or generic event bus.

**Failure semantics.** Database unavailable/backpressured fails the append visibly; transaction rollback admits nothing; same stable source identity plus changed normalized payload conflicts; no-stable-ID inputs are never text-hash deduplicated.

**Required tests.** Real PostgreSQL migration, reopen/restart durability, rollback, immutable ID, parent existence/order, concurrent commit-order inversion test, scoped dedup same payload/conflicting payload, retained text selector resolution, unavailable media preservation, Mem0-active database configuration, packaged/bundled PostgreSQL smoke. In-memory adapters do not satisfy closure.

**Exit criteria.** Met for the store foundation: a real PostgreSQL repository durably appends and reconstructs A8.1 envelopes with transactionally serialized ordering, works independently of Memory-backend selection, and introduces no production semantic ingress.

**What later leaf depends on it.** A8.2b–A8.2f.

# A8.2b — Conversational ingress

**Status:** IMPLEMENTED REALITY; [validation](../validation/v0.1.3-a8.2b-conversational-ingress.md).

**Goal.** Make conversational input durable before Runtime semantic admission.

**In-scope current surfaces.** `/message`, `/v1/messages`, `/v1/messages/stream`, `/ws`, and chat image attachments insofar as they are part of the conversational turn.

**Preconditions.** A8.2a.

**Existing authority it must preserve.** Runtime owns turn/stream semantic execution; conversation IDs remain domain IDs; transport data does not become Person truth.

**Exact scope.** Create/reuse one narrow conversational receipt-admission seam that normalizes route-specific input, builds host authority fields from facts actually available, commits the RECEIPT, then and only then calls `Runtime.handleUserMessage` / `Runtime.streamUserMessage` or the current equivalent. WebSocket caller-supplied Runtime-event fields are not trusted authentication or journal identity.

**Implemented boundary.** `apps/server/src/conversational-receipt-admission.ts` is the host-owned seam. The ordinary `/message`, `/v1/messages`, `/v1/messages/stream` and `/ws` user-message paths commit an A8.1 RECEIPT before entering Runtime; HTTP/SSE constructs its Runtime event only after append succeeds, preserving the preselected event ID as correlation. The Journal authority records unresolved principal and Person binding, unknown audience/membership, route surface, session and Runtime event correlations, and host-owned producer/policy versions. No route has a stable authenticated upstream input ID, so no source dedup key is invented. Retained normalized text is stored under a host-generated immutable payload reference; chat image bytes stay in the existing Runtime-only path and the Journal records only a nonselectable `NOT_RETAINED` IMAGE descriptor. Append failure returns a bounded HTTP 503 or WebSocket error and skips Runtime.

Requests carrying `speechObservationId` continue through the existing `commitSpeechTurn` handoff without an A8.2b receipt. That accepted speech observation belongs to A8.2c and must not acquire a second original receipt here.

**Identity/audience rule.** If these routes lack an authenticated transport principal or membership snapshot, record explicit unresolved/unknown state. Local dashboard/token access is not automatically a Person binding.

**Retention.** Reuse/version existing durable text where safe or use minimal Journal text payload storage. Chat images keep existing ephemeral/non-archival behavior; metadata may be durable while raw image payload remains `NOT_RETAINED`/`UNAVAILABLE` as appropriate.

**Failure semantics.** Append failure prevents Runtime/model/downstream semantic work. Stable transport IDs deduplicate only within their real namespace; absent stable IDs are not guessed from content.

**Required tests.** Each ordinary route commits before Runtime callback, append failure blocks callback, streaming cannot begin before commit, stable-source replay is effect-once only when a real stable source ID exists, conflicting replay fails, identical text without a stable ID remains distinct, unknown principal stays unknown, unknown audience is preserved, ephemeral chat image does not become archived, and the speech observation handoff is not double-receipted.

**Exit criteria.** Met for ordinary conversational text and chat-image turns on the listed HTTP/SSE/WebSocket surfaces: each commits a durable receipt before Runtime, with real PostgreSQL ordering/failure tests. The pre-existing `speechObservationId` path is explicitly reserved for A8.2c; this leaf does not close other conversational or voice ingress paths.

**What later leaf depends on it.** A8.2f aggregate closure.

# A8.2c — Finalized speech and voice-message ingress

**Status:** IMPLEMENTED REALITY; [validation](../validation/v0.1.3-a8.2c-speech-ingress.md).

**Goal.** Commit accepted finalized speech before it enters ordinary semantic conversation while preserving current voice fencing and retention.

**In-scope current surfaces.** Finalized STT/transcription admission and `/v1/voice/message` or their source-equivalent production seams.

**Preconditions.** A8.2a.

**Existing authority it must preserve.** Current capture-epoch/pending-turn fences, STT attribution limits, voice binding owner, Runtime turn admission and bounded voice-review buffer.

**Exact scope.** Runtime synchronously reserves and normalizes finalized speech, provisionally fences its observation/segment IDs, and returns a token without publishing a turn or performing activity/proactive side effects. A host-owned speech receipt facade appends one A8.1 RECEIPT. Runtime then finalizes the same token against the committed envelope, retaining its Journal event reference in the pending speech turn. Journal failure releases only token-owned provisional claims. A live VAD epoch remains synchronous during database I/O; if it supersedes the reservation, the committed receipt remains but no handoff-ready turn or usable observation ID is returned. Finalized `/v1/audio/transcriptions`, `/v1/voice/message`, and existing `/v1/messages` plus `/v1/messages/stream` speech handoffs share this single original receipt. The message handoff adds no second conversational receipt.

**Retention.** Transcript text is retained in Journal under a host-generated immutable payload reference with Unicode code-point bounds. Raw audio is represented only by a nonselectable `NOT_RETAINED` descriptor when audio was supplied; bytes are not copied into Journal. The existing bounded voice-review buffer remains a separate retention class and is not promoted to Journal truth. Review retention still precedes Journal admission and is not rolled back on append failure.

**Identity rule.** Caller-supplied speaker/profile hints and acoustic similarity are not transport authentication. Preserve resolved/unresolved state according to the existing voice identity owner.

**Failure semantics.** Journal failure releases the provisional Runtime reservation and blocks observation handoff, `commitSpeechTurn`, and semantic voice-message admission without fabricating successful STT/identity conclusions. VAD may advance while append is in flight. A receipt committed for a reservation later made stale is kept as evidence of accepted finalized observation at reservation time, but cannot revive the old epoch or start semantic conversation. Volatile pending turns do not survive restart and there is no automatic replay or restart-durable speech dedup.

**Required tests.** Commit-before-semantic-callback, append failure, capture-epoch race, pending-turn cancellation/currentness, transcript restart reconstruction where retained, raw-audio non-archival, caller speaker spoofing does not authenticate, existing voice-review limits unchanged.

**Exit criteria.** Met for finalized transcription, immediate voice message and both existing speech-observation handoff routes: each handoff-ready observation has one durable receipt first, without changing audio/privacy or identity authority. Preview transcription remains outside finalized admission. The receipt describes accepted STT observation only, not transcript truth, speaker authentication, or completed Runtime work.

**What later leaf depends on it.** A8.2f aggregate closure.

# A8.2d — Standalone vision ingress

**Status:** IMPLEMENTED REALITY; [validation](../validation/v0.1.3-a8.2d-vision-ingress.md).

**Goal.** Bring standalone vision analysis under durable input accounting without turning YUVI into an image archive.

**In-scope current surface.** `/v1/vision/analyze` or its source-equivalent path that invokes the vision provider outside Runtime.

**Preconditions.** A8.2a.

**Existing authority it must preserve.** Vision provider semantics, current raw-image retention policy, current separation from Runtime conversational turns.

**Exact scope.** `HostVisionReceiptAdmission` receives only a host-derived source classification (`INLINE_BYTES` or `URL_REFERENCE`) and optional prompt; it cannot receive `imageBase64`, decoded bytes, `imageUrl`, or identity hints. It uses the existing host-authority append API to commit a RECEIPT before provider work. Inline bytes use `DIRECT_OBSERVATION` only to mean YUVI received image bytes; a URL uses `ATTRIBUTED_ASSERTION` because YUVI received only the caller's reference. Neither asserts visual truth. The image descriptor is `IMAGE/NOT_RETAINED` and nonselectable, with no image selector. An optional prompt is a separate retained TEXT payload with exact Unicode bounds; absent prompt creates no text payload. Raw URLs, credentials, identity hints and provider output are not persisted. Request disconnect is checked after append and before provider invocation; a committed receipt is retained if cancellation arrives during append. Do not route the operation through Runtime.

**Failure semantics.** Journal failure prevents the provider call. A missing retained image after restart remains unavailable evidence rather than reconstructed text.

**Required tests.** Real PostgreSQL commit-before-provider ordering and held-append cancellation; Journal failure/no-fallback; URL/base64 non-persistence; nonselectable image descriptor and retained-prompt reconstruction; no guessed identity or dedup; provider-result exclusion; existing provider-abort behavior and A8.2b/A8.2c regressions.

**Exit criteria.** Met for `POST /v1/vision/analyze`: PostgreSQL receipt commit precedes provider invocation, admission failures fail closed, request cancellation prevents later provider work, and raw image bytes/URLs remain outside Journal persistence. Provider output is not journaled.

**What later leaf depends on it.** A8.2f aggregate closure.

# A8.2e1 — Product / Person local-control receipts

**Status:** IMPLEMENTED REALITY; [validation](../validation/v0.1.3-a8.2e1-product-controls.md).

**Goal.** Record durable CONTROL receipts for locally authorized Product and Person commands before their existing operations, without moving Product/Person ownership into Journal.

**In-scope routes.** `PUT /product/configuration`, `POST /product/people`, and `POST /product/proactive/resume`. These routes already use the local-dashboard guard and share the Product route's mutation queue where they mutate Product settings. Provider tests, local-service detection/probes and query/list routes are excluded. The local guard does not authenticate a human or Person.

**Preconditions.** A8.2a and the source audit that split the former aggregate A8.2e. The e1 implementation does not close aggregate A8.2e.

**Existing authority it must preserve.** Local dashboard authorization, Product-store configuration and Person ownership, Runtime's proactive-wake owner, Product's existing serialized mutation queue, reload/apply response semantics, and the existing downstream profile-evidence behavior.

**Implemented boundary.** `HostProductControlReceiptAdmission` is a separate AppContext facade with a strict operation union and no request, Product writer, Memory, Runtime, provider or raw repository exposure to routes. After local authorization and route-specific precondition/shape validation, the three routes append a host-built `RECEIPT/CONTROL`, then call the existing Product persistence/apply path or Runtime proactive-resume method. Configuration receipts retain only operation and expected revision. Person create preallocates its ID and update verifies the existing target before append; summaries include only operation, target ID and requested-primary flag. Names, notes, persona values, API keys, provider IDs/URLs/models and full configuration remain outside Journal. No source dedup is inferred from revision, Person ID, request content or local address.

**Critical boundary.** The receipt means YUVI accepted the locally authorized control request for processing; it does not claim a settings save, Runtime reload, packaged speech reload, Memory profile-evidence write or proactive wake succeeded. Existing partial-save and profile-evidence behavior remains, without OUTCOME/DERIVATION or cross-store reconciliation. This is not A10 lineage.

**Failure semantics.** Journal failure blocks the corresponding Product/domain operation with a bounded admission error and no volatile fallback. A committed receipt remains if later Product apply or Memory profile evidence fails. Product configuration/Person preconditions and the existing queue are held through Journal append so stale revisions cannot be receipted.

**Required tests.** Local authorization before admission; malformed/stale requests create no receipt; real-PostgreSQL receipt-before-save ordering; concurrent same-revision saves remain serialized; append failure blocks mutation; credentials, provider URLs, Person names/notes/persona values do not enter Journal; profile-evidence partial failure leaves receipt and Product save; proactive resume follows append; no inferred principal/Person and no source dedup.

**Exit criteria.** Met for the three listed Product routes: real PostgreSQL receipts commit before their existing operation, append failures fail closed, concurrent Product saves remain serialized through admission, and the existing partial-apply/profile-evidence semantics are preserved. Principal and Person binding stay unresolved; no source dedup, outcome, derivation, A9, A10 or external effects are added.

**What later atom depends on it.** A8.2e2, A8.2e3 and A8.2f aggregate closure; A10.2 later adds profile-evidence lineage where required.

# A8.2e2 — Runtime-governed local-control receipts

**Status:** IMPLEMENTED REALITY; [validation](../validation/v0.1.3-a8.2e2-runtime-controls.md).

**Goal.** Close the source-audited local Runtime control surfaces that are distinct from Product/Person routes and proactive-consent policy mutation.

**In-scope paths.** `POST /p8/corrections` and `POST /capabilities/read-text/authorize`. `requireLocalDashboardAccess` remains ahead of all Journal admission. A narrow `HostRuntimeControlReceiptAdmission` accepts only the two fixed operation variants and appends through `JournalRepository.appendWithHostAuthority`; routes cannot supply authority, event identity, source dedup or retained content.

**P8 correction boundary.** The route parses the canonical P8 record, then Runtime performs a read-only preflight using the same `reconstructP8MainProfile` semantic validation as final append. It reads the exact address/scope plus the global correction-reference namespace. A canonical same-reference record may proceed to admission and the subsequent P8 append returns `ALREADY_STORED`; a changed record under a known reference, invalid target or invalid lineage is rejected before Journal admission. After the CONTROL receipt commits, Runtime reloads and revalidates P8 state before the existing append. Concurrent change can therefore leave a committed receipt followed by bounded `CONFLICT`/`ERROR`; the receipt remains and no OUTCOME is appended. Repeated canonical requests create separate Journal receipts because `correctionReference` is domain identity, not transport source dedup.

**Read-text boundary.** The route prevalidates the actual Runtime input contract before receipt admission, including whitespace-only `sessionId`, exact path trimming, absolute path and path-length bounds. Only after Journal commit does it call `Runtime.authorizeReadText`. The receipt contains no path or file content and does not read the filesystem. The grant remains the existing process-local, overwrite-by-session, one-shot Runtime state; it is neither reconstructed nor replayed from Journal after restart.

**Receipt authority and privacy.** Both CONTROL receipts use unresolved principal and Person binding, `subjects: []`, unknown audience and fresh host-generated immutable TEXT payload references. P8 payloads retain only operation, `REVISE`/`RETRACT`, target kind and optional fixed invariant-target enum. Read-text retains only its operation marker. No sourceDedup is supplied. Neither receipt proves P8 persistence/current truth, later file access, Runtime survival or a human/controller identity. Localhost and the development dashboard token authorize the route only.

**Failure ordering.** Journal unavailable/persistence failure returns a bounded 503 and prevents P8 append or read-text grant. Malformed/known-invalid/conflicting P8 commands and invalid read-text inputs receive no receipt. There is no cross-store transaction; post-commit P8 races preserve the admission receipt.

**What must NOT be absorbed.** Product/Person routes are A8.2e1. `POST /v1/proactive/consent` is a separate Desktop-settings projection boundary implemented by A8.2e3. Voice-identity routes are A8.2f.

**What later atom depends on it.** A8.2e3 completes the e aggregate; A8.2f closes aggregate A8.2.

# A8.2e3 — Proactive-consent authority closure

**Status:** IMPLEMENTED REALITY; [validation](../validation/v0.1.3-a8.2e3-proactive-consent.md).

**Goal.** Keep Desktop/Tauri persisted settings as the authored consent authority while journaling accepted READY projections before they change volatile Runtime consent.

**Authority and protocol.** `POST /v1/proactive/consent` is a local-only projection protocol, not a settings editor or authored consent store. READY `{revision, enabled}` projections are strictly validated, Runtime-preflighted, committed as host-built `RECEIPT/CONTROL`, then revalidated and applied in Runtime. The receipt has unresolved principal and Person binding, no subjects, unknown audience and no source-dedup identity. Its safe retained summary records the settings projection, not a claim about who authored the upstream save. Exact current READY replay is a no-op; stale revision and same-revision conflict are rejected before a receipt.

`UNKNOWN_DENIED {revisionFloor}` immediately advances Runtime's volatile revision fence and denies/cancels proactive eligibility without waiting for PostgreSQL or writing a receipt. It represents unavailable/invalidated settings authority, not authored consent=false. A stale in-flight READY may still commit its receipt, but post-commit Runtime revalidation prevents it from re-enabling consent. Runtime policy persistence continues to own suppression and eligible-after state; it ignores legacy `consentEnabled` snapshots in this production mode and does not reconstruct the volatile projection on restart. Main projects only current SettingsViews and sends UNKNOWN_DENIED on read failure or proactive invalidation.

**Existing authority preserved.** Desktop/Tauri settings remain durable authored policy. Runtime remains scheduler/eligibility owner, and startup denies until a current settings projection arrives. Local dashboard authorization does not authenticate a human or Person.

**Exit criteria.** Met for the consent projection seam with real PostgreSQL admission/race/restart coverage. Voice controls and aggregate bypass closure remain A8.2f.


## A8.2 family non-goals

Across all leaves, do not implement early:

- A9 transactional outbox, dispatch, retry or reconciliation;
- A10 grounded Memory/profile/P8 lineage migration;
- QQ/Snowluma transport integration;
- a universal Runtime ingress wrapper merely for architectural symmetry;
- text-hash deduplication presented as transport identity;
- automatic principal→Person binding;
- raw screenshot/audio archival;
- a second PostgreSQL daemon, migration framework or semantic database owner;
- full event-sourcing rewrite of Runtime or existing domain stores.

## Coding-agent rule

A coding agent implements **one leaf only**. Before each leaf it must fetch/verify the exact target HEAD, read the current A8.2 authority plus the previous leaf validation, audit the concrete source seam and stop on meaningful mismatch. It must not mark aggregate A8.2 implemented before A8.2f closes the bypass audit.
