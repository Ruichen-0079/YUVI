# Production reachability closure

## Current development trunk — 2026-10-07

`main` is the authoritative development trunk. The former platform-completion
and Multi-Character branches are historical work pointers, not instructions to
select another long-lived development branch. Historical validation records
retain their original branch names and dates; they do not prescribe today's checkout.
Public release versions remain governed by release tags and published releases,
not by the development trunk's feature inventory.

[Multi-Character Core](../architecture/multi-character.md) is implemented using
stable Character binding and independent existing Runtime compositions, without
a large CharacterInstance container. Product Person can be shared through an
explicit read view; Memory, Relationship, Profile, recent conversation, P8
corrections, proactive and execution state are isolated. Memory has no cross-Character
read-through. Primary Yuvi preserves legacy data compatibility. Independent
Registries can share one model service: separate mutable coordination does not
require duplicate model processes.

[Acceptance](../validation/multi-character-2026-10-07.md) includes real PostgreSQL
durable isolation, SIGKILL/restart and two Registries calling one real local
Qwen service. The configured built-server bootstrap is reachable; desktop Character
selection, a unified roster/supervisor, shared voice-binding administration and
physical presentation scheduling remain future work.

Alice is a future Character composition; Plunge should supply QQ transport and
social context bound to that composition. Historical persona-overlay prototypes
are not the new isolation mechanism. Plunge migration, QQ social attention and
multi-message handling remain future work; no real QQ acceptance has run.

The complete Linux packaged conformance gate has **not passed** in this environment.
It lacks the required native PG16 packaged distribution (`YUVI_POSTGRES_HOME`);
Docker PostgreSQL acceptance cannot substitute for that gate. Other packaged
prerequisites (including the pinned Node version and Mem0 environment) also need
validation. This is a release-conformance prerequisite blocker, not a failed
Multi-Character isolation test, and no formal v0.1.3 release is claimed.

Audit baseline: GitHub `main` at `a0a277068e466a2908f0c0b2191e3ecf921e257c` (fresh fetch). This audit covers current claims in the roadmap, Campaigns A–I, and the subsequent Linux release gate. Historical atom plans do not extend the production scope. `LIVE` means there is a real product caller and observable result; configured provider credentials, local weights, and device availability remain prerequisites. Tests alone are not the reachability evidence.

## Defects corrected

- P8 main reconstruction and its Character ABI projection were exported but had no production caller. Character independently assigned `KNOWN` to identity, style, and relationship PromptBuilder text. Runtime now reconstructs P8 on each turn and supplies its typed sections to both initial Character and Cognition re-entry. The existing authored production persona has moved to P8; no second profile system or learned relationship inference was added.
- P8 correction persistence had only a PostgreSQL library adapter. The local production adapter uses the existing append/load and lineage contract, under `YUVI_RUNTIME_ENV_DIR/p8-corrections.json`. The protected controller route validates P8 authority before appending. Corruption is `ERROR`, never an empty correction history.
- Acoustic enrollment did not bind a person, and committed speech did not resolve a person before Memory use. The Local intelligence panel now offers an explicit person binding. Runtime writes trusted binding evidence through Memory and persists only its event references in `voice-binding-references.json`. On every speech turn it loads those exact Memory events and calls P8 resolution. Missing, failed, conflicting, or mixed-speaker evidence cannot select a person or enable durable person-scoped Memory. `/v1/voice/message` now commits the server-owned STT observation instead of accepting caller identity assertions as recognition.
- Production selected simple Cognition despite the existing bounded capability-aware implementation. The normal callback now uses the current read-text round-trip, Runtime capability admission, observation normalization, continuation, and Character re-entry. One explicitly authorized file, one round, no loop, no generic orchestrator. The concrete path never comes from Cognition text.
- Memory vNext's existing `characterProjection` was not consumed. Its projection also omitted ordinary long-term hits when no associative/episode hit existed. Memory now projects admitted long-term evidence, provenance, partial/limited outcomes, and thin temporal uncertainty; Runtime passes that output to `projectMemoryVNextToCharacterAbi`. It no longer reconstructs facts from PromptBuilder text.
- Proactive decision and continuation used the legacy profile prompt. They now consume the same producer-owned projections. Their separate NO_OP / REQUEST_TEXT protocol, Runtime admission, and output-language preference remain intact.

## Controller contracts

The three controller routes require localhost and the configured dashboard development token. The voice UI uses the existing token transport. Acoustic profile existence is checked through the selected provider before a binding write. Binding references contain no person semantics: missing referenced Memory records fail closed. Conflicting assignments remain conflicting; automatic reassignment, acoustic confidence promotion, and transcript self-identification do not override P8.

`POST /p8/corrections` accepts the existing `p8-1e.v1` correction record. Use the current `characterInstanceId` (`yuvi-default-character-instance`), configured persona ID, explicit person `subjectScopeId`, and its exact `buildMemoryScope(personId, personaId)` reference. The live relationship interpretation target is `relationship.current`. Authored identity/persona invariants retain their existing fixed revision policy. Arbitrary conversation text does not become a persisted correction or a known relationship. No evidence is `EMPTY`, insufficient meaning is `UNKNOWN`, and unavailable/error inputs retain their states.

`POST /capabilities/read-text/authorize` accepts `{ "sessionId": "...", "path": "/absolute/file.txt" }`. The next Character turn in that session consumes the authorization even when it needs no capability. Cognition sees only an opaque read-only capability description. Runtime supplies the concrete path. The adapter accepts one regular UTF-8 text file of at most 64,000 bytes. The authorization is not persisted across restart. No authorization means an empty capability inventory; it does not select a legacy/simple bypass.

## Adversarial continuation pass

The previous matrix was challenged against alternate transports, automatic wakeups, reload/restart, read-only preparation, and scoped episode persistence. Counterexamples found and corrected:

- Proactive `NO_OP` preparation wrote L1 episodes. All prompt assembly now reconstructs without persisting; only admitted completed-turn persistence writes episodes.
- Non-streaming unresolved voice finalization reused the requested write flag after prompt preparation had disabled it. Turn-level memory admission now applies the same resolved speaker restriction before persistence and finalization.
- Ordinary and streaming `writeMemory=false` turns could still write L1 and trigger Dream. Completion gates now honor the write flag, and persisted user and assistant metadata excludes those turns (including failed or silent turns) from later durable episode reconstruction after restart. Read-only L0/L1 narrative reconstruction remains available.
- A shared session's whole history could be relabeled with its latest person's scope. Memory vNext filters source messages and stored episodes against the explicitly selected identity. Runtime supplies the canonical Memory scope to durable episodes and Dream.
- Live proactive SSE subscribed to the replaced Runtime after settings reload. The route now subscribes through the stable AppContext forwarding subscription.
- Automatic proactive wakeups omitted the configured person/persona. Startup and reload now pass that identity into scheduler admission and P8/Memory preparation.
