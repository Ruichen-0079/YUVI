# Memory, lineage and reconstruction

Status: **PRODUCTION ARCHITECTURE DECISION** for future ownership; **IMPLEMENTED REALITY** for the mechanisms identified here; aggregate A10.1 is **IMPLEMENTED REALITY**, with A10.1a–f3 implemented; see [aggregate validation](../validation/v0.1.3-a10.1f3-aggregate-memory-profile-closure.md).

Memory is a replaceable set of evidence indexes, retrieval/ranking policies, compaction and retention views. The committed Journal owns original causal evidence; Memory does not become world truth, disposition state, obligation state or identity authority. Mem0 can propose/index normalized material, but neither its extraction nor mutable search results may silently become canonical history. All provider requests and Memory writes remain behind existing contracts.

## Assets to reuse

The current finalized-turn ingestion ledger already gives parent turns and child events stable identities, payload keys, versioned claims/leases, dispatch-start persistence and ambiguous-delivery reconciliation. Its executor calls `writeEventIdempotent` and refuses unsafe blind delivery recovery. Dream delivery also uses keyed writes and reconciliation. These are downstream delivery assets; A9 does not replace them with another retry engine. Read-only A9 compatibility intent identities link to their stable child keys; each delivery still has one active executor.

The Mem0 provider sends normalized writes with `infer: false`. Its canonical Memory event ID and backend ID are not journal receipt IDs. The local controller evidence provider separately preserves trusted voice-binding evidence. Legacy Memory and Mem0 have distinct active paths; architecture must test both, not infer safety of one from tests of the other.

Before A10.1a, the optional legacy `LlmMemoryExtractor` could force generated candidates to `originRole: user`, accept model `sourceTraceId` and model clocks, and let provenance enrichment attach unrelated user text as `evidenceText`. The deterministic weather-to-astronomy probe stored an unsupported generated preference as durable legacy Memory with a forged trace ([baseline](implementation-baseline.md#verified-defects-and-gaps)). **A10.1a closes this extractor path:** when `MEMORY_EXTRACTOR=llm`, the reasoning provider is not invoked; only the existing rule-based extractor supplies candidates, and status reports `unsupported-grounding`. Unknown values reject through shared parsing, server boot and runtime reload. Mem0 continues to skip legacy extraction. A10.1b carries conversation ancestry, and **A10.1c now validates that ancestry for new legacy evidence-backed writes**; A10.1f1 provides a local derived ProfileProvider substrate and A10.1f2 implements its People.Model freshness bridge; f3 closes aggregate A10.1 as IMPLEMENTED REALITY.

P8 qualification: the reproduced row could contaminate legacy Memory prompt retrieval. Current legacy mode has no semantic `MemoryProvider`, so that exact row is not directly passed into Runtime P8 reconstruction as a semantic `MemoryEvent`; Runtime receives an unavailable semantic Memory outcome. If future code exposes generated or lineage-bearing Memory to P8, model-owned `originRole: user` metadata alone must not authenticate it or make it verified user evidence.

A10.1b stores the exact host-derived `JournalEventRef` on each newly admitted conversational or finalized-speech user message in the durable conversation repository. The reference is separate from Runtime event/trace IDs, `sourceUserEventId`, speech observation IDs and Memory/backend IDs. Legacy messages remain null; no receipt is guessed from text.

## Implemented A10.1c legacy grounding boundary

New evidence-backed legacy Memory candidates now require a separate host-owned grounding context containing the Runtime event's committed Journal reference and exact source text. `JournalMemoryGroundingResolver` resolves that exact parent from the existing Journal repository, accepts only eligible factual RECEIPTs, finds a committed retained/selectable TEXT descriptor and selector, resolves the retained payload, applies Unicode code-point bounds, and requires the selected committed text to equal the source text supplied to deterministic extraction. A missing parent, mismatched turn, unsupported receipt class, unavailable/redacted/nonselectable payload or unresolved selector rejects the write; `sourceTraceId` and candidate metadata are never fallback authority.

Successful writes store versioned `MemoryLineageV1` on the Memory row with the exact Journal parent and selector, derivation/policy version, host-derived origin and committed source time. `ATTRIBUTED_ASSERTION` over `USER_INPUT` is `USER_ASSERTION`; `DIRECT_OBSERVATION` over `EXTERNAL_RESULT` is `EXTERNAL_OBSERVATION`. Hearsay therefore records that a report was made and remains an external claim; the committed receipt does not verify the reported world proposition. Principal, Person binding and audience snapshots are copied from the parent without resolving caller hints or compatibility IDs. Candidate clocks do not replace the parent's `recordedAt`; `occurrenceTime: UNKNOWN` stays unknown in lineage.

PostgreSQL stores the lineage JSONB, consumer key and payload digest with a partial unique consumer-key index. Identical logical replay returns the existing row; conflicting replay fails closed. The in-memory repository follows the same behavior. Historical null-lineage rows are projected as `LEGACY_INCOMPLETE`, without a text/trace backfill. Direct/synthetic Memory writes must be explicitly marked `NON_EVIDENCE`; dashboard candidate acceptance keeps the original host grounding privately, rejects changed content and revalidates before saving. A10.1d grounds Mem0's finalized-turn path before durable child admission; current voice Runtime policy still skips legacy Memory storage if no governed subject is resolved, despite the receipt ancestry being preserved.

## Implemented A10.1d finalized grounding boundary

Runtime and recovery supply the exact committed Journal reference and persisted user text. The same grounding resolver validates them before policy output is admitted. `MemoryWriteEventInput.lineage` and `MemoryEvent.lineage` are vendor-neutral fields. Each durable child freezes a `FINALIZED_INGESTION` lineage before payload digest, event identity and backend key are derived. Source digest includes ancestry, exact source text and policy identity; retries never re-resolve Journal.

The provider reserves a 65,536-byte canonical JSON lineage envelope with encoding version and SHA-256 integrity. Arbitrary caller metadata cannot override it or authority fields. Malformed/conflicting backend lineage causes a safe error/unavailable result, and a malformed applied write response remains ambiguous. Storage scope does not resolve committed principal, Person binding or audience; committed source clocks and real/mock speech distinctions remain exact. Finalized dispatch is always `infer:false`.

Local Mem0 2.2.1 keeps the private 1024-dimensional embedding collection and YUVI PostgreSQL lifecycle. Existing terminal history stays history; nonterminal legacy payloads without required lineage cannot be newly dispatched. Exact post-dispatch reconciliation remains in force. [A10.1d validation](../validation/v0.1.3-a10.1d-grounded-finalized-mem0.md) records real PostgreSQL, sidecar and packaged Linux results. A10.1f1 implements bounded Mem0 source enumeration and local Profile materialization; A10.1f2 implements freshness and regeneration, while f3 closes aggregate A10.1 as IMPLEMENTED REALITY.

## Consumer contract

Every future evidence-backed write carries committed parent IDs and selectors, source/subject/audience/binding scope, producer and policy version, an immutable consumer key and payload identity. The owner validates those fields outside the model output. An index row without valid lineage is unavailable for authoritative use. Unverifiable generated content may be kept as labeled generated output where retention permits, never relabeled user evidence.

A consumer uses a durable checkpoint, idempotent output key and compare-and-set version. If its store is separate, no distributed atomicity is invented: commit derivation and delivery intent locally, then use the existing keyed delivery/reconcile mechanism. Duplicate processing produces the same logical child; a changed derivation version produces a new child with explicit supersession. Sidecar outage is degraded retrieval, not permission to fabricate a memory or mark delivery complete.

Memory extraction may propose statements only from eligible committed source selectors; model output cannot provide authoritative event IDs, clock values, principal or scope. A10.1a fails closed on the optional legacy LLM candidate path while preserving rule-based extraction; A10.1b preserves the committed source reference on conversation rows; A10.1c resolves and validates committed selectors before new legacy evidence-backed writes. A scoped, auditable bounded extractor can be introduced later through the measurement gates. The [remaining-core architecture freeze](v0.1.3-authority-effect-context-architecture-freeze.md) freezes A10.2 controller commands with committed control/A9/native owner lineage. `profile-evidence.ts` currently writes an unsupported compatibility claim directly to Memory; its replacement is a derived Product projection, NON_EVIDENCE if persisted, not a new independent Memory root. Native explicit voice bindings remain with LocalControllerEvidenceProvider.

It distinguishes retrieval candidates from what was actually exposed to the model. A reference to a mutable Mem0 search or “latest profile” is not reconstruction. Persist authorized normalized input/output evidence rather than hidden reasoning. Replay reconstructs views and reducers without calling live tools or claiming nondeterministic model output will repeat bit-for-bit.

## Corrections and legacy data

Journal AMENDMENT remains reserved/not production-active in v0.1.3. Native owner revision/correction changes drive current invalidation: locate descendants, mark invalid/stale, withdraw affected indexes and caches, recompute eligible derivations under a declared version, then atomically replace each owner's current projection pointer. This is not a distributed transaction. While correction is pending, affected material is unavailable for authoritative context. A failed consumer remains visibly behind its checkpoint; unrelated branches remain valid. A new owner correction must not silently erase a genuine later independent observation.

Old rows have incomplete lineage. Import them with an explicit legacy/import producer, import time, retained original timestamps marked source-reported, and declared gaps. Do not fabricate original journal receipts or historical audiences. They may remain available under existing conservative retrieval policy, but cannot count as independent measured support or authenticated identity merely because they were imported. Compatibility adapters are scoped and temporary; new writes cannot use a blanket legacy exception.

The Journal, A9, Memory and correction owners have one-way responsibilities: Journal records causal/control receipts; A9 records command identity/execution; native owners commit revisions; Memory/P8 update their governed meanings and current projections. No production Journal effective-root/AMENDMENT producer or second state reducer is installed. Historical context manifests retain the exact revisions consumed, with explicit retention gaps. [P8 ownership](p8-ownership.md) specifies atomic cutover rules.
