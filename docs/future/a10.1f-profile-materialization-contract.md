## 2. Subject and source-reader ABI

All proposed objects are strict, unknown keys reject, and returned values are deep
copies/read-only. Strings are exact unless a normalization rule is stated below.

```ts
type ProfileSubjectV1 = {
  kind: "MEMORY_SCOPE";
  scope: string;
  subjectReference?: string;
};
type ProfileSourceReadInput = {
  subject: ProfileSubjectV1;
  asOf: string;                 // host-selected ISO UTC instant, once per read
  signal?: AbortSignal;
};
type ProfileSourceReadOutcome = {
  state: "COMPLETE" | "PARTIAL" | "UNAVAILABLE" | "ERROR";
  backend: "legacy" | "mem0" | null;
  sources: ProfileEvidenceSourceV1[];
  reasons: ProfileSourceReadReason[]; // sorted, unique safe codes only
  diagnostics: {
    asOf: string;
    scannedCount: number;
    eligibleCount: number;
    excludedCounts: Record<ProfileExclusionReason, number>;
    exhausted: boolean;
  };
};
interface ProfileMemorySourceReader {
  listEligibleSources(input: ProfileSourceReadInput): Promise<ProfileSourceReadOutcome>;
}
```

`scope` must be the canonical `buildMemoryScope(userId, characterId)` encoding
already owned by `packages/memory/src/scope.ts`: parse then rebuild must equal the
input. Maximum 2,048 UTF-8 bytes; decoded nonempty IDs are at most 512 UTF-8 bytes
each and must already be trimmed. No defaults, wildcard scope or cross-scope merge.
`subjectReference`, when present, is a trimmed, nonempty opaque caller correlation
reference, at most 512 UTF-8 bytes. It is stored in subject identity and changes
the subject key/revision; it never filters evidence, grants access or asserts a binding.
Absence remains absence. It may later correlate a governed People owner to this
scope, but f1 neither resolves nor authenticates it.

None of `subjectUserId`, `personaId`, Product `primaryPersonId`, a display name,
a voice profile/acoustic match, localhost access or controller access authenticates
a Person. Compatibility IDs select a storage partition only. Lineage retains the
actual receipt principal/binding states, including unresolved/conflicting states.
The caller of this internal ABI must already have host-authorized scoped read
access; the ABI is not a public unauthenticated HTTP endpoint.

The composition root selects exactly one reader for the active Memory backend.
No shadow/union read or fallback to another backend on outage. Memory disabled or
no reader configured returns UNAVAILABLE/MEMORY_DISABLED, not COMPLETE with zero sources.
Here “disabled” is an explicit host unavailable-reader/admission condition, not a
new MEMORY_ENABLED environment variable. Existing per-turn readMemory=false must
not invoke generation; disabling writeMemory alone does not erase readable history.

### Completeness, bounds and errors

f1 uses **one bounded snapshot page**, with lookahead. There is no public cursor,
continuation token, paging loop, resumable scan, background job or partial-read cache.
This choice is smaller than retaining a multi-request database snapshot and avoids
the baseline sidecar's unstable prefix/offset pagination entirely.

Fixed f1 limits: 4,096 scoped raw records, one additional lookahead record,
65,536 UTF-8 bytes of content per record, 65,536 bytes of encoded lineage per record,
16,777,216 bytes of canonical normalized eligible sources in aggregate, and
67,108,864 bytes of canonical persisted snapshot. SQL/sidecar request deadline is
30,000 ms. Limits are host policy constants, not caller or model authority. They
apply before/after filtering as specified; never truncate a content or lineage string.

Bound physical IO too: maximum 67,108,864 bytes per raw snapshot/HTTP response.
SQL projections compute raw row byte length and omit an oversized row's large
content/lineage/payload fields with an explicit oversize flag rather than transferring
them. Consume the one SELECT through a server cursor in batches of at most 100;
stop on the raw aggregate byte budget. Such an oversize/early-stop result is PARTIAL
with SOURCE_BYTES_BOUND and an empty source array, not a successful empty snapshot.
The HTTP adapter caps streamed response bytes before JSON.parse and maps overflow
the same way. These internal fetch batches share the single statement/transaction
snapshot; they are not separate offset reads or public continuation pages. Bound
markers are internal framing, never fabricated missing lineage.

| State | Meaning | Returned sources / persistence |
| --- | --- | --- |
| COMPLETE | Snapshot page exhausted within all bounds and every scoped row could be classified safely. Zero eligible sources is valid. | Full eligible set; generation may persist. |
| PARTIAL | Snapshot has >4,096 raw records, an eligible record/aggregate exceeds byte bounds, or the adapter explicitly cannot prove exhaustion. | Valid bounded subset only, with reason; generation returns no snapshot/revision and persists nothing. |
| UNAVAILABLE | Memory disabled, unsupported enumeration mode, connection/service unavailable, timeout or cancellation. | Empty sources; no persistence, even if a prefix was read. |
| ERROR | Malformed lineage/record, cross-scope result, identity conflict, invalid authoritative lifecycle fields or unexpected adapter/storage failure. | Empty sources; discard the whole read, no persistence. |

Read reason enum: `ROW_BOUND`, `CONTENT_BOUND`, `LINEAGE_BOUND`, `SOURCE_BYTES_BOUND`,
`EXHAUSTION_UNPROVEN`, `MEMORY_DISABLED`, `ENUMERATION_UNSUPPORTED`,
`BACKEND_UNAVAILABLE`, `TIMEOUT`, `CANCELLED`, `RECORD_INVALID`, `LINEAGE_INVALID`,
`SCOPE_MISMATCH`, `SOURCE_IDENTITY_CONFLICT`, `BACKEND_ERROR`.
Exclusion reason enum: `LEGACY_INCOMPLETE`, `NON_EVIDENCE`, `PAYLOAD_UNAVAILABLE`,
`UNSUPPORTED_ORIGIN`, `UNSUPPORTED_DERIVATION`, `UNSUPPORTED_SELECTOR`,
`INACTIVE`, `SUPERSEDED`, `NOT_YET_VALID`, `EXPIRED`, `ROOT_RETIRED`.
Initialize exclusion counts to zero. Counts are diagnostic, never evidence identity.
Scope mismatch from an adapter is ERROR, not a count of silently filtered foreign rows.

Known historical missing lineage is a normal exclusion and does not make an
otherwise exhausted read PARTIAL. COMPLETE means complete **eligible Memory set**,
not complete lifetime knowledge or absence of historical gaps. Malformed lineage
is different from absent lineage. Bounds never turn malformed evidence into usable evidence.
Validate/classify all rows in the admitted bounded prefix before returning PARTIAL;
an integrity error outranks partial truncation. The lookahead row proves truncation
only and is never consumed as evidence.

Invalid caller inputs/programmer invariants throw a typed validation error before
IO. Expected outages and evidence/read errors return the outcomes above, with
safe codes and no content, DTO, URL, credentials or stack in diagnostics/logging.
Do not require healthy embeddings or a configured LLM to read existing storage.

## 3. Legacy enumeration

Add `MemoryRepository.listProfileSourceSnapshot({scope, rawLimit: 4096, signal?})`
with PostgreSQL and in-memory parity. Its internal result is
`{records: ProfileLegacySourceRow[], exhausted: boolean}`. `ProfileLegacySourceRow`
contains exactly the native non-vector fields needed to construct section 5,
plus evidence classification and the minimal existing claim metadata needed by
the shared deserializer. Its lineage is untrusted until strictly parsed; it must
not pass through a mapper that fabricates defaults or throws before the reader
can classify the outcome. No new source/evidence table is added.

Add `rawBytesExceeded: boolean` to that internal result for the IO guard above;
on true return no records and exhausted=false. It is false on normal/lookahead
results. Use a read-only transaction for the cursor and always close/rollback
on cancellation/error. The in-memory capture enforces the same byte budget.

The exact row fields are `id`, `subjectUserId`, `personaId`, `scope`, `scopeId`,
`type`, `subtype`, `content`, `status`, `validFrom`, `validUntil`, `expiresAt`,
`supersededAt`, `supersedes`, `supersededBy`, `contradicts`, `lineage` (unknown),
`lineageConsumerKey`, `evidenceClassification` and `claimMetadata` (unknown).
All native nullable columns remain null; times are ISO UTC strings, not Date
instances. `claimMetadata` is only the keys consumed by existing
`deserializeClaimMetadata`, selected from native metadata without exposing the
rest. Require a grounded row's non-null lineageConsumerKey to equal its parsed
lineage.consumerKey. The source reader derives no identity from claimMetadata.

Decode scope to the compatibility user/persona pair. PostgreSQL filters the
**stored first-class** `subject_user_id = userId AND persona_id = characterId`
before LIMIT, orders by UUID `id ASC`, and reads at most 4,097 rows in one SELECT
statement snapshot. Project/user/session/agent/plugin native scopes of rows in
that partition are retained as `nativeScope`, not inferred from content or joined
to other partitions. This subject represents the user×persona partition, not
only the native `scope='user'` subset. `scope_id` remains a domain sub-scope,
not a principal identifier. Rows with null/different partition columns are
outside the requested scope; do not use metadata/default IDs or `mem0Scope` as fallback.
This deliberately tightens the profile read relative to broad legacy prompt retrieval.

Select no embedding column and do not update last-access state. In memory, select
the lowest 4,097 matching UUIDs and clone only their bounded native projections in
one synchronous capture, then classify. Do not clone embeddings/all matching rows
before applying bounds. PostgreSQL `exhausted` is true only when the SELECT
returned <=4,096 rows and the raw-byte guard did not stop it. No count query against
a later snapshot is needed. Native status strings are validated against current
lowercase MemoryStatuses, then interpreted using the uppercase labels below.
Do not use `listRecentMemories`, empty-text search, `retrieveRelevantMemories`,
rank/importance cutoffs, or the lossy Legacy backend adapter.

Consume persisted `supersedes`, `supersededBy`, `supersededAt`, `contradicts`, status
and validity/expiry columns. `MemoryService.applyAutomaticSupersession` marks old
rows separately after admitting a correction; f1 does not rerun its heuristic
relationship detector or finish a partially applied correction. An active row with
only another row's `supersedes` suggestion remains present until its own current
state says superseded; mark the unresolved relationship as section 7 specifies.

## 5. Eligibility and normalized evidence schema

An eligible record has nonempty bounded content and strict GROUNDED
`memory-lineage.v1`, retained/selectable TEXT parents, and one of:

* USER_ASSERTION or EXTERNAL_OBSERVATION with direct derivation
  RULE_BASED_EXTRACTION, EXPLICIT_REMEMBER, CORRECTION or FINALIZED_INGESTION;
* DERIVED with the strict DREAM_DERIVATION shape and per-parent source snapshots.

Exclude ASSISTANT_GENERATED and the older permissive direct-shape DERIVED origin
(no root snapshots), even if the V1 union structurally accepts them. No fabricated
ancestors. All semantic kinds/subtypes may participate as attributed evidence,
including identity, emotional, relationship and commitment **evidence**; none
becomes authoritative identity, affect, relationship or prospective state.
No profile-only personality taxonomy, subtype whitelist, confidence threshold,
semantic similarity, test-name regex or importance ranking. Explicit NON_EVIDENCE
always excludes; conflicting NON_EVIDENCE plus GROUNDED lineage is ERROR.
Explicit ASSISTANT_INFERENCE claim classification also excludes as UNSUPPORTED_ORIGIN;
it cannot acquire original-user authority merely by attaching a user-origin parent.

| Current source state | Eligibility |
| --- | --- |
| Null lineage / valid LEGACY_INCOMPLETE | Exclude, historical gap only. |
| Valid PAYLOAD_UNAVAILABLE | Exclude; never fetch/invent original payload. |
| NON_EVIDENCE | Exclude, regardless of text/identity-looking metadata. |
| ACTIVE | Include only within authoritative validity window. |
| SUPERSEDED, or non-null supersededBy/supersededAt | Exclude, even if status still says active. |
| FORGOTTEN, ARCHIVED, EXPIRED | Exclude. Archival memory layer alone is not archived status. |
| expiresAt <= asOf or validUntil <= asOf | Exclude as EXPIRED even before maintenance updates status. |
| validFrom > asOf | Exclude as NOT_YET_VALID. Null time fields stay null. |
| Malformed lineage, invalid timestamp/status/relationship shape | ERROR; no successful projection. |
| Wrong scope | Database predicate excludes it; if adapter returns it, ERROR. |

After integrity/size validation, choose one diagnostic exclusion reason in this
order: NON_EVIDENCE, LEGACY_INCOMPLETE, PAYLOAD_UNAVAILABLE, unsupported origin,
derivation, selector, SUPERSEDED, INACTIVE (archived/forgotten/expired status),
EXPIRED (time window), NOT_YET_VALID, ROOT_RETIRED. Unsupported selectors are valid
non-TEXT selectors; malformed selectors are LINEAGE_INVALID instead. An oversized
unreadable row stays partial, never an invented exclusion or source. Validate all
readable bounded rows even if their lifecycle would exclude them.

Use the host's one `asOf`, never repeated Date.now calls. Validity is a half-open
window `[validFrom, min(validUntil, expiresAt))`; no recency/elapsed-time inference.
f1 trusts the frozen host lineage from c/d/e, does not re-resolve Journal payloads
on every read, and makes no claim that it has processed future amendments. f2 owns
change-driven invalidation; A10.3 owns broader current disclosure/context validation.

```ts

  memoryId: string;             // legacy:<UUID> or existing mem0:<UUID>

  memory: ProfileMemoryRef;
  scope: string;                // canonical subject storage partition
  nativeScope: { kind: MemoryScope; scopeId: string | null } | null;
  kind: MemoryEventKind;
  subtype: MemorySubtype | null;
  content: string;
  claimClass: MemoryClaimProvenanceClass | null; // descriptive, no identity resolution

```

Every field above is mandatory, except the subject's optional reference. Embedded
types reuse existing schemas; do not redefine principal/binding/audience/time or
lineage shapes. Bounds: memory IDs/references <=512 UTF-8 bytes, native scopeId
<=512 bytes or null, relationship arrays <=4,096 unique refs, roots <=256 unique
ref/selector pairs per source. Bound violations make the read PARTIAL, invalid
shape makes it ERROR. Every reference's backend must match this read's backend.

Legacy kind mapping is mechanical: CORRECTION lineage → correction;
EXPLICIT_REMEMBER → user_claim; otherwise type episodic → episodic; otherwise fact.
Keep native subtype as stored. Read claimClass via the existing claim deserializer,
or null when absent; do not manufacture SELF_REPORT from compatibility IDs.
Legacy content is exact stored content; Mem0 content is the existing semantic
mapper's trimmed content. `subtype`/`nativeScope` are null for Mem0, whose current
mapper supplies kind and optional claim class. Never re-extract a subtype from text.

The materializer sees no embedding, raw provider DTO, raw metadata, confidence
score, summary, credentials, audio/images, voice match or invented time. Original
source clocks and authority snapshots are available only through lineage/roots.

## 6. Roots, Dream and inherited constraints

For direct lineage, construct each root constraint from its parent ref/selector
and its existing authority/origin/sourceTime. For Dream, use the existing
`sources[]` snapshots exactly, never Dream job/episode/backend timestamps or an
invented aggregate authority. Parent/source disagreement fails the existing schema.

`rootKey` identifies the original **Journal receipt**, using namespace+eventId,
not Memory ID, consumer key, text, model, episode or Dream event. Different selectors
of the same receipt share a root key, conservatively preventing fragmentation from
creating independence. Retain every distinct selector/authority snapshot separately.
Conflicting snapshots for the same ref+selector within this read are ERROR.

Direct A plus Dream(A) may remain two attributed representations, but their root
union contains A once. f1 reports root references, **never a confirmation count,
independence assertion or confidence increase**, even for different receipts.
Same text with different roots is not deduplicated as one logical source. No
semantic similarity is involved.

Legacy raw snapshot includes retired direct sources. If an otherwise eligible
Dream shares any rootKey with a scoped grounded direct source currently superseded,
forgotten, archived or expired (including time expiry), exclude the entire Dream
as ROOT_RETIRED. Do not trim individual parents from an immutable derived claim.
This is a conservative guard, not a new correction authority. It may withhold an
entire multi-parent derivation; unrelated direct sources stay eligible. Not-yet-valid
direct rows do not establish retirement. Mem0's present-only view has no such
tombstone proof; do not pretend missing Memory parents invalidate original Journal
roots. Cross-backend erasure and complete descendant invalidation are not claimed.

Entry constraints are the sorted deduplicated union of its sources' root
constraints. Preserve PRIVATE(channelRef), GROUP(channelRef, exact KNOWN/UNKNOWN/
INCOMPLETE membership snapshot) and UNKNOWN(reason) separately, along with actual
principal/binding states. A heterogeneous entry keeps the entire constraint array.
No synthesized PUBLIC, broader group, preferred private recipient, aggregate
membership, guessed Person or intersection-only permission. UNKNOWN is unknown,
not unrestricted. f1 stores constraints; later disclosure owners decide if/how
content may be used. Returning a snapshot through this ABI grants no disclosure.

## 7. Deterministic materializer and conflict rules

Policy ID: **`a10.1f1-deterministic-evidence.v1`**. It is pure code, takes only the
subject and COMPLETE eligible sources, and does not read an old profile. It needs
no LLM, embedder, hosted profile service, provider ranking or free-form narrative.

1. Validate, canonicalize and sort sources as section 9 defines.
2. Group by exact `(scope, lineage.consumerKey)`. Identical semantic payloads
   excluding only physical `memory` identity collapse to one logical entry,
   retaining every sorted physical evidence reference. Different content, lineage,
   native scope/kind/subtype, claim class, lifecycle or relationship state for the
   same logical key is SOURCE_IDENTITY_CONFLICT; fail generation with no snapshot.
3. One logical source gives one entry, copying content exactly. Equal content under
   different consumer keys remains separate; no paraphrase merging or corroboration.
4. Resolve **explicit stored** relationship refs only against eligible references.
   If either side's contradicts targets another eligible entry, symmetrically mark
   both CONFLICTING and link entry IDs. If an eligible source's supersedes targets
   another still-eligible source, also link them as unresolved supersession and
   mark both CONFLICTING; do not apply a lifecycle update yourself. Never choose by
   timestamp, confidence, importance, embeddings or model judgment.
5. A relationship to an excluded/missing source is retained in the source record
   but does not create a phantom entry or conflict with an absent entry. A self-link,
   or a link between two physical aliases of the same logical entry, is an integrity
   error. Reference cycles between distinct active entries remain unresolved conflicts.
6. Unlinked contradictory prose remains separate, unverified and **NOT_ASSESSED**
   for semantic conflict. f1 cannot discover natural-language negation/conflict.
   Absence of an explicit link never asserts agreement or truth. No winner or merged
   proposition is emitted. Hearsay content stays verbatim, with its claimClass and
   root provenance; no removal of “X said”, verification upgrade or subject substitution.
7. DIRECT/DERIVED comes only from lineage. Dream stays DERIVED/system evidence;
   do not relabel it original self-report. Identity-related content is just an entry,
   not a Person field, principal binding, acoustic binding or authored identity.
8. Empty COMPLETE set produces INSUFFICIENT_EVIDENCE with no entries. Explicit
   active conflicts produce PARTIAL generation state, with all entries retained.
   Otherwise generation state is COMPLETE. “COMPLETE” describes projection coverage,
   not verified knowledge, semantic conflict detection or current People freshness.
9. Non-COMPLETE source enumeration returns its outcome without materialization or
   persistence. There is no profileRevision for a truncated/unknown eligible set.
   Snapshot byte overflow returns FAILED/SNAPSHOT_BOUND without persistence.

## 8. Strict profile schema

Name/version: **`yuvi-profile.v1`**. Implement with exported strict Zod schemas and
derived TypeScript types, consistent with existing lineage conventions. No separate
JSON Schema generator/dependency is required. All nullable fields below are required
and never silently omitted. Narrative is mandatory null in this version.

```ts
type ProfileEntryV1 = {
  entryId: string;              // pe1_<SHA256({scope, consumerKey})>
  content: string;              // exact source content, no extra proposition
  kind: MemoryEventKind;
  subtype: MemorySubtype | null;
  claimClass: MemoryClaimProvenanceClass | null;
  status: "EVIDENCE" | "CONFLICTING";
  epistemicStatus: "UNVERIFIED";
  derivation: "DIRECT" | "DERIVED";
  evidenceRefs: ProfileMemoryRef[]; // nonempty, resolves into sourceSet.sources
  rootEvidenceKeys: string[];   // nonempty, sorted unique root keys
  constraints: ProfileRootConstraintV1[]; // nonempty exact inherited union
  conflictAssessment: "EXPLICIT_LINKS_ONLY";
  semanticConflictAssessment: "NOT_ASSESSED";
  conflicts: {entryId: string; reason: "CONTRADICTS" | "UNRESOLVED_SUPERSESSION"}[];
};
type ProfileSnapshotV1 = {
  version: "yuvi-profile.v1";
  subject: ProfileSubjectV1;
  profileRevision: string;
  producer: {
    providerId: string;
    providerVersion: string;
    materializerVersion: string;
  };
  generationState: "COMPLETE" | "PARTIAL" | "INSUFFICIENT_EVIDENCE";
  generatedAt: string;         // host asOf of first persisted generation request
  sourceSet: {
    completeness: "COMPLETE";
    backend: "legacy" | "mem0";
    sourceSetDigest: string;
    sources: ProfileEvidenceSourceV1[];
  };
  entries: ProfileEntryV1[];
  narrative: null;
};
```

Maximum 4,096 sources/entries and evidence references per entry. Conflict arrays
have an 8,192 bound (two reasons per peer); constraint/root arrays may union at most 256 roots per logical
entry since aliases must have identical semantic payloads. Each conflict edge is
unique by `(entryId, reason)`. Source/entry content bounds are unchanged.
Validate hashes, references, exact copied fields, root unions, symmetric conflict
links, generation-state derivation and no extra/ungrounded entry on load and put.
Keep source payloads in the snapshot so a later mutable Memory read cannot silently
rewrite the historical basis. They are copies of evidence indexes, not new receipts.
Producer IDs/versions are nonempty opaque strings <=160 UTF-8 bytes. The local
implementation uses exactly the constants in section 11; the ABI/schema allows a
future declared provider/policy, without granting it authority or hosted features.

## 9. Canonical identities

Use SHA-256 over UTF-8 `canonicalLineageJson` (the existing sorted-object-key
function). Digests are 64 lowercase hexadecimal characters, never truncated.
No locale-dependent sorting: use ordinal JS string comparison; UUIDs use lowercase
canonical UUID strings. Validate native IDs instead of trimming/coercing aliases.
All schema-required nullable fields serialize as null. Optional subjectReference
is omitted when absent. Strings otherwise retain exact code points: no extra NFC,
whitespace collapsing, case folding or timestamp manufacture. Timestamp fields
are normalized to ISO UTC when their existing semantic schema represents an instant;
opaque clockSource, reasons and refs are preserved.

Arrays with set semantics are deduplicated by canonical JSON and sorted by that
JSON: relationship refs, root constraints, lineage parents and Dream sources.
Principal/binding candidate arrays also have set semantics: canonical-sort and
deduplicate them in every authority snapshot, then revalidate the existing schema
(an ambiguous/conflicting state must still have at least two distinct candidates).
For Dream, sort sources then rebuild parents from the sorted sources so the
existing parent/source schema invariant holds. Do not reorder semantic content.
`lineageDigest = SHA256(canonicalLineageJson(canonicalized parsed lineage))`;
this semantic digest may differ from a Mem0 transport digest that preserved a
different parent-array order. Decode/validate the transport digest first, using
the existing decoder, never substitute one digest for the other.

Sort normalized sources by `(memory.backend, memory.sourceRecordId)`; duplicate
physical IDs must have identical full normalized payloads or produce ERROR.
Sort entries by entryId, evidenceRefs by canonical JSON, conflicts by canonical
JSON, and rootEvidenceKeys ordinally. Physical aliases stay in sourceSet; collapsing
a logical entry does not delete evidence references or pretend migration IDs match.

```text
sourceSetDigest = SHA256(canonicalLineageJson({
  version: "yuvi-profile-source-set.v1",
  sources: canonicalSortedEligibleSources
}))

subjectKey = "ps1_" + SHA256(canonicalLineageJson(subject))

profileRevision = "pf1_" + SHA256(canonicalLineageJson({
  schemaVersion: "yuvi-profile.v1",
  materializerVersion, // exact declared policy; f1 local value is fixed above
  subject,
  sourceSetDigest
}))

entryId = "pe1_" + SHA256(canonicalLineageJson({scope, consumerKey}))
rootKey = "pr1_" + SHA256(canonicalLineageJson(JournalEventRef))
```

The source-set input is exactly section 5's normalized source objects, including
stable physical identities, content, canonical lineage/digest/consumer identity,
kind/subtype/claim class, native scope, authoritative validity and correction state,
and root constraints. This binds every input that can change a materialized entry.
Effective exclusions remove sources; retiring a source therefore changes the set.
No excluded-row prose/counts, query score, row order, vector, access/update/retry
time, deadline, asOf, generatedAt or request/job ID enters these identities.
Current time can change which sources are eligible at expiry; it never changes
identity when the effective eligible semantic source set is unchanged.

**Same eligible semantic source set → same sourceSetDigest. Same subject/schema/
policy/set → same profileRevision.** Backend migration with new physical IDs is a
new source set, not an asserted cross-backend identical revision. COMPLETE-empty
sets share a digest; backend still appears in snapshot, so see the collision rule
below before changing active backends with an empty set.

For an empty set, sourceSet.backend is diagnostic provenance and is excluded from
the logical payload comparison, just like generatedAt. On replay retain the first
stored backend; the generation outcome reports the current read's backend separately.
For nonempty sets backend is bound by every source. This is the only additional
nonlogical snapshot field; all other fields are compared. This rule prevents empty
legacy→Mem0 activation from causing a false same-revision payload conflict.

Any implementation that changes schema/projection meaning must change the
materializer policy version. Provider/model metadata is descriptive, never stronger
authority; a future adapter needs its own declared materializer version if output
differs. A same-revision conflicting logical payload fails closed, even if caused
by an alleged SHA collision. Never salt a digest, overwrite, or mint a random revision
to conceal nondeterminism. PARTIAL enumeration never collides with a COMPLETE
snapshot because it is not persisted and has no revision.

## 10. Immutable persistence contract

```ts
interface ProfileSnapshotStore {
  putImmutable(snapshot: ProfileSnapshotV1): Promise<{
    disposition: "CREATED" | "REPLAY";
    snapshot: ProfileSnapshotV1; // original stored copy, including generatedAt
  }>;
  getRevision(input: {subject: ProfileSubjectV1; profileRevision: string})
    : Promise<ProfileSnapshotV1 | null>;
  getCurrent(input: {subject: ProfileSubjectV1}): Promise<ProfileSnapshotV1 | null>;
}
```

`putImmutable` recomputes/validates revision, source digest and references. Its
logicalPayloadDigest is SHA256 of canonical snapshot excluding generatedAt and,
only for empty sets, sourceSet.backend. Same address+same logical digest returns
the first persisted payload. A differing logical payload throws
`ProfileSnapshotConflictError` with safe code PROFILE_REVISION_CONFLICT; no write
or pointer change. Compare canonical logical payload as well as digest to reject
a detected collision. Deep clones ensure in-memory and PostgreSQL immutability.

Primary identity is `(subjectKey, profileRevision)`. Neither Person ID nor backend
job is a primary key. `getRevision` is an exact scoped historical read, never fallback
to another subject/revision. `getCurrent` means **last successfully explicitly
selected persisted revision**, not known-fresh current evidence or People.Model.
Each successful put, including a replay of an older revision after source state
returns to it, atomically selects that stored revision. An outage/failed/partial
read never clears or advances the pointer. Concurrent puts serialize per subject;
last successful pointer transaction wins. No timestamp-based source precedence.
f2 replaces this minimal selection with source-aware freshness/CAS orchestration.

Expected migration: `packages/memory/migrations/017_profile_snapshots_v1.sql`.
Implement idempotently using the existing lexicographic migration runner. Schema:

```text
profile_snapshots
  subject_key TEXT NOT NULL
  profile_revision TEXT NOT NULL
  subject JSONB NOT NULL
  schema_version TEXT NOT NULL (= yuvi-profile.v1)
  materializer_version TEXT NOT NULL
  source_set_digest TEXT NOT NULL (64 lowercase hex)
  logical_payload_digest TEXT NOT NULL (64 lowercase hex)
  payload JSONB NOT NULL
  generated_at TIMESTAMPTZ NOT NULL
  stored_at TIMESTAMPTZ NOT NULL DEFAULT now()   -- operational only
  PRIMARY KEY(subject_key, profile_revision)

profile_current
  subject_key TEXT PRIMARY KEY
  profile_revision TEXT NOT NULL
  selected_at TIMESTAMPTZ NOT NULL DEFAULT now() -- operational only
  FOREIGN KEY(subject_key, profile_revision)
    REFERENCES profile_snapshots(subject_key, profile_revision)
```

SQL checks enforce object/version, ps1_/pf1_ hash formats and mirrored subject,
revision, digest, materializer and generatedAt columns against payload (instant
comparison for timestamp). Application strict validation enforces the complete
contract. Transaction-scoped per-subject advisory lock precedes insert/reload,
comparison and current-pointer upsert; rollback on conflict. No UPDATE to snapshot
payload, append-on-replay, original-evidence FK/cascade, historical backfill or dirty
column. The in-memory store serializes the same per-subject put and pointer sequence.
Reuse the AppContext-owned Pool without closing a shared Pool from this repository.
No new database daemon, collection, vector migration or custom migration runner.
In composition, use PostgreSQL whenever AppContext.databasePool exists (independent
of the active Memory backend); otherwise use the in-memory development/test store.
Do not silently fall back to memory when PostgreSQL is configured but unavailable.

Stored snapshots contain the strict schema, exact eligible source copies and
constraints, logical revision/digests, producer/policy and first generatedAt.
Operational timestamps live in store columns. Read diagnostics and excluded raw
records are not persisted. There is no f1 deletion API; later privacy machinery must
also account for retained derived copies. Immutability is logical replay integrity,
not permission to bypass future authorized erasure.

## 11. ProfileProvider ABI and lifecycle

```ts
type ProfileProviderCapabilities = {
  providerId: string;
  providerVersion: string;
  localPrivate: boolean;
  hosted: boolean;
  asyncGeneration: boolean;
  schemaVersion: "yuvi-profile.v1";
  materializerVersion: string;
  sourceBackends: ("legacy" | "mem0")[];
};
type ProfileFailureCode =
  | "SOURCE_UNAVAILABLE" | "SOURCE_ERROR" | "SOURCE_PARTIAL"
  | "SNAPSHOT_BOUND" | "STORE_UNAVAILABLE" | "STORE_ERROR"
  | "PROFILE_REVISION_CONFLICT" | "GENERATION_NOT_FOUND";
type ProfileReadOutcome =
  | {state: "COMPLETE" | "PARTIAL" | "INSUFFICIENT_EVIDENCE";
     snapshot: ProfileSnapshotV1; freshness: "UNCHECKED"}
  | {state: "NOT_FOUND"; snapshot: null}
  | {state: "FAILED" | "UNAVAILABLE"; snapshot: null; code: ProfileFailureCode};
type ProfileGenerationOutcome =
  | {state: "COMPLETE" | "PARTIAL" | "INSUFFICIENT_EVIDENCE";
     snapshot: ProfileSnapshotV1; persistence: "CREATED" | "REPLAY";
     sourceRead: ProfileSourceReadOutcome}
  | {state: "PARTIAL" | "FAILED" | "UNAVAILABLE"; snapshot: null;
     code: ProfileFailureCode; sourceRead: ProfileSourceReadOutcome | null}
  | {state: "PENDING"; snapshot: null; generationId: string};
type ProfileGenerationStatus =
  | {state: "PENDING"; generationId: string}
  | {state: "COMPLETE" | "PARTIAL" | "INSUFFICIENT_EVIDENCE";
     generationId: string; subject: ProfileSubjectV1; profileRevision: string}
  | {state: "FAILED" | "UNAVAILABLE"; generationId: string; code: ProfileFailureCode};
interface ProfileProvider {
  capabilities(): ProfileProviderCapabilities;
  getProfile(input: {subject: ProfileSubjectV1; profileRevision?: string;
                     signal?: AbortSignal}): Promise<ProfileReadOutcome>;
  generate(input: {subject: ProfileSubjectV1; signal?: AbortSignal})
    : Promise<ProfileGenerationOutcome>;
  getGenerationStatus?(input: {subject: ProfileSubjectV1; generationId: string;
                              signal?: AbortSignal})
    : Promise<ProfileGenerationStatus>;
}
```

Successful read/generation state must equal snapshot.generationState. PARTIAL with
a snapshot means explicit unresolved evidence conflict over a COMPLETE source set;
PARTIAL with null snapshot means incomplete enumeration. Consumers check the
discriminant and snapshot presence, never interpret either as current Person truth.
NOT_FOUND means no stored snapshot at that address, not no Memory/no Person.

Local capabilities are exactly providerId `yuvi-local-profile`, providerVersion `1`,
localPrivate=true, hosted=false, asyncGeneration=false, schemaVersion yuvi-profile.v1,
materializerVersion a10.1f1-deterministic-evidence.v1, sourceBackends `["legacy","mem0"]`.
This advertises implementations supported, not that both backends are enabled.
Local generate is synchronous, returns only after persistence, never PENDING, and
omits getGenerationStatus entirely. No fictional hosted job, request ID or scheduler.

getProfile performs store reads only; no enumeration/generation side effect. Missing
profileRevision selects getCurrent; an explicit revision selects getRevision. It
always reports freshness UNCHECKED: f1 cannot certify source freshness. Stored history
can be read when Memory is disabled, but generate returns UNAVAILABLE and cannot
manufacture an empty profile. Store outage returns UNAVAILABLE; corrupted stored
schema/digests return FAILED/STORE_ERROR. Never silently return an older snapshot
as the result of a failed generation.

Explicit local lifecycle:

```text
host-authorized generate(subject)
→ capture asOf once
→ active backend's scoped bounded source reader
→ COMPLETE? otherwise return null snapshot with explicit outcome
→ canonical eligible source set / sourceSetDigest
→ deterministic entries, conflicts, constraints / profileRevision
→ set generatedAt to captured asOf (replay retains the original value)
→ validate strict snapshot / byte bound
→ putImmutable and atomic explicit-current selection
→ return original stored snapshot + CREATED/REPLAY + current read diagnostics
```

Map source PARTIAL→PARTIAL/SOURCE_PARTIAL; UNAVAILABLE→UNAVAILABLE/SOURCE_UNAVAILABLE;
ERROR→FAILED/SOURCE_ERROR. Snapshot integrity/identity failure maps to SOURCE_ERROR,
revision conflict to FAILED/PROFILE_REVISION_CONFLICT. Store availability vs corrupt/
unexpected store errors map separately. Expected cancellation before put maps to
UNAVAILABLE; once a put starts, complete its bounded atomic transaction and report
its actual result, never pretend it did not persist. No automatic generation retry.
Unexpected defects may throw at internal pure-function/repository boundaries;
provider catches IO failures into safe outcomes, while invalid caller input throws
the programmer validation error. Do not catch bugs and label them empty evidence.

The optional async ABI preserves opaque generationId from a future provider and
optional status lookup without imposing jobs on local code. An async adapter's
eventual revision still identifies a validated frozen YUVI source set and declared
policy. Actual hosted adapter configuration, idempotency, retries, durable jobs,
privacy and upstream schema validation are outside this task/f1 baseline.
Future generation IDs are nonempty opaque strings <=512 UTF-8 bytes; status lookup
is scoped to the supplied subject and cannot resolve a foreign subject's job.
