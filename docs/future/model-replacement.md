# Model replacement as a release gate

Status: **PRODUCTION ARCHITECTURE DECISION** for separable continuity contracts; **PLANNED ENGINEERING** for the later release harness; complete cross-model continuity remains a **RESEARCH HYPOTHESIS**.

A foundation model is replaceable computation, not the sole custodian of history. Preserve journal evidence, identity bindings, prospective items, explicit projections and their versions outside vendor prompts/weights. A4's canonical context and provider adapters are current assets, not proof that replacing a model preserves behavior.

| Continuity axis | Required test and owner |
| --- | --- |
| Factual and obligation continuity | Correct attribution, correction, scope and unresolved-outcome handling; prospective closure/overdue tests; journal and prospective owners |
| Relationship and preference continuity | Same eligible evidence supports appropriately bounded projections and relevant choices; blind source intervention and ablation; explicit integrator owner |
| Normative continuity | Charter, permissions, disclosure, uncertainty and no self-generated authority remain enforced; governed policy / Runtime |
| Style continuity | Voice, phrasing, persona expression and user preference, measured separately; Character/provider/presentation |

No single “same person” or likeness score can mask an obligation leak or normative failure with improved style. Critical authorization, disclosure, attribution and false-closure cases must have zero failures in the release suite; report confidence limits and suite size rather than claiming a universal zero risk. Noncritical preference/style tolerances and cost/latency limits are preregistered per release.

Pin old/new model/provider versions and configuration; run paired frozen histories, real consented holdouts and human-blinded judgments, including disagreement and safety cases. Record unsupported capabilities and model-specific dependencies. If factual/obligation or normative gates fail, block replacement; if only style changes within declared tolerance, report it independently. Do not fine-tune a new model to conceal a broken evidence pipeline.

Models differ in priors, instruction following and interpretation. Portability is necessarily partial and empirical. A projection that one model ignores or overweights may need a versioned presentation adapter, but adapters may not mutate historical evidence to make scores look stable. Every optional Z/post-training artifact needs its own deletion/retraining and replacement test. Post-training remains an optional experiment after explicit mechanisms, not an architecture requirement.
