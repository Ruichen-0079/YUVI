## 2. Publication means a candidate; freshness is a read proof

The smallest correct design has **two independent pointers**:

* f1 `profile_current`: last explicitly persisted/selected revision, unchecked;
* f2 `candidate_revision`: revision successfully selected by the fenced generation
  procedure, potentially exposable after a fresh live check.

Neither is durably labelled CURRENT. A successful f2 selection records the source
observation it passed; it never promises that no future or unobserved write occurs.
**Every People.Model read performs a new complete bounded source read.** There is
no freshness TTL, timestamp-only proof, digest cache, fallback to a historical
snapshot or “current because regeneration finished” shortcut.

A proof means equality to the admitted Memory row snapshot returned by that read,
with f1 eligibility evaluated at its captured host `asOf`. It is an observation
boundary, not a perpetual guarantee or proof about queued/unapplied writes. An
overlapping mutation may linearize after that source read; the next read must see
its resulting source state. An already returned value cannot be remotely revoked.
`asOf` is reported explicitly, not renamed last-modified/current-source revision.
Time affects eligibility exactly as frozen in f1; it is never sufficient evidence
of freshness. Subsequent consumers must perform their own bridge read rather than
reuse an earlier proof. No claim of an atomic distributed Mem0+YUVI transaction is made.

This deliberate live-read requirement closes the notification-loss gap on both
backends. Invalidation improves withholding latency and regeneration scheduling;
it cannot replace evidence comparison. Publication is a CAS of a candidate reference,
not the exposure of stale prose as currently certified People.Model.

## 3. Minimal state, derived states and transitions

Persist one control row per **explicitly enrolled f1 subject**, keyed by the existing
`profileSubjectKey(subject)`. Optional `subjectReference` remains opaque; multiple
references in one scope have separate rows, all invalidated by scope changes.
Enroll on an authorized internal scope-model read or generation request only.
Mutation hooks do not invent subjects/Person mappings or materialize every scope.

Persist: subject/scope, control version, regeneration-needed flag, observed source
digest/backend/read outcome, candidate reference and its verification observation,
attempt budget/due time, lease fencing identity, last safe reason/error. History
remains entirely in the f1 store. Process-local: reader/provider handles and their
composition token, AbortControllers, timers, worker promise, wakeup flag and
ephemeral read proofs. A proof never survives process restart as current authority.

Observable state has orthogonal axes; do not store a single overloaded enum:

```ts
type ScopeProfileStatus = {
  subject: ProfileSubjectV1;
  controlVersion: string; // unsigned decimal bigint, never JS Number
  candidateRevision: string | null; // diagnostic address, no content
  evidenceState: "NO_PROFILE" | "UNCHECKED" | "STALE" | "VERIFIED";
  regenerationRequired: boolean;
  workState: "IDLE" | "WAITING" | "RUNNING" | "BLOCKED";
  lastError: ProfileLifecycleError | null;
};
```

`VERIFIED` exists **only in a successful live model read**. A status-only read
returns UNCHECKED for a clean candidate, STALE if it has a known invalidation or
digest mismatch, NO_PROFILE if no f2 candidate exists. No candidate can coexist
with VERIFIED unless all section 5 conditions hold. STALE includes possibly stale:
an invalidation need not already have produced different semantic content.
No candidate plus regeneration error remains NO_PROFILE with BLOCKED/error.
Work state: RUNNING for a currently valid lease; WAITING for needed/due-or-delayed
work with attempts remaining; BLOCKED for a disabled source, unsupported/integrity
condition or exhausted budget; otherwise IDLE. An expired lease is reclaimable work,
never proof that a cancelled or crashed attempt succeeded.

| Authoritative trigger | Durable transition | Observable / exposure consequence |
| --- | --- | --- |
| First authorized enrollment | Insert row, version 0, needed=true, due now+250ms, no candidate | NO_PROFILE/WAITING; return no content. |
| Explicit generation request | Increment control version; needed=true; reset budget; due at most now+250ms | Candidate becomes STALE; requests coalesce into the same row. |
| Known relevant source mutation notification | Increment version; needed=true; record reason; reset budget for new version; bounded due time | Old candidate withheld, including during in-flight work. |
| Complete verifier observes a different backend/digest from last observation | Save observation; increment version and request work | STALE or NO_PROFILE; old candidate withheld. |
| Complete verifier observes unchanged state | Update diagnostic observation only | Does not clear dirty, a generation failure or budget exhaustion. |
| Verifier returns PARTIAL/UNAVAILABLE/ERROR | Save safe outcome/error; withhold; worker cannot select | No empty success, no pointer fallback; polling may seek recovery. |
| COMPLETE follows a non-COMPLETE source observation | Record recovery; request one new work version | A retry is allowed once on this transition, not on every poll. |
| Due row successfully claimed | Increment lease fence, set owner/until and claimed version; needed stays true; increment that version's attempt count | RUNNING. |
| New invalidation during RUNNING | Increment control version; retain old lease; needed=true | Attempt is obsolete; eventual result cannot clear the newer work. |
| Successful generation and all selection fences pass | Set candidate/ref/digest/backend/version/verification asOf; needed=false; clear own lease/error/due | IDLE/UNCHECKED; content still requires a live read proof. |
| Evidence/composition/version fence fails | Keep candidate unchanged, needed=true; release own lease; schedule latest version | STALE; obsolete result may exist in immutable f1 history only. |
| Failure | Keep candidate unchanged, needed=true; record safe error; release own lease; retry or block | Prior profile is never blessed as fresh. |
| Cancellation/shutdown/crash/lease expiry | No publication; leave needed=true; release own lease when possible, otherwise reclaim after expiry | History may include a completed f1 put, but no model proof. |
| Authorized source unavailable / Memory disabled | Withhold model; needed work blocked; preserve candidate/history | UNAVAILABLE on content read. Re-enable needs complete verification and fenced generation. |

Changing control state requires short transactions with row locks/CAS. There is
no row/advisory lock held across source IO, generation or HTTP. Version and lease
fence increments are transactional, monotonically increasing, overflow fails closed.
Candidate/control reads and transition transactions use the primary shared store,
not a lagging replica. A failed attempt may update error/budget/due only for its
exact claimed control version; if V has advanced, it may release its own F/owner
lease but must preserve the newer version's reason, error, budget and pending work.

### Hook ordering and loss recovery

Legacy notifications occur **after** the source statement commits (in memory,
after synchronous mutation), not atomically with it. Changing original Memory
transaction semantics or requiring Profile availability for erasure is unnecessary:
no model content is served without live evidence comparison. Hooks capture minimal
scope identity, emit safe failure diagnostics, and return the original mutation
outcome; a notification failure never changes “applied” into “not applied”.

Mem0 wrappers invalidate best-effort **before remote dispatch and in finally after**
dispatch returns/throws. Pre-invalidation promptly withholds known candidates;
finally handles outcomes including ambiguous effects. Neither is evidence of remote
commit or a distributed transaction. Await each bounded notification at most 1s;
on failure mark process-local hook health degraded, log code only, and continue the
existing source operation (especially withdrawal). One already dispatched mutation
must not be aborted/replayed just because Profile notification failed. Remote late
completion remains detectable by live reads and polling, not by timeout assumptions.

Do not attach hooks only to the UI or delivery success statuses. Repository and
shared backend mutation seams cover current bypasses; probe wrappers use original
frozen payload scope rather than guessing from a provider ID. Invalidation targets
only already-enrolled control rows. Failure during notification is a liveness loss,
not permission to return a cached certificate. Profile store failure makes model
reads unavailable; a recovered store still needs a complete live source check.

## 5. Exact freshness and selection algorithm

The composition root supplies a captured handle `{reader, provider, backend,
compositionToken}`. Reader and provider resolve the **same captured MemoryService**.
Reuse `LocalProfileProvider.generate`, configured with that reader and the existing
f1 store; this is composition of the existing generator, not a second materializer.
The original f1 ABI, `getProfile` and immutable store semantics remain unchanged.
Swap/invalidate this handle when the active service changes; an opaque process-local
token detects replacement but does not authenticate Person or name a Memory revision.
Do not rely on the existing boot closure tracking `context.memory` on reload.

Define `D(read)` only for COMPLETE reads: canonicalize using f1
`canonicalizeProfileEvidenceSource`, exact physical-ID deduplication/conflict checks,
ordinal backend/record ordering and existing `profileSourceSetDigest`. Reuse the
same canonical rules, not a new lineage parser or alternative digest/policy.
Malformed/partial/oversized/unsupported sources have no certifiable digest.
Audit observations and live-read mismatches apply control transitions under a row
lock; a worker's pre/generator/post reads do not independently increment their own
captured V. Only final fenced selection records their successful observation.

### Generation and candidate selection

1. Claim one due control row in a short transaction, increment lease fence and
   capture `(subjectKey, controlVersion=V, leaseFence=F, owner)`. Capture one reader/
   provider handle H. Needed remains true while generating.
2. Perform COMPLETE pre-read at its own fresh host asOf: token
   `T = {subjectKey, V, F, H.compositionToken, backend, Dpre}`. If it fails, handle
   its typed outcome without calling the generator or selecting a candidate.
3. Call H.provider's existing explicit f1 `generate(subject, signal)`. It does its
   own complete read and immutable put. Require a returned snapshot, current schema/
   policy/capabilities, valid subject and `Dgen === Dpre`, and the actual sourceRead
   backend equal H.backend. Do not use stored snapshot backend alone: empty replay
   deliberately retains the original backend as diagnostic provenance in f1.
4. Perform a **new** COMPLETE post-read with fresh asOf through H.reader. Require
   `Dpost === Dgen === Dpre`, same active backend and H still active. Do not infer
   this from generation timestamps, excluded counts or success of a keyed write.
5. In one control-store transaction, CAS requires exact V/F/owner, unexpired lease,
   needed=true and no cancellation/replacement. Set candidate to the returned f1
   revision, digest, actual verified backend, candidateVersion=V and post-read asOf;
   clear needed, error and own lease atomically. Record latest COMPLETE observation.
   Profile snapshot existence is required by FK. No mutation of snapshot or f1
   current pointer is performed by this transaction.
6. Return `SELECTED` with candidate revision and **observation metadata**, never
   `freshness=CURRENT`. A People.Model read uses the next procedure. If any compare
   fails, do not select; retain needed and run the latest request within bounds.

This three-read procedure is intentionally conservative about ABA during generation:
control-version change rejects even if D returns to its original value. Later stable
generation can replay the old `pf1_` revision under a newer control version.

### People.Model live read fence

1. Validate/authorize exact scope subject. Enroll if absent; do not generate inline.
   Memory-disabled/readMemory=false returns UNAVAILABLE with no source/store content
   read. Person-only input is rejected as section 7 specifies.
2. Read control row and exact candidate revision from the **historical f1 address**,
   never `getProfile()` without a revision. Return no model if no candidate, needed,
   lease/in-flight obsolete work, generation error or corrupt/missing snapshot.
3. Capture active handle H and control tuple `(V, candidateRevision, candidateVersion)`.
   Perform a new COMPLETE read, canonical Dlive, preserving reader bounds. Require
   candidateVersion=V, Dlive=candidateDigest=snapshot.sourceSetDigest and actual
   backend=candidateBackend=H.backend. Validate snapshot/schema/materializer without
   changing it. Reject H replacement/cancellation.
4. Re-read control tuple in a short transaction, requiring unchanged V and candidate,
   needed=false, no error and no valid work lease. Only this call may construct the
   transient VERIFIED result with the live proof. A raced known invalidation returns
   WITHHELD. No proof is stored as permanently current.
   Check the local composition/cancellation token again after the final await and
   immediately before assembling the result; no IO follows that check.
5. Mismatch conservatively requests coalesced regeneration and returns WITHHELD;
   non-COMPLETE returns PARTIAL/UNAVAILABLE/FAILED with null model. If writing the
   invalidation fails, still withhold. No inline generation, semantic arbitration,
   fallback snapshot, successful empty set or stale content is returned.

The S1→S2 race is closed: committed S2 before post-read fails D equality; notified
S2 after post-read fails control CAS; unnotified S2 after post-read leaves only a
candidate selected against the earlier observation, and the model read's Dlive
rejects it. A write overlapping Dlive may occur after that read boundary; the proof
explicitly identifies that boundary. There is no claim of indefinite currentness
or atomic publication with arbitrary external Mem0/admin writes.

Validity transitions need no mutation counter. Every read uses fresh f1 asOf, and
no proof is cached. If a returned eligible source's validUntil/expiresAt crosses
before assembling the response, discard that proof and withhold/request recheck.
An excluded future validFrom may activate on the next read; f2 promises the explicit
captured-asOf observation, not a hidden completion-time clock revision. Periodic
audits recover generation liveness without using time alone to certify freshness.

## 6. Proposed persistence: migration 018, not implemented here

leases/fences and a source-aware candidate cannot be inferred from immutable 017
history after restart. Keep migration 017 and f1 pointer semantics untouched.
Use the same AppContext-owned Pool, migration runner and no outage fallback. Proposed
schema below is normative; it is not SQL added by this task:

```text
profile_lifecycle

  subject JSONB NOT NULL                            -- strict f1 subject
  scope TEXT NOT NULL                               -- equals subject->>'scope'
  control_version BIGINT NOT NULL DEFAULT 0 CHECK >= 0
  regeneration_needed BOOLEAN NOT NULL DEFAULT true
  observed_backend TEXT NULL                        -- legacy | mem0
  observed_digest TEXT NULL                         -- 64 lowercase hex

  candidate_digest TEXT NULL                        -- 64 lowercase hex
  candidate_backend TEXT NULL                       -- legacy | mem0, actual last verification backend

  candidate_verified_as_of TIMESTAMPTZ NULL          -- historical observation only
  attempt_version BIGINT NOT NULL DEFAULT 0          -- <= control_version
  attempt_count SMALLINT NOT NULL DEFAULT 0          -- 0..3
  next_attempt_at TIMESTAMPTZ NULL                   -- operational due time
  lease_fence BIGINT NOT NULL DEFAULT 0 CHECK >= 0
  lease_owner UUID NULL
  lease_until TIMESTAMPTZ NULL
  lease_version BIGINT NULL                         -- <= control_version
  last_reason TEXT NULL                             -- closed safe reason enum below
  last_error TEXT NULL                              -- closed safe error enum below
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now()       -- diagnostic, not freshness
  FOREIGN KEY(subject_key, candidate_revision)
    REFERENCES profile_snapshots(subject_key, profile_revision)
  INDEX(scope)
  INDEX(next_attempt_at, subject_key)
```

SQL enforces object/kind/scope mirrors, hash/backend/state formats, nonnegative and
ordered versions, all-or-none candidate fields and all-or-none lease fields,
all-or-none observed backend/digest, attempt count range and reason/error enum.
Application verifies canonical subjectKey,
full strict schemas and candidate digest/revision/policy against the snapshot.
`regeneration_needed=false` requires a complete candidate tuple, matching candidate
and control versions, source_read_state=COMPLETE, observed backend/digest equal to
the candidate observation, no lease/error and next_attempt_at=null. A source read failure
may move it to needed=true; old candidate is retained diagnostically. `observed_digest`
and backend describe the last COMPLETE observation; a failed observation does not
replace them with an empty digest. Source_read_state records latest attempt outcome.

No event-per-invalidation/job table, original evidence copies, Person field,
semantic source counter, Journal FK/cascade, reverse-root index or profile patches.
Short transactional row locks/CAS arbitrate claims and publication. Leases use DB
`clock_timestamp()` at the actual lease check/renewal and UUID owner, not the
transaction-start `now()` as an expiry fence; bigint values cross TypeScript ABI as
decimal strings. No
unbounded operation receipts are stored by f2.

In-memory parity uses deep clones and short serialized per-row transitions with an
injected clock, identical versions/leases/outcomes. It is explicitly process-local:
restart loses both in-memory f1 history and lifecycle; a new scope starts NO_PROFILE.
Do not claim restart durability or multi-process sharing for that mode. PostgreSQL
has restart-safe needed/candidate/claim state and shared workers.

## 8. Bounded regeneration, recovery and execution

One lifecycle row is the coalesced work item; invalidations never create job rows.
The first request sets due=now+250ms. While work is already needed, further requests
use `min(existing due, now+250ms)`; do not indefinitely debounce by sliding due later.
Known invalidations increment control version even during generation. Release of
obsolete F cannot clear a newer lease or work version. When a fence fails with no
new version, record latest observed digest and increment/request once if it differs;
otherwise retry within the same bounded attempt budget.

One worker per process, concurrency **1**, polls due rows every **1s**, claims at
most **1** at a time using a short `FOR UPDATE SKIP LOCKED` transaction. Lease is
**90s**, renewed every **15s** by owner/fence while that attempt is active, maximum
attempt wall duration **120s**. Cancellation stops certification; f1 may finish an
already-started immutable put, but an expired/lost/cancelled fence cannot select it.
Failed heartbeat means stop publication, leave needed and allow lease reclamation.
No SQL locks are retained while invoking the provider.

At most **3 attempts per control version**: first due as above, retries after **1s**
and **5s**. Source PARTIAL/integrity/schema/policy/revision-conflict failures block
immediately; unavailable source and retryable IO/store failures consume that budget.
Exhaustion sets due=null, needed=true, safe error RETRY_EXHAUSTED. No previous model
is blessed. Explicit request, actual new invalidation or a newly observed different
source state resets budget. Repeated identical COMPLETE polling does not reset it.
Source recovery from non-COMPLETE may request one recovery attempt/version.
No new Memory writes, semantic duplicates or random profile revisions are produced.

Also run a fair **enrolled-subject audit** in the same executor: every **30s** start
one round, read up to **100** rows per batch, ordered by subjectKey, progressing a
cursor through all enrolled rows before restarting. One complete verifier at a time;
no accumulated overlapping timers/promises, no generation per poll. Interleave at
most one due generation between audit checks so neither source auditing nor work
starves. Polling is a liveness fallback for CLI/admin/late effects and clock expiry;
content-read safety always uses live verification. No fixed global bound on detection
latency for arbitrarily many enrolled scopes is claimed. Fixed f1 row/byte/time bounds
remain in force. No top-k scan or new external queue/infrastructure is used.

At startup, mark existing enrolled rows needed in bounded batches/increment versions,
clear only expired leases, and begin audits. Do not clear another process's valid
lease. Concurrent startup may cause conservative extra invalidation but not duplicate
work rows or unsafe publication. Never restore VERIFIED from stored timestamps.
Crash before notification/after source commit is discovered at first model read or
audit; crash after f1 put/before candidate commit leaves history only. Crash after
candidate commit still requires a fresh read on restart.

Shutdown stops claiming/auditing, aborts active source/generation reads, drains up
to **2s**, and conditionally releases only its own lease with needed preserved.
If IO cannot drain, revoke the local publication token and let lease expire; no late
callback can publish. Coordinate with existing server producer drain/ingestion
shutdown, then stop profile work **before closing the shared Pool**. A late immutable
f1 put is harmless historical work; no false cancellation/rollback claim is made.

## 10. Backend parity and concurrency cases

| Guarantee | Legacy PostgreSQL | Local Mem0 |
| --- | --- | --- |
| Complete canonical current read | Native bounded one-statement scoped row capture, f1 rules | Bounded sidecar one-statement present-record capture, existing mapper |
| Native lifecycle/correction/contradiction | Persisted columns, explicit links, validity and retirement guard | Not provided. No fabricated metadata authority or generic “latest wins” |
| Root/descendant retirement | Surviving native retired direct rows exclude shared-root Dream; scope invalidation re-evaluates | Missing direct records do not prove root retirement; surviving Dream remains eligible under f1. Physical legacy deletion also loses a tombstone |
| Source revision / atomic cross-store fence | No current scope revision. New control version is scheduling only | No current revision/CAS; RLock is not a distributed publication lock |
| Hook coverage | Repository notifications cover current server/CLI adapters after effects | Shared backend dispatch/finally plus reconciliation callbacks; direct sidecar/admin writes lack push notifications |
| Safe bridge freshness | Mandatory complete live digest plus control/composition fences | Same observation-boundary guarantee for representable present state; no claim of missing lifecycle semantics |
| Availability failure | Null model, no in-memory failover | Null model, no legacy/hosted fallback |

Parity is freshness **against f1's actually representable current eligible set**,
not amendment/erasure/disclosure parity or absence of pending source effects.
No production source change is required to the f1 materializer/lineage contract.
The stricter live-read bridge is f2 authority, and does not alter low-level f1 reads.

| Race / crash | Required result |
| --- | --- |
| Two source mutations race | Atomic control increments do not lose notifications. Rechecks see actual committed row state; one row coalesces work. Missed notifications cannot authorize mismatching content. |
| Mutation during generation | Dpre/Dgen/Dpost and V fence reject changed state; no selection from S1 for live S2. |
| Two workers/processes | One valid lease per subject, new monotonically fenced claim after expiry; old owner cannot renew/release/select over new F. Generation may physically overlap after lease loss, but immutable replay is safe. |
| New invalidation after claim | Old completion cannot clear newer needed/version. Retry claims latest version, not one job per notification. |
| Source returns to old deterministic revision | Stable new attempt replays exact historical f1 revision under newer candidateVersion. No timestamp preference, patch chain or new revision salt. |
| Concurrent model reads / invalidation | Each complete live observation and second control read either matches or withholds. Returned proof is confined to its source boundary; no indefinite cached content. |
| f1 explicit generation races f2 generation | May move unchecked profile_current in any order; f2 exact historical candidate reference is independent. Both use immutable replay/conflict rules. |
| DB transaction fails after generation/before selection | No f2 candidate commit; needed remains. Immutable f1 result may persist. Lost acknowledgement → re-read control row; do not assume selection succeeded or overwrite history. |
| Crash before/after effect notification | Live read/audit recovers missed source change; lease/state recovery never restores currentness from timestamps. |
| Mem0 late effect after ambiguous timeout | Pre/finally notification is advisory. Subsequent live read/audit catches actual present change; existing C1/Dream reconciliation remains sole effect authority. |
| New backend at restart / handle replaced | Startup recheck and H fence; candidate backend/digest must match live reader, including empty replay's historical backend exception. No cross-backend merge. |
| Expiry without writes | Fresh asOf eligible set changes; no cached proof or reliance on maintenance. |
