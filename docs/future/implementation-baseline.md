## Reusable delivery machinery

The finalized-turn ingestion ledger (`packages/memory/src/finalized-ingestion-ledger.ts`, PostgreSQL) gives each child event a stable ID, payload digest and backend idempotency key, uses versioned lease claims, and persists `dispatch_started_at` **before** calling `writeEventIdempotent` (`finalized-ingestion-executor.ts`). An expired lease after dispatch start moves the event to `reconcile_required` with result `ambiguous`; it is not blindly resent. A provider without `writeEventIdempotent`, or an event without a payload digest, is definitively rejected rather than written unsafely. Dream delivery (`dream-delivery.ts`) uses the same keyed write plus `reconcileEvent` pattern. Mem0 writes use `infer: false`, so Mem0 does not run its own LLM ADD/UPDATE/DELETE over YUVI's payloads. The canonical Memory event ID and the Mem0 backend ID are not journal receipt IDs.

This is the local precedent for A9's INTENT → ATTEMPT → OUTCOME protocol. A9 reuses it; it does not add a second retry or reconciliation engine for Memory delivery.

## Retention reality

- Conversation persistence stores normalized text turns. Raw vision input is not written to Memory: visually grounded turns are marked `memoryEphemeral` in the Runtime orchestrator, and some internal paths run with `writeMemory: false`.
- Voice audio is **not** fully ephemeral. `apps/server/src/services/voice-review.ts` retains a bounded private review buffer: at most 30 single-speaker mono PCM16 samples of at most about 8 seconds each, written only when the local acoustic contract proposes review material. This supports controller review of voice bindings. It is not a general audio archive and is not journal evidence.
- Consequently no current path supports exact replay of raw perception. The architecture must not claim it, and the journal must not start retaining raw media by default.

## Verified defects and gaps

1. **Legacy LLM extractor attribution defect (reproduced before A10.1a).** The old LLM extractor forced accepted candidates to originRole=user; model-supplied sourceTraceId, clocks and metadata crossed the boundary. Provenance enrichment could trust the declared role and use the whole user message as evidenceText. A deterministic weather-to-astronomy probe stored an unsupported generated preference with a forged trace/time and unrelated user text as evidence.
   - This path existed when MEMORY_BACKEND selected legacy Memory and MEMORY_EXTRACTOR=llm; shared config parsing also mapped unknown non-empty extractor values to llm.
   - P8 qualification: the row could contaminate legacy Memory prompt retrieval, but legacy MemoryService has no semantic MemoryProvider; the row was not directly reconstructed into P8 as a semantic MemoryEvent. Runtime receives an unavailable semantic Memory outcome in this mode.
   - **A10.1a closes this extractor path.** LLM-selected legacy extraction no longer invokes the reasoning provider; only the existing rule-based extractor supplies candidates and status reports unsupported-grounding. Unknown values reject in shared parsing, server startup and runtime reload. Mem0 continues to skip this legacy path. See [A10.1a validation](../validation/v0.1.3-a10.1a-llm-memory-grounding.md). **A10.1b carries ancestry only:** new conversational and finalized-speech user messages retain their exact committed Journal event reference. **A10.1c now consumes that ancestry for new legacy evidence-backed writes:** it verifies committed receipts/selectors and durably stores a versioned lineage; Mem0 finalized ingestion, dream and Profile consumers remain A10.1d–f.
2. **Controller profile write outside Runtime.** `apps/server/src/services/profile-evidence.ts` (called from `routes/product.ts`) writes an `EXTERNAL_CLAIM` from the local controller directly to the Memory provider with `writeEvent`. It has no Runtime admission, no idempotency key and no causal receipt, so a retried save can duplicate the claim. Repair: **A10.2**.
3. **Production durable causal ingress and explicit limits.** A8.2b commits ordinary `/message`, `/v1/messages`, `/v1/messages/stream` and `/ws` user-message receipts before Runtime. A8.2c commits one finalized-speech receipt before transcription observations become handoff-ready or `/v1/voice/message` enters semantic Runtime processing. Speech principal and Person binding remain unresolved; caller speaker/profile hints and acoustic matches do not authenticate. The Runtime capture reservation and pending handoff are volatile, so receipts survive restart but turns are not replayed and no restart-durable dedup is claimed. Preview STT remains outside finalized admission. A8.2d commits a minimal standalone vision input receipt before provider invocation; image bytes and URLs remain outside Journal, and provider results are not recorded. A8.2e1 commits minimal CONTROL receipts before Product configuration/Person store operations and proactive resume; local controller identity is unresolved and private settings/profile fields are omitted. A8.2e2 commits minimal CONTROL receipts before P8 correction append and process-local read-text grant creation; correction/path content is withheld and read-text grants are not restored after restart. A8.2e3 keeps Desktop/Tauri settings as authored durable consent, journals accepted READY projections before applying volatile Runtime consent, and uses immediate receipt-free UNKNOWN_DENIED invalidation for settings failure/change. Runtime policy persistence does not become a second authored consent store; its legacy consentEnabled field is ignored in production projection mode. No Person binding is inferred, no source dedup is claimed, and projection state is not replayed from Journal after restart. A8.2f1 commits minimal CONTROL receipts before direct voice-profile enrollment, profile-to-saved-Person binding, profile deletion and explicit binding removal. A8.2f2 commits minimal CONTROL receipts before Product voice review decisions and multi-recording enrollment. Voice receipts keep caller principal/Person unresolved, retain no raw audio, label, display name or embedding, and use AUDIO/NOT_RETAINED only when an operation consumes audio. Review sample state is re-read after receipt; local privacy deletion stays independent of Journal and wins when it completes before that check. Existing Memory-before-reference-index and binding/profile/sample deletion sequences remain unchanged, and post-receipt partial states have no cross-store rollback. A8.2f3 receipts the external proactive-turn request before Runtime work. A8.2f4 commits a standalone TTS CONTROL receipt before provider resolution while keeping raw synthesis text unavailable and making no authorship claim; no source dedup is inferred from session or options. A8.2f5 disables production manual Memory create/edit/restore, retains localhost-only Journal-independent privacy withdrawal and closes production maintenance-run reachability. It does not add receipts or establish cross-backend Mem0 erasure. A8.2f6 audited the complete current production surface: no remaining A8.2 semantic/control ingress bypass was found. Diagnostic/read-only surfaces, transient VAD, internal work, operational process controls, Live2D presentation administration and output-effect callbacks are explicitly outside this family; privacy withdrawal remains Journal-independent. Chat image bytes and raw speech audio remain outside Journal; the separate bounded voice-review buffer remains unchanged. Existing conversation, Runtime, A3 and Memory records remain distinct, and durable effect accounting remains A9. Aggregate A8.2 is implemented for this documented scope; A10 lineage is still separate.

A7.1 adds validated static registry metadata; A7.2 adds host-approved in-process registration and drain only. Durable intent/attempt/outcome accounting remains A8–A9 work. ## P8 authority finding

No LLM, provider, cognition or character output path writes P8 identity or relationship state:

- Authored identity/persona comes from code constants (`production-invariants.ts`).
- Relationship context is a read-only interpretation reconstructed each turn.
- The only persistent P8 write is `appendP8Correction`. It is reachable only through `POST /p8/corrections` behind local dashboard access, and it rejects any provenance other than `EXPLICIT_USER_CORRECTION` (`correction.ts`).
- Assistant-generated evidence is classified `ASSISTANT_MODEL_GENERATED`/`NON_AUTHORITATIVE`, and identity resolution discards `ASSISTANT_INFERENCE`.

This is preserved rather than rewritten. The [P8 ownership map](p8-ownership.md) records the details and migration conditions.
