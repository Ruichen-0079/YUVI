## Why A10.1 is split

A8.2 established durable admission for the documented semantic/control receipt family. A10.1 now answers a different question: once a fact, statement, or derived record is written into Memory, what committed evidence actually supports it?

The source audit found six sequential engineering leaves. The first is an immediate fail-closed safety repair. The later leaves carry committed Journal ancestry through conversation persistence, legacy Memory, finalized Mem0 ingestion, and dream derivation, then close the aggregate dual-backend contract.

```text
A10.1a  Fail closed on legacy LLM evidence
   ↓
A10.1b  Carry committed Journal receipt ancestry
   ↓
A10.1c  Ground new legacy Memory writes
   ↓
A10.1d  Ground finalized Mem0 ingestion
   ↓
A10.1e  Ground dream derivations
   ↓
A10.1f  Aggregate dual-backend lineage closure
```

The order is deliberate. Do not skip directly from A10.1a to backend lineage. A10.1b establishes the ancestry seam required by later consumers.

The exact c/d/e file boundaries may be refined after A10.1b if source ownership reveals a cleaner shared grounded-consumer contract. Preserve the invariants and dependency order rather than an artificial file split.

## Shared A10.1 invariants

- Generated/model content must never become user evidence merely because the model labels it `user`, assigns a high confidence, or supplies user-like metadata.
- Host/consumer authority owns Journal parent IDs, eligible selectors, source scope, principal/binding/audience states, and authoritative timing.
- Model output may propose semantic content; it must not assign authoritative lineage.
- New factual evidence-backed writes require eligible committed evidence. If grounding cannot be proved, fail closed.
- Deliberately unretained payloads remain explicitly unavailable; do not fabricate exact selectors.
- Runtime IDs, conversation IDs, Memory UUIDs, finalized child IDs, episode IDs, provider/backend IDs, and Journal event IDs are distinct identities unless an explicit typed mapping says otherwise.
- Assistant output is generated evidence, not silent user evidence.
- Hearsay remains attributed hearsay; committed lineage proves what was said/reported, not that the reported world proposition is true.
- Old rows and episodes may be `LEGACY_INCOMPLETE`; never invent historical receipts, audiences, Person bindings, or clocks.
- Preserve one active Memory backend and existing finalized/dream keyed delivery, lease, idempotency, and reconciliation machinery. A10.1 adds ancestry; it does not create another delivery engine.
- Semantic Memory task identity is independent of execution model tier, provider, and backend. `Local`, `Chat`, `Cognition`, provider names, model names, and backend IDs are execution/provenance facts only; none grants evidence or Memory authority.
- Changing which model executes an extraction or derivation must not change the host-owned grounding contract. A stronger model is not a stronger authority.
- A10.1 must not encode a specific model tier as the semantic identity of Memory extraction, finalized ingestion, or dream derivation. Model-selection and escalation policy remain outside this atom.
- A9 effect accounting is separate.
- Product profile evidence, controller/Person, voice-binding, and P8 correction issuer/binding lineage remain A10.2.
- Context-use manifests remain A10.3.

## Model-execution neutrality

A10.1 defines grounded Memory semantics, not an inference-budget router. Future execution policy may choose a local model, Chat-class model, Cognition-class model, deterministic code, or another approved implementation for a semantic task without changing that task's authority or lineage rules.

Conceptually:

```text
semantic task / derivation kind
   ↓
future execution policy
   ↓
concrete implementation / provider / model
   ↓
host validation of committed lineage
   ↓
Memory admission
```

The semantic task and the execution choice are different identities. Do not introduce contracts equivalent to `MemoryExtractor = Cognition`, `Dream = Cognition`, or `model tier = authority`. The existing `LlmMemoryExtractor` name is a legacy implementation identifier and must not become the target semantic abstraction.

Execution provenance may be recorded for audit and reconstruction when available, but it is descriptive. It cannot supply Journal parents, selectors, principal/binding/audience state, authoritative time, or admission permission.

No Local → Chat → Cognition escalation policy is implemented by A10.1. This roadmap only preserves the seam needed for such policy to be introduced later without rewriting Memory semantics.

## A10.1a — Fail closed on legacy LLM evidence

**Status:** PLANNED ENGINEERING.

**Goal.** Immediately close the reproduced legacy LLM attribution vulnerability without pretending committed selector grounding already exists.

Current audited defect:

- optional legacy `LlmMemoryExtractor` forces accepted candidates to `originRole: "user"`;
- model `sourceTraceId` can override the host source trace;
- model observation/event/validity times can override host timing;
- provenance enrichment trusts model-declared user-like provenance and can attach unrelated user text as `evidenceText`;
- later admission can store the generated proposition as durable Memory.

Reproduced example:

```text
user:      "The weather is nice today."
assistant: "Okay."

model proposal:
  "User strongly prefers astronomy."
  confidence = 0.99
  sourceTraceId = "forged-trace-999"
  model-selected time
```

The unsafe path can store the astronomy preference as durable user-originated Memory with forged trace/time.

**Required repair.** Until structural committed grounding exists, unsupported optional LLM candidate admission fails closed through the existing safe rule-based path. Do not replace authority with prompt wording, confidence thresholds, substring/token overlap, embeddings, another LLM verifier, or silent rerouting to a different model tier. Unknown `MEMORY_EXTRACTOR` values must not silently enable LLM mode. This leaf is a safety closure, not execution-policy redesign.

**Non-goals.** No Journal ancestry plumbing, no Memory lineage schema, no finalized/dream changes, no Local/Chat/Cognition router, no A10.2/A10.3/A9 work.

## A10.1b — Carry committed Journal receipt ancestry

**Status:** PLANNED ENGINEERING.

**Goal.** Preserve the exact committed A8.2 receipt reference across Runtime/conversation persistence so downstream Memory consumers can identify the actual source event.

Current gap:

- ordinary conversational routes commit receipts but do not persist the committed Journal reference on the corresponding durable user message;
- finalized speech temporarily carries its committed receipt in pending Runtime state, then loses it before durable conversation/Memory ingestion;
- later Memory ingestion therefore sees Runtime/conversation IDs and text without a typed Journal parent/selector.

Required properties:

- persist the existing committed Journal reference rather than minting another one;
- speech handoff keeps its one original speech receipt;
- carry unresolved principal/Person/audience states unchanged;
- validate retained selectors against committed payloads;
- represent unavailable/non-retained evidence explicitly;
- do not infer identity from local access, caller hints, `subjectUserId`, acoustic matches, or display names.

No backend admission-policy rewrite belongs here.

## A10.1c — Ground new legacy Memory writes

**Status:** PLANNED ENGINEERING.

**Goal.** Require host-validated committed evidence for new evidence-backed writes to the legacy Memory backend.

After A10.1b provides ancestry:

- rule-based extraction may propose content from the actual user utterance;
- host policy resolves and validates committed parents/selectors;
- new factual writes without eligible support fail closed;
- explicit remember/correction remains supported as a grounded current user action;
- hearsay remains an attributed external claim;
- assistant-generated content remains generated unless the user later makes a new explicit grounded assertion;
- historical rows without lineage read as `LEGACY_INCOMPLETE` rather than receiving invented receipts.

A small migration may add uniqueness for a host-issued consumer key on new lineage-bearing legacy rows. Do not backfill historical Journal IDs by inference.

## A10.1d — Ground finalized Mem0 ingestion

**Status:** PLANNED ENGINEERING.

**Goal.** Freeze validated committed ancestry into the existing finalized-turn child payload and carry it through the Mem0 boundary.

Reuse existing finalized-ingestion machinery:

- finalized turn identity;
- stable child event ID/key;
- payload digest;
- backend idempotency key;
- lease/claim lifecycle;
- dispatch-start marker;
- reconciliation.

Do not add another executor or retry protocol.

Mem0 rules:

- keep `infer: false`;
- backend UUID is not a Journal event ID;
- finalized child ID is not a Journal event ID;
- Journal parent, child identity, and backend identity remain distinct;
- lineage encoding must round-trip through the actual Mem0 metadata sanitizer without silently dropping/truncating selectors;
- Journal read unavailability for new grounded work must not produce fabricated ancestry.

## A10.1e — Ground dream derivations

**Status:** PLANNED ENGINEERING.

**Goal.** Preserve committed source ancestry through episode construction and dream derivation.

Current episode compression keeps statement text/conversation IDs but not exact per-statement Journal ancestry. Capture source-message → committed receipt/selector mapping before compression.

```text
committed receipt
   ↓
grounded source statement
   ↓
episode
   ↓
dream derivation
   ↓
Memory child
```

Dream output is `DERIVED`, never a fresh original user receipt. Episode IDs are not original receipts. Old episodes lacking source mapping remain incomplete; do not backfill them by matching text.

Dream is a semantic derivation path, not a Cognition-owned authority. The concrete executor may change in future — including local, Chat-class, Cognition-class, or deterministic implementations — without changing `DERIVED` origin, committed-parent requirements, selectors, or Memory admission semantics. If model/provider identity is retained, record it only as execution provenance.

Preserve the current keyed dream delivery/reconciliation path.

## Canonical lineage direction

The source audit recommends a small host-constructed versioned lineage representation for new evidence-backed Memory consumers, conceptually:

```text
MemoryLineageV1

state:
  GROUNDED
  | PAYLOAD_UNAVAILABLE
  | LEGACY_INCOMPLETE

parents:
  JournalEventRef[]

selectors:
  validated SourceSelector[] associated with their parent

sourceAvailability:
  retained/selectable
  | explicitly unavailable with reason

child:
  immutable finalized/dream consumer identity

derivation:
  semantic task / derivation kind
  producer component/version
  policy version
  optional execution provenance:
    implementation/provider/model/version

origin:
  USER_ASSERTION
  | EXTERNAL_OBSERVATION
  | ASSISTANT_GENERATED
  | DERIVED

scope:
  Memory storage scope
  plus principal / Person binding / audience state
  exactly as actually known
```

This is an implementation direction, not a model-writable authority object. The owning consumer validates it. Execution provenance is descriptive and must not affect lineage authority or origin classification. `LEGACY_INCOMPLETE` is compatibility-read state only and is never a valid escape hatch for a new evidence-backed write.

## Semantic examples

`"My friend says the restaurant is closed."` grounds the user's report that the friend made the assertion; it does not verify that the restaurant is closed.

Assistant: `"You seem to prefer astronomy."` followed by user `"Okay."` does not create a new user preference claim.

User: `"Yes, remember that I like astronomy."` creates a current grounded user assertion/request, while preserving whatever unresolved identity state its receipt actually contains.

A user correction is grounded by the new correction receipt and linked to the prior Memory/claim. The old claim is not rewritten into a fabricated original receipt.
