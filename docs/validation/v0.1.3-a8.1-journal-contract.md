Status: **IMPLEMENTED REALITY**. This is a versioned, storage-independent semantic contract. A8.2 durable append, commit ordering and ingress remain planned. The target branch matched the required A7.2 starting commit `8b1d7d15c2c3fed17b015a0fd7cec46bfd94a38b` before edits; A7.1/A7.2 were implemented and A8.1 was planned.

## Focused source audit

The audit was performed before editing the verified starting tree.

1. **Reusable correlation IDs.** Protocol `RuntimeEvent.id` and `traceId`, A1 turn/session/message IDs, A2 `RuntimeCognitionExecution.executionId`, A3 in-memory capability request/observation sequence, conversation message/session IDs, and voice `observationId`/`captureEpoch`/`segmentId` exist today. A2 has a process-local monotonic deadline and `reasoningRoundsUsed` ordinal, but no durable reasoning-round ID. Capability request/observation pairs do not currently have durable IDs. A8.1 places typed correlations in the separate host authority snapshot; prospective intent/attempt correlations remain explicitly prospective and do not create durable IDs.
2. **Principal, Person and voice identity.** No general transport `Principal` type exists. Memory has `MemoryClaimIdentity { entityId, resolution }`; P8 voice identity has explicit local `personId` bindings. Neither is transport/account authentication. Product `Person.id` and voice profile bindings remain separately owned by the controller/identity path.
3. **Source, provenance, verification, correction and scope.** Protocol owns Runtime events and voice transcript observations. Memory owns `MemoryEvent` with its own `id`, source/source record, scope, observed/occurred time and metadata; claim provenance distinguishes `SELF_REPORT`, `EXTERNAL_CLAIM`, `DIRECT_OBSERVATION`, `ASSISTANT_INFERENCE` and `UNKNOWN_AMBIENT`; claim assertion verification is `unverified`/`verified`/`unknown`. Memory corrections are separate Memory events with supersession metadata, and P8 has its own correction store. Existing `MemoryScope` is not receipt-time private/group audience or membership. No current canonical payload-retention, source-selector or audience-snapshot type existed.
4. **IDs that remain domain-specific.** Runtime event/trace IDs, A1 session/turn/message IDs, A2 execution ID, voice observation/capture/segment IDs, Memory event IDs, Mem0 UUIDs, `sourceTraceId`, Memory claim attribution/provenance references and P8 correction/evidence references are not journal event IDs. Memory currently has no standalone canonical claim-ID type. The A8.1 schema wraps existing identifiers in typed correlation/source references. Legacy Memory references have their own `LEGACY_MEMORY_EVENT` tag and cannot satisfy a journal-event reference.
5. **Package boundary.** `packages/protocol` is the narrowest correct owner: it already owns shared versioned contracts and Zod schemas, and has no Memory/store responsibility. Core remains Runtime admission authority; Memory remains an evidence index. No runtime journal owner or store was introduced.
6. **Structural versus store-backed checks.** A8.1 can validate schema versions, strict fields, kind-specific payload shape, time interval shape, selector syntax/modality/bounds supplied by the host catalog, payload availability, selector-to-source-event lineage, duplicate/self parent syntax, namespace shape, direct kind relations when a read-only history resolver is supplied, and cycles only when a resolver explicitly supplies the complete relevant graph. It cannot authenticate a principal, mint identity, prove source existence without a trusted resolver, allocate commit order, serialize concurrent commits, or guarantee global parent existence/acyclicity without the A8.2 store.

## Implemented contract

`packages/protocol/src/life-event-journal.ts` defines three versioned schemas: producer `life-event-command.v1`, committed `life-event-envelope.v1`, and `source-selector.v1`. The producer command is a strict discriminated union for exactly `RECEIPT`, `INTENT`, `ATTEMPT`, `OUTCOME`, `DECISION`, `DERIVATION` and `AMENDMENT`. Authority-owned event identity, namespace, commit sequence, record time, producer/model/codebook identity, principal, source references, binding, surface/channel, correlations, audience and policy cannot be supplied by a producer command. Causal parents are proposals and require a read-only history resolver; kind-specific parent references must agree with it. The committed schema can represent authority fields, but A8.1 has no function that assigns IDs or appends records. Validated values are detached from caller input and deeply frozen.

`INTENT`, `ATTEMPT` and `OUTCOME` have distinct shapes. A command has no model-minted logical intent or attempt ID; future intent/attempt correlations are explicitly prospective. An `INTENT` is accepted only when its action and effect contract match a host-provided authorization snapshot tied to a direct prior `DECISION` parent. Policy version and producer/model/codebook identity come from that separate host snapshot. `ATTEMPT` records the `MAY_BEGIN` boundary and references an intent event. `OUTCOME` references an attempt and requires `CONFIRMED_SUCCESS`, `CONFIRMED_FAILURE` or `UNKNOWN`; confirmed outcomes need a typed predicate and source selector evidence, while `UNKNOWN` cannot assert an established predicate. The v1 predicate vocabulary distinguishes local result produced, service accepted, remote persisted, device presented, human acknowledged, delivery rejected and no effect established. This types claims only and dispatches nothing; it does not decide whether the cited source semantically proves the predicate.

Selectors are discriminated by modality: Unicode code-point text spans, audio millisecond/channel ranges, pixel-coordinate image/frame rectangles, JSON Pointers, and exact tool-result references with JSON Pointer or Unicode code-point fragments. The validator uses the trusted host-provided payload catalog to check immutable payload version, modality, retention/availability, result/frame identity and supplied bounds. For derivations, each cataloged payload selector names its source event; that event must be listed as a committed direct parent, and derivations without source events are rejected. It rejects malformed/inverted/non-finite ranges, fabricated payload references, modality mismatches, malformed JSON Pointers and selectors into non-retained/unavailable content. Redacted content is selectable only when the host explicitly identifies a selectable redacted representation. OCR and semantic search are not used. A JSON pointer is checked against exact catalog pointers when supplied; otherwise A8.1 can verify syntax only.

The separate host authority snapshot represents resolved/unresolved/ambiguous transport principal, Person binding state/version, subjects, private/group/unknown audience, membership known/unknown/incomplete, disclosure-policy state/version, policy and producer/model/codebook versions, source references, surface/channel, and correlations. Payload states are `RETAINED`, `REDACTED`, `NOT_RETAINED` and `UNAVAILABLE`. Principal and Person are separate discriminated types. A derivation claim keeps assertor, subject and provenance separate, including `UNKNOWN_AMBIENT`. The validator does not authenticate the snapshot, map display names or voice matches to a Person, or merge audience scopes. Group/channel identity must match between the host-supplied surface and audience snapshot. Unknown membership remains explicit.

Occurrence time is unknown, an instant or an interval with source clock and uncertainty. It is never compared to `recordedAt` for causal order. Equal and out-of-order times are valid. Causal parents are typed journal references; duplicate/self parents, cross-namespace edges and known illegal kind relationships reject. Attempt/Outcome targets and amendment/source lineage must be direct parents. A read-only history fixture can validate known parent existence and, only when marked complete, full ancestry cycles. It does not claim a global graph guarantee for missing/incomplete history.

Legacy Memory event references are explicit `LEGACY_MEMORY_EVENT` source references. A Memory UUID, Mem0 UUID, `sourceTraceId` or claim identifier cannot pass as a journal event identity by shape, and a legacy Memory reference alone cannot be admitted as a new `RECEIPT`. No original journal receipts are synthesized for old Memory rows.

Typed `JournalContractError` codes distinguish unsupported versions, producer authority overrides, invalid command/context/envelope, invalid or unavailable selectors, duplicate/self/cross-namespace/unknown parents, illegal relationships, self-generated disposition claims and read-only duplicate/non-monotonic fixture identities. No coercion or guessed authority fallback is performed.

## Source-backed deviations and limits

- The roadmap describes correlation to reasoning rounds/capability observations, while A2/A3 source has no stable round or durable capability observation ID. A8.1 uses the existing execution ID plus round/call ordinal and opaque observation reference; it does not claim persistence or continuity after restart.
- There is no source-level transport Principal or general receipt audience snapshot to reuse. A8.1 adds protocol representations, not authentication, identity resolution or production snapshots.
- Existing Memory event and claim types have event-like names, but belong to Memory delivery/index/provenance. They were not reused as journal events.
- A8.1 does not create producer-controlled logical intent or attempt identities because the current roadmap reserves durable uniqueness and dispatch identity for A9. Prospective typed correlations remain non-authoritative.
- A8.1 does not implement global scope/parent resolution, durable commit sequence, source authentication or append locking. These require A8.2 store authority.
