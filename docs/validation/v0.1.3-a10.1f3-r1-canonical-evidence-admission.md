## Canonical authority

`EvidenceAdmissionV1` and `EvidenceAdmissionStore` now own the host answer for Mem0 evidence. The representation contains:

- version and deterministic `admissionId`, derived from scope plus logical event identity;
- scope and actual producer kind: `FINALIZED_INGESTION` or `DREAM_DERIVATION`;
- logical event/idempotency identity and frozen semantic payload digest;
- immutable schema-validated lineage plus its digest;
- expected immutable backend effect digest;
- backend `mem0`, exact backend UUID, and `PREPARED` or `EFFECT_BOUND` state.

SQL stores preparation/binding timestamps separately as bookkeeping. Evidence meaning has one immutable versioned representation. There is no lease, dispatch counter, retry scheduler, reconciliation status, tombstone, or Person authority in this store.

```text
Journal-grounded/frozen host semantic event
  → canonical PREPARED admission
  → existing workflow delivery/reconciliation
  → exact effect proof
  → canonical EFFECT_BOUND admission
  → bounded present Mem0 record + matching admission
  → ordinary Profile eligibility / roots
  → f1 sourceSetDigest / snapshot
  → unchanged f2 freshness / People.Model
```

Only the host producer path prepares admissions. Backend lineage and keyed delivery alone cannot create them. The provider's ordinary `writeEvent` and an unprepared `writeEventIdempotent` persist generic Memory without admitting evidence. Direct sidecar writes have no access to the host admission path.

Finalized and Dream workflow stores retain their existing work/retry/reconciliation responsibilities. Profile queries neither workflow store. The generic Mem0 mapper now performs structural transport decoding rather than separate finalized/Dream assertion/time/claim authority interpretation. Those producer-specific branches were removed; the canonical frozen effect digest detects transport changes uniformly.

## Exact effect binding

The binding checks exact backend UUID and scope, plus SHA-256 of canonical scope, exact stored content, and every non-storage metadata field. Expected metadata is generated by the existing host transport serializer, includes the encoded lineage and delivery key/digest, defaults `schemaVersion` to 1, and follows the sidecar's existing omission of null metadata. The backend UUID is separately bound and is never inferred from metadata during Profile enumeration.

Only Mem0's redundant storage fields `data`, `hash`, `user_id`, `created_at`, and `updated_at` are outside the effect digest. Scope/content are bound directly; storage clocks are not evidence clocks. Assertion, source-time, provenance, lineage, delivery identity, and other metadata changes cannot retain eligibility. No sidecar schema or evidence-admission decision was added.

Copying exact legitimate transport to another UUID fails the host lookup. Wrong scope fails isolation or lookup. A copied delivery key with changed content, semantic payload, or metadata fails the immutable binding. A correct backend key is delivery addressing, not admission.

## Existing-data reconstruction

`bootstrapPostgresEvidenceAdmissions` performs a bounded 128-row keyset scan of authoritative host workflow history at startup and persists deterministic admissions. It never enumerates Mem0 for promotion, matches prose, invents receipts, or adds producer fallback branches to Profile. A host bootstrap is used rather than SQL guessing because exact reconstruction requires the versioned TypeScript lineage/transport serialization and frozen Dream validation.

For finalized history, reconstruction verifies the frozen payload digest and delivery identity. A successful `complete`/`unchanged` child with exact `mem0:<UUID>` effect identity can bind; the UUID must equal the existing deterministic keyed endpoint address. Missing effect proof remains PREPARED and ineligible.

For completed Dream history, reconstruction validates the frozen source snapshot/digest, rebuilds the expected derived event from its grounded snapshots, and requires exact equality with the frozen stamped result. The current production Dream path delivers through the deterministic Mem0 keyed endpoint; the frozen logical key gives its exact UUIDv5(NAMESPACE_URL, key) address. Only completed proven jobs bind. Pending/ambiguous jobs remain PREPARED until existing reconciliation proves delivery. Missing/malformed snapshots or changed frozen results remain unsupported. The reader still requires the actual exact present effect and digest, including on reconstructed bindings.

Startup does not require Mem0 availability: host reconstruction materializes expected proven bindings from host history; present-state verification remains the reader's responsibility. This is an idempotent startup materialization, not a per-read historical inference path.

## Profile, mutation, deletion and failure states

The Mem0 reader retains bounded raw enumeration, structural validation and exhaustion/byte bounds. It makes one scoped batch lookup against canonical bound admissions, compares exact effects, and uses admission lineage for eligible candidates. It then applies the existing generic origin/derivation/root rules. There are no finalized-ledger or Dream-store branches in Profile.

| State | Source-reader behavior |
| --- | --- |
| Definitively absent admission, or PREPARED only | Exclude as NON_EVIDENCE; COMPLETE is possible. |
| Present effect differs from frozen binding | Explicit unsupported NON_EVIDENCE exclusion; no changed-state admission. |
| Admission authority/readiness unavailable | UNAVAILABLE / ADMISSION_UNAVAILABLE, no sources, never COMPLETE. |
| Internally contradictory canonical representation | ERROR / ADMISSION_INVALID, no sources. |
| Malformed backend transport/scope/identity | Existing structural integrity failure or bound PARTIAL behavior. |
| Effect absent from bounded current enumeration | Not a present Profile source, regardless of historical admission. |

Ordinary unsupported rows remain stored and available to existing generic Memory behavior; their declared lineage is transport, not host evidence. Neither Profile nor People.Model may promote them.

The existing sidecar generic update already rejects lineage-bearing effects. Real admitted-effect generic mutation remains prohibited with VALIDATION_ERROR; corrections must arrive through a real grounded semantic producer. Even an out-of-band content/metadata rewrite fails the host effect digest. The admission store exposes no mutation/rebinding semantics.

Deletion removes the present effect. The historical admission can remain, but live enumeration removes the source and changes the source set. f2 withholds the old model even without a mutation notification. Binding emits the existing advisory delivery-observed notification; liveness does not depend on receiving it. f2 itself was not redesigned.
