## Source boundary

Before this leaf, `/v1/tts` validated the request, resolved the configured TTS provider, created the existing request-disconnect boundary, and called `synthesizeSpeech`. It did not write a Journal receipt. The route is a provider-facing media route and does not use Runtime. AppContext already owns the shared Journal repository, so no second repository, pool, or provider authority was needed.

The existing request schema and provider inputs remain unchanged. In particular, the existing `sessionId` field is not newly bounded at the public request boundary. A value longer than A8.1's opaque correlation limit is simply omitted from the Journal correlation so the established TTS request behavior is preserved.

## Receipt and privacy boundary

`HostTtsReceiptAdmission` is constructed in AppContext over the existing `JournalRepository`; request handlers see only the narrow `TtsReceiptAdmission` interface. It accepts a bounded optional session correlation, Unicode code-point count, voice/language presence flags, and the already-validated output-format enum. It receives no raw synthesis text, option values, request/auth object, Runtime, Memory, or provider.

For a valid request the route installs the existing disconnect boundary, checks that it is current, appends the host-built `RECEIPT/CONTROL`, checks currentness again, and only then resolves and invokes the existing provider with its existing cancellation signal. Runtime remains uninvolved. There is no source dedup: text, options, format, and session correlation are not transport delivery identities; repeated identical requests receive distinct Journal event IDs.

The host authority records an unresolved principal, unresolved Person binding, no subjects, unknown audience, unresolved source and disclosure policy, and the local `/v1/tts` surface. The session is only a bounded conversation correlation. `USER_INPUT` on the payload descriptors means entry through this external request boundary; it makes no claim that the request was authored by an authenticated person.

The synthesis text has a host-generated `TEXT/NOT_RETAINED/selectable=false` descriptor with its code-point count. No selector can resolve that text. A separate retained, host-built JSON control summary is the only selectable TEXT payload; it contains the operation, count, option-presence booleans, and normalized format. Raw text, voice/language values, generated audio, provider output/configuration, and auth/token material are absent from Journal persistence. No prompt archive or audio archive is introduced.

If the request is already disconnected before admission, neither Journal work nor provider work starts. If disconnect occurs during append and PostgreSQL commits, the receipt remains, but the route checks request currentness and does not resolve/call the provider. Journal rejection/unavailability/persistence failure returns a bounded admission error and prevents provider resolution; there is no in-memory fallback or automatic retry. Provider failures after successful admission retain the existing provider error mapping; the receipt does not claim synthesis was attempted or succeeded.
