## Old gap and new admission boundary

A10.1b already carried a committed `sourceJournalRef` through source user events and durable conversation user rows. The finalized Runtime admission calls omitted it; missing-admission recovery extracted only trimmed user content. The policy therefore admitted a durable semantic child without committed lineage, and compatibility `subjectUserId` could create a resolved SELF_REPORT claim.

The new path is:

```text
committed user receipt
→ exact Runtime sourceJournalRef + untrimmed sourceText
→ shared JournalMemoryGroundingResolver
→ MemoryIngestionPolicy with groundedSource
→ per-event MemoryLineageV1 / FINALIZED_INGESTION
→ frozen durable child payload and delivery identity
→ existing claim / dispatch marker / keyed Mem0 submit / outcome
```

All three Runtime finalized admission points (non-stream persistence, streaming finalization and scheduling) pass the exact source ref/text. The direct input contract can carry a host-owned ref; it never mints a receipt. A Mem0 finalized turn without a durable admission port now fails closed instead of bypassing the ledger through `storeConversationTurn`.

Recovery follows `sourceUserEventId` to the exact persisted user row and passes its original content and `sourceJournalRef` through the same admission service. No Journal text search or trace/session/time inference exists. Missing user rows remain diagnostic; legacy rows without ancestry and malformed refs fail closed with no child dispatch. Grounding failures have durable `terminal_failed` parents, `failure_stage=materialization`, zero children and stable `MEMORY_GROUNDING_*` codes; they are distinct from provider outages.

Grounding reuses A10.1c's committed evidence reader/resolver and exact retained TEXT selector / Unicode-code-point equality. Tests reject missing/malformed refs, unknown/wrong-namespace parents, wrong parent kind, CONTROL receipts, missing selectors, unavailable/nonselectable/NOT_RETAINED payloads and source-text mismatch. No similarity or trace fallback is introduced.

## Frozen lineage, identity and authority

`MemoryLineageV1` retains its version and gains only `FINALIZED_INGESTION`. It preserves exact Journal parent/selector, retained-selectable availability, deterministic consumer key, producer/version, policy, host-derived origin, actual authority snapshot, committed `recordedAt` and exact `occurrenceTime`.

The finalized policy epoch is `factual-v1/schema-2/grounded-a10.1d`. Producer is `@companion/memory`, version `0.1.0` (the package's current version). Consumer key:

```text
semantic fingerprint = SHA-256(canonical {kind, NFC content, scope})
consumerKey = mlf1_ + SHA-256(canonical {parent, policyVersion, fingerprint})
```

This precedes lineage-bearing payload hashing and excludes delivery identities, so it is not circular. `eventPayload.lineage` exists before durable admission. Existing canonical payload hashing now includes lineage, then derives event key, child ID and backend key using the existing formulas. Same child/source replays frozen work. Changing lineage changes payload digest/event key/backend identity; conflicting source ancestry for the same current-epoch finalized turn rejects as `FINALIZED_INGESTION_SOURCE_CONFLICT`, including an admission race. Source digest now binds exact ref/text and admission/policy inputs; no retry clock is included. The executor validates frozen lineage shape/compatibility and never re-reads Journal or re-decides grounding.

Storage scope stays user/persona partitioning. It does not prove Person identity. Grounded policy bypasses compatibility default claim manufacture; freezing removes claims, caller authority metadata, candidate clocks and typed participants. Typed assertion is unverified, while committed authority is authoritative in lineage. Principal UNRESOLVED, binding UNRESOLVED and audience UNKNOWN survive exactly. There is no authenticated self-report manufactured from caller IDs, voice profile or acoustic cluster.

- Typed conversational ATTRIBUTED_ASSERTION/USER_INPUT → USER_ASSERTION lineage, user/unverified assertion.
- Real finalized speech DIRECT_OBSERVATION/EXTERNAL_RESULT transcript → EXTERNAL_OBSERVATION lineage, unknown/unverified assertion.
- Mock text speech ATTRIBUTED_ASSERTION/USER_INPUT → USER_ASSERTION, without binding upgrades.

Source `recordedAt` is used as observed time. INSTANT may project to occurredAt; UNKNOWN stays unknown, and INTERVAL stays exact in lineage without an invented scalar. Mem0 created_at remains backend-record time. Completion/retry/model times do not replace Journal source clocks. All finalized submits remain `infer:false`, without an evidence LLM.

## Provider and metadata transport

`MemoryWriteEventInput.lineage` and `MemoryEvent.lineage` are optional first-class vendor-neutral fields. Runtime imports no Mem0 DTO. The provider encodes schema-validated lineage using three host-owned reserved keys:

- `yuviLineageEncoding = yuvi.memory-lineage-json.v1`.
- `yuviLineageJson`: deterministically sorted canonical JSON, maximum **65,536 UTF-8 bytes**.
- `yuviLineageDigest`: SHA-256 of that exact JSON.

Oversize encoding rejects before child admission. No truncation, recursive generic metadata relaxation or raw audio/image bytes is permitted. Generic metadata retains its original primitive/array/key bounds. Reserved lineage/parent/selector/consumer/authority/claim/verification/clock/delivery keys are stripped from caller metadata; typed host values win. Sidecar keyed scope/content/digest/key fields replace conflicting body metadata. The sidecar validates transport integrity and version without implementing a second Journal grounding algorithm.

Tests assert schema equality, not key presence: frozen ledger lineage equals outbound decoded metadata, persisted JSONB decoded lineage and reconstructed get/search MemoryEvent lineage. Long opaque namespaces/payload refs, Unicode selectors/reasons and UNKNOWN/INSTANT/INTERVAL times round-trip losslessly. Partial/unknown/noncanonical/malformed/digest-conflicting/oversized encodings reject. Conflicting verification, assertion origin, source time or resolved claim also reject for grounded finalized records. get raises a safe lineage error; search returns error with no grounded results. An applied response missing/differing lineage is ambiguous, preserving reconciliation instead of claiming definitive no effect.
