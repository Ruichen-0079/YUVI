## 3. A9.1 invariants preserved

The semantic `effect_intents.intent` JSON is not changed by dispatch, cancellation, expiry, retries or observations. Its decision, causal refs, request, authorization version, digest, audience and identity remain the original admission history.

One logical key and equal semantic payload replay one intent; differing payload conflicts. Allocation time, execution correlation and dispatch bookkeeping do not become semantic content. One row still creates admission and initial pending work atomically. Later work projection is intentionally mutable: PENDING becomes CLAIMED once, or is withheld before allocation. No authorization or identity rule changes. Twelve batches of 24 identical admissions, the original 24-worker case and payload-conflict cases pass.

## 4. Canonical ATTEMPT and observation models

`EffectAttemptV1` fixes:

- `effect-attempt.v1`, immutable concrete `attemptId`, `intentId`, exact decimal-string `attemptOrdinal`;
- immutable contract reference and adapter identity/version;
- current decimal-string fence, lease owner and expiry;
- immutable creation time and write-once `dispatchStartedAt`;
- a monotonic integrity-conflict flag.

Owner is derived from the frozen host contract, rather than duplicated in a competing column. Attempt identity is `ea1_` plus SHA-256 of canonical `{ intentId, ordinal }`. It is distinct from `ei1_` logical identity, Runtime execution ID, receipt ID and optional remote effect identity. Retry creates a new ordinal/ID. Reconciliation increments the processing fence on the **same** attempt.

Ordinal/fence and observation IDs use native PostgreSQL bigint, exposed as validated decimal strings. Allocation uses BigInt under the locked intent row. Unit tests exercise values beyond JavaScript's exact integer range and reject overflow beyond signed PostgreSQL bigint.

`EffectObservationV1` binds immutable safe evidence to the attempt, fence, adapter/contract, native observation ID, observation time and canonical evidence digest. Evidence distinguishes APPLIED, DEFINITIVE_REJECTION, PROVEN_NOT_APPLIED and UNKNOWN, plus the evidence layer and fixed safe reason code. Strict schemas reject incompatible reason/layer/certainty tuples and extra private content. Remote effect ID is optional, bounded correlation; current read adapter records none.

APPLIED at `LOCAL_READ_RETURNED` means the bounded local read returned successfully to the adapter. It does not establish remote delivery, Cognition consumption, presentation completion, human perception, Person truth or Journal authority.

## 6. Atomic claim, dispatch start and live authorization

1. Lock INTENT; require ADMITTED/PENDING, expected contract, unexpired deadline and host current authority. Insert first attempt and set CLAIMED in the **same transaction**. Concurrent workers elect one winner.
2. A separate transaction locks the same intent/attempt, requires exact current owner/fence, live lease, no terminal observation, unexpired deadline and live authority; persist the write-once dispatch timestamp.
3. After COMMIT returns, read the durable current attempt again. Reject replaced owner/fence, expired lease, an observation/hold or missing start. Recheck the host authority synchronously immediately before entering the adapter, with no asynchronous yield between that check and entry.
4. The adapter receives the committed started snapshot. Target errors become UNKNOWN; outcome commit never determines whether invocation was allowed earlier.

Currentness is checked synchronously before claim/start COMMIT submission, including deadline/lease checks. This is an admission/dispatch observation boundary, not a distributed atomic authorization transaction. A delayed start COMMIT response cannot let an old worker invoke after a replacement reconciles and retries: the final durable fence/lease check prevents it.

Read-text authority remains process-local and execution-owned. Runtime supplies a consumed one-shot path, current Cognition execution and the exact committed turn receipt. The host copies the receipt's principal, subjects, binding, audience and disclosure policy exactly, grants only static read permission for that scope, and freezes its policy/execution authority version. UNKNOWN audience and unresolved principal/binding remain unresolved. Storage scope/session, execution identity, controller, principal and Person are not merged.

Volatile grant registration precedes admission COMMIT visibility, avoiding a background-worker race. It is removed when the caller settles. Restart restores neither a grant nor an A2 loop. Runtime cancellation is combined with worker shutdown cancellation at the actual local reader. Runtime replacement retains the same host facility while the existing Core drain/currentness rules govern already-admitted work.

## 7. Contracts, retry and reconciliation

The host's frozen delivery table pins adapter identity, evidence layer, supported lookup policy and whether proven-not-applied permits retry. Only read-text allows an optional **host** lookup implementation. The active local reader has no lookup; controlled test adapters supply certified fixture evidence. Plugins/models cannot populate or strengthen these declarations through their supported APIs.

Retry requires durable proof:

- expired unstarted claim: LOCAL_PROTOCOL/UNSTARTED_RECOVERY; new attempt only if current/unexpired;
- started attempt: adapter reconciliation proves NOT_APPLIED under its contract; new attempt only if current/unexpired;
- cancellation, expiry, authority revocation, shutdown withholding or integrity conflict: no automatic retry.

A lease timeout, crash, missing response, HTTP timeout, provider confidence or `retryable` flag is never proof. An unsupported lookup records RECONCILIATION_UNSUPPORTED/UNKNOWN and removes repeated background probing; it does not clear the queue by resending. Reconciliation success closes the same attempt; it never mints an invocation identity or republishes an old transient result. Definitive rejection is distinct from proven absence and is not automatically retried by this implementation.

## 8. Cancellation, expiry, fencing and conflicts

| Boundary | Disposition |

| PENDING expiry | EXPIRED/WITHHELD, no attempt |
| CLAIMED, not started | Cancel/start serialize on the same intent/attempt lock. Winning cancel records a LOCAL_PROTOCOL pre-dispatch disposition; start cannot proceed |
| CLAIMED expiry/revocation | Before start, withhold invocation with explicit no-dispatch evidence |
| Started attempt cancellation/expiry | Cannot assert remote non-occurrence or change uncertainty to CANCELED. Existing evidence/ambiguity survives |
| Proven no-effect, then retry loses currentness/expiry | Intent records future-work withholding; original reconciliation evidence stays unchanged |
| Old worker returns after lease expiry/replacement | Exact attempt/fence/owner/adapter/contract binding rejects stale mutation and transient publication |
| Exact outcome replay | Idempotent; no new invocation or observation |
| Conflicting definitive evidence | Preserve both safe observations, persist integrity hold; diagnostic certainty is INTEGRITY_CONFLICT, no last-writer-wins or retry |

## 10. Shutdown and drain

Server `preClose` initiates the generic effect seal/drain before Fastify waits for active HTTP handlers. `onClose` independently awaits the same drain promise before plugin shutdown, bridge close, existing Memory/Runtime/Profile drains and repository closure; the shared DB pool closes last. AppContext's pool-close method defensively invokes effect shutdown again. The server order regression holds the effect drain and proves plugin teardown cannot overtake it.

The dispatcher stops accepting work, clears discovery scheduling, aborts owned calls and awaits active promises. At its default two-second deadline, unresolved started work records SHUTDOWN/UNKNOWN when the current fence still permits the observation. A durable start without an outcome is already recoverable UNKNOWN if a lost fence prevents recording. Unstarted work remains safely unstarted/withheld. Adapter objects and in-flight promise closures remain retained until they settle; no late transient result publishes. After forced abandonment/DB closure, late callbacks have no right to overwrite accounting. Current adapter is host-local, with no disposable plugin implementation; existing A7.2 in-flight plugin retention remains unchanged.
