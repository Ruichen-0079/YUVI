## Source audit and original behavior

Before this leaf, finalized `/v1/audio/transcriptions` performed STT, retained eligible review audio in the bounded private voice-review buffer, called mutating `Runtime.admitFinalizedSpeechObservation`, then returned its observation ID. `/v1/voice/message` followed the same path, then consumed the pending observation using `commitSpeechTurn` and called `Runtime.handleUserMessage`. The ordinary and streaming message routes already treated `speechObservationId` as a handoff and intentionally skipped A8.2b conversational receipt admission.

`admitFinalizedSpeechObservation` combined normalization and fence acceptance with live epoch changes, obsolete-epoch state, accepted segment claims, pending turn publication and proactive/activity updates. Appending before this mutation could durably record stale/duplicate speech; appending afterward could fail after the observation had already been claimed. `observeSpeechActivity` is a separate synchronous VAD/barge-in boundary and must not wait on PostgreSQL.

`Runtime.transcribeSpeechAudio` was documented as transcription-only but called the old mutating admission method. Repository search found no production caller. It now returns provider output only; production finalized route admission goes through the reservation and Journal boundary. Preview transcription also remains outside finalized receipt admission.

Current route identity inputs (`subjectUserId`, `createdByUserId`, `personaId`, `speakerId`, `voiceProfileId`, and optional `captureEpoch`) do not authenticate a transport actor. Provider `speakerClusterId` and `voiceProfileMatch` remain acoustic observations. The existing voice identity/P8 owners do not make them receipt-time Person bindings. `retainSpeechReview` is a separate bounded private buffer and already ran before capture admission; that ordering and retention contract remain unchanged.

## Implemented ownership and ordering

Runtime owns capture epochs, duplicate/segment fences, reservations, pending turns and currentness. `HostSpeechReceiptAdmission` in `apps/server/src/speech-receipt-admission.ts` owns only host construction and append of a normalized speech receipt, using the existing `JournalRepository.appendWithHostAuthority` seam. AppContext gives routes the narrow `SpeechReceiptAdmission`; routes do not receive the Journal repository.

The path is:

```text
STT
  → bounded voice-review retention (existing separate class)
  → Runtime reserve + normalize
  → host speech RECEIPT append
  → Runtime finalize the same reservation, or release it on append failure
  → optional one-shot commitSpeechTurn
  → Runtime semantic processing
```

Reservation synchronously normalizes/generates observation and segment IDs, chooses the effective capture epoch, rejects known-obsolete epochs and wholly duplicate segments, and records token-owned provisional segment claims. It creates no pending turn, accepted claim, activity revision, proactive wake or semantic input. Active reservations are bounded at 64 and are never evicted; capacity fails visibly. A per-session reservation lock serializes finalized admissions while VAD remains independent. Mixed old/new segment lists retain existing behavior: already accepted segment keys are skipped while unseen keys may reserve the observation. Release removes only claims owned by the reservation token and never rolls back an independent VAD transition.

Reservation does not install a provisional live-epoch transition. It snapshots the prior live epoch and leaves VAD/current epoch untouched; finalization can advance the epoch only if that snapshot is still current. Thus release needs no broad epoch rollback, and a VAD transition during append is preserved by ownership/currentness comparison.

After append succeeds, Runtime verifies the committed envelope is a RECEIPT correlated to the exact reserved observation and capture epoch. Normal finalization converts provisional claims to accepted claims, records the Journal event reference with the volatile pending turn, and only then performs the previous activity/proactive admission behavior. The committed Journal reference is required by `commitSpeechTurn`, which also rechecks session, text, one-shot pending state and live epoch. A mismatched receipt does not finalize the reservation.

If a new VAD epoch arrives while PostgreSQL append is pending, VAD updates immediately. When append completes, finalization retains the receipt and consumes the reservation into a stale, non-handoff state; it does not restore the prior epoch, publish pending turn state, perform admission activity updates or return a usable observation ID. The deterministic PostgreSQL test blocks append, advances VAD, then commits and checks these outcomes.

## Receipt and retention semantics

One finalized observation produces one original Journal RECEIPT. Its `DIRECT_OBSERVATION` classification means only that YUVI accepted the finalized STT observation through its capture fence; it does not establish transcript truth, a definite human utterance, speaker identity, Person identity, audio retention or Runtime completion. Mock-text-only input without audio uses `ATTRIBUTED_ASSERTION` and does not invent an AUDIO payload.

The receipt authority includes session correlation, one observation-level `VOICE_OBSERVATION` correlation containing the normalized observation ID and capture epoch, and unique segment-level correlations for normalized source segment IDs. Journal event ID, Runtime event ID, observation ID, capture epoch and segment IDs remain distinct. A multi-speaker transcript remains one receipt; speaker clusters and caller-supplied speaker/profile hints do not become principal or subject bindings. Receipt principal and Person binding remain unresolved, subjects are empty, and audience is unknown. No source dedup key is supplied: the available identifiers may be caller/provider generated or process-local and are not stable transport identity.

Transcript text is retained through a host-generated immutable payload reference and exact Unicode code-point bounds. When source audio was supplied, the Journal records only a nonselectable `NOT_RETAINED` descriptor; no raw audio/base64 enters Journal tables. The bounded private voice-review sample may still be retained if Journal admission later fails. It is intentionally not rolled back or reclassified as Journal evidence. Occurrence time stays `UNKNOWN`; request time, relative segment offsets and Journal `recordedAt` are not substituted.

Preview STT remains a preview response with no finalized reservation, Journal receipt or accepted observation ID. Finalized transcription returns an observation ID only after Journal append and successful currentness finalization. `/v1/voice/message` commits its one speech receipt before `commitSpeechTurn` and `handleUserMessage`; it does not add an A8.2b conversational receipt. Message and stream speech handoffs consume that same one-shot receipt-backed pending observation and do not create another receipt.

## Failure and restart limits

- STT failure or disconnect before a finalized result creates no reservation or receipt.
- Stale/duplicate rejection at reservation creates no receipt. Journal failure releases the reservation and prevents an accepted observation ID, pending turn, `commitSpeechTurn` and semantic voice message.
- If append commits and the request disconnects, a VAD epoch supersedes the turn, `commitSpeechTurn` fails, or later Runtime/provider work fails, the receipt remains as evidence of accepted finalized speech only. No automatic receipt deletion or semantic replay occurs.
- Runtime reservation/currentness and pending handoff state are process-local. Reopening Journal reconstructs retained transcript and receipt but does not reconstruct an executable pending turn. There is no restart-durable source dedup or exactly-once speech guarantee.
- The STT provider call itself is not transactionally coupled to Journal and this leaf adds no A9 provider/effect attempt accounting.

## Roadmap/source deviations and remaining work

- The roadmap describes appending after the source can accept/fence speech. Source showed the existing Runtime acceptance operation was itself mutating and could not be safely rerun after Journal commit. This leaf therefore splits it into a Runtime-owned provisional reservation plus token finalization/release, with VAD independent during database I/O.
- `transcribeSpeechAudio` had a documented transcription-only contract but mutated capture admission; there were no production callers. It was corrected to be transcription-only so no production bypass can create receipt-less pending speech.
- Available observation/capture/segment identifiers are not durable source identities; Journal dedup remains unused.
- A8.2a durable event and payload storage are implemented here only through the existing repository. There is no A9 outbox, provider attempt/reconciliation, Runtime replay, or durable pending-turn state.
- A8.2d standalone vision, A8.2e controller/product/Person/P8 controls, A8.2f voice identity controls and aggregate ingress-bypass closure remain planned. A9 and A10 are untouched.

No SnowLuma A12.1 authority was changed. No production preview receipt, external effect, raw-media archive or A9/A10 behavior was added.
