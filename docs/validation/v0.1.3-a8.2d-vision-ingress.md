## Focused source audit

Before editing, the target branch matched the required starting commit and contained no A8.2d implementation. A8.2a–A8.2c were implemented; A8.2d was planned. The preserved pre-A7.1 stash remained at object `5d8a6ae43981c486b5f2ee5f48a0565e72fdfbf8` and was not modified.

`POST /v1/vision/analyze` was a standalone provider path, separate from Runtime: parse `VisionRequestSchema`, validate either a public HTTP(S) `imageUrl` or canonical PNG/JPEG base64 (up to 20 MiB), create the request disconnect boundary, resolve the vision provider, then call `analyzeImage` with the same image fields, prompt, identity metadata and `AbortSignal`. It had no Journal receipt. A truthy URL takes provider-source precedence over base64; an empty URL falls through to base64. Request disconnect is tracked from raw request abort/socket close; after provider start that signal is passed through the existing provider cancellation contract. The route did not prefetch remote URLs.

`VisionRequestSchema` inherits `sessionId`, `subjectUserId`, `createdByUserId`, `personaId`, `speakerId` and `voiceProfileId` from the shared media identity schema. The route passes those values as provider metadata, but the source has no authenticated transport-principal or Person-binding authority. The provider interface accepts URL/base64/prompt and a call signal; it does not require Runtime. The shared AppContext already owns the Journal repository through the A8.2a Pool and exposes narrow A8.2b/A8.2c facades. A8.1 already supports IMAGE and TEXT descriptors, retention states, TEXT selectors, unresolved identity/audience states and host-supplied authority. No protocol or Journal API change was needed.

No stable authenticated upstream vision request identity exists. Session IDs, caller hints, image bytes/URLs, image hashes, prompts, timestamps and request addresses are not source-dedup identities. No A8.2d append uses `sourceDedup`.

## Host receipt boundary

`HostVisionReceiptAdmission` in `apps/server/src/vision-receipt-admission.ts` is a separate narrow host facade. Its strict input accepts only a host-derived `INLINE_BYTES`/`URL_REFERENCE` classification and optional prompt. The route never passes it raw `imageBase64`, decoded image bytes, `imageUrl`, MIME text, session/caller identity hints or provider output. The facade uses the existing `JournalRepository.appendWithHostAuthority`; AppContext exposes only `VisionReceiptAdmission`, not the repository.

The facade creates one A8.1 `RECEIPT` with unknown occurrence time, no causal parents, unresolved principal and Person binding, no subjects, unknown audience, unresolved disclosure policy and an unresolved source reference. The route correlation list is empty; no caller-controlled session or identity hint is promoted to Journal authority. No source dedup key is supplied.

Inline image bytes use `DIRECT_OBSERVATION` only to establish that YUVI received image material at the endpoint. A URL uses `ATTRIBUTED_ASSERTION`, because the ingress received only a caller-supplied reference; the remote image content has not yet been observed by YUVI at receipt time. Neither classification establishes what the image depicts, model/provider truth, OCR, labels, objects or confidence.

Every request has a host-generated IMAGE payload reference with `retention: NOT_RETAINED` and `selectable: false`. The command has no IMAGE selector. Image bytes, data URLs and URLs are never given to the Journal facade or written to Journal columns. URLs are not prefetched, persisted as source references/payload metadata, used for dedup, or added to logs by this leaf. The existing A8.1 descriptor cannot encode safe source-form/MIME metadata without widening the schema; the inline-versus-reference distinction is used only for the receipt class and is otherwise omitted.

A present prompt is retained separately as a host-generated immutable TEXT payload, with the exact string and Unicode code-point bounds. A nonempty prompt gets a selector over that TEXT payload only. An empty prompt may be represented as retained, nonselectable TEXT with zero characters; an absent prompt creates no TEXT descriptor or content. The prompt remains user input, not truth.

## Ordering and cancellation

The production route is:

```text
validate request and image source
  → install request disconnect boundary
  → host-built PostgreSQL RECEIPT append
  → check cancellation / response currentness
  → resolve provider and call analyzeImage with existing AbortSignal
```

If the boundary is already aborted, the route returns the existing bounded cancellation response without starting admission or provider work. Journal failure maps to HTTP 503 with only one of `JOURNAL_UNAVAILABLE`, `JOURNAL_ADMISSION_REJECTED` or `JOURNAL_PERSISTENCE_FAILED`; no provider call, in-memory fallback or retry follows. Database/SQL details, connection strings, URL, image data and provider configuration are not returned.

If disconnect happens while the append is blocked, the append is allowed to settle according to PostgreSQL. After a successful commit, the route checks cancellation before provider resolution/invocation. It keeps the receipt and does not call the provider. The deterministic PostgreSQL test holds the real namespace-state row lock, observes the append reach its `FOR UPDATE` query, disconnects, then releases the lock and verifies the receipt commits while provider call count remains zero. A second barrier pauses after an actual PostgreSQL commit but before the route resumes; disconnect at that boundary also leaves the receipt and prevents provider work. If disconnect occurs after provider start, existing AbortSignal behavior remains covered by media route cancellation tests.

Provider response text and analysis metadata are returned as before and are not appended as RECEIPT, OUTCOME or DERIVATION. Provider effects are not given A9 INTENT/ATTEMPT accounting here.

## Roadmap/source notes and remaining limits

- The source confirms this route is provider-facing and outside Runtime. No universal ingress manager, Runtime gate, Memory writer or second Journal authority was added.
- A8.1 already has the needed IMAGE/TEXT payload descriptors and authority states. The source has no safe source-form field for inline-versus-URL, so the durable envelope does not retain that metadata beyond conservative `receiptClass` selection.
- The image itself cannot be reconstructed after restart. Its descriptor is metadata only; no exact image selector or post-restart visual grounding is claimed. Retained prompt text remains separately resolvable.
- The receipt proves input admission before provider work, not that the provider received, interpreted or correctly analyzed the input. There is no provider outcome lineage, external-effect accounting or retry/reconciliation.
- No authenticated principal, Person binding or audience snapshot exists on this route. Caller identity hints remain provider metadata only.
- A8.2e–A8.2f local-control, product, Person/P8 and voice-identity control receipts plus aggregate bypass closure remain planned. A9 and A10 remain untouched.

No SnowLuma A12.1 contract or validation document was changed. A8.2 aggregate status remains incomplete.
