## Focused source audit

The audit was performed against the verified starting tree before route changes.

1. **HTTP route ownership.** `POST /message` and `POST /v1/messages` register the same `handleMessage` function in `apps/server/src/routes/message.ts`; each supplies only its route-specific surface constant.
2. **Synchronous HTTP order.** Both routes parse `MessageRequestSchema`, normalize text/options, create a `user.message` Runtime event, then call `Runtime.handleUserMessage`. Runtime owns later conversation persistence and provider/semantic work. A8.2b now reserves an opaque Runtime event ID, commits the Journal receipt, then constructs the event with that ID and enters Runtime. A failed append creates no Runtime event and calls no Runtime handler.
3. **SSE order.** `/v1/messages/stream` had equivalent validation and created its event before constructing the async generator. Calling `streamUserMessage()` returns a generator; the first `.next()` starts Runtime lifecycle, persistence and provider work. The route now commits before constructing its ordinary Runtime event, generator or iterator, and before `.next()`, response hijack or SSE headers. Existing abort listeners, cancellation and iterator cleanup remain in place. The `speechObservationId` branch remains with the existing speech handoff.
4. **WebSocket fields.** `/ws` accepts a client-supplied `RuntimeEvent` containing `id`, `timestamp`, `traceId`, optional `parentId` and user payload. Those fields are treated as correlation only. The event ID is not a Journal event ID; trace/parent IDs are not source authentication, causal authority or dedup identity. Unsupported event types are rejected before Journal admission.
5. **Authentication.** The ordinary message routes and `/ws` have no principal-authentication pre-handler. CORS limits browser origins but does not authenticate users; loopback binding is network exposure policy; dashboard tokens guard selected other endpoints and are not applied to these routes. None establishes an authenticated transport principal, governed Person binding or audience membership.
6. **Stable source IDs.** HTTP request schemas do not contain a stable upstream message identity. WebSocket Runtime event IDs and trace IDs are client supplied and have no authenticated stability guarantee. No in-scope route supplies a valid source-dedup identity; A8.2b omits dedup and records identical text/repeated client event IDs as distinct receipts.
7. **Speech boundary.** The synchronous and streaming message routes accept `speechObservationId` and call `Runtime.commitSpeechTurn`. This is the existing finalized-speech handoff. A8.2b intentionally skips its independent conversational receipt for that path so A8.2c can create the original speech receipt without duplicate provenance. Standalone voice routes are untouched.
8. **Image behavior.** Existing chat image attachments are passed to Runtime after receipt admission. A8.1's `IMAGE` payload descriptor has no MIME/byte-length fields, so this leaf records only a host-generated IMAGE reference marked `NOT_RETAINED` and nonselectable; it does not broaden the contract or persist base64/raw image bytes.

## Implemented admission and authority boundary

`apps/server/src/conversational-receipt-admission.ts` is one host-owned facade shared by the ordinary HTTP, SSE and WebSocket routes. It accepts only a strict normalized input containing route surface, session/conversation ID, host-generated Runtime event correlation ID, exact normalized text and image-presence metadata. It has no Memory, Person resolver, provider, voice-identity or Runtime execution authority.

The facade proposes a versioned A8.1 `RECEIPT` with unknown occurrence time, no causal parents, an `ATTRIBUTED_ASSERTION` classification and an exact Unicode code-point selector over the retained normalized text. It generates immutable payload references and persists the text through the Journal's retained TEXT payload support. Its separate host-built authority draft records the route surface, conversation and Runtime correlations, host-owned producer/policy versions, unresolved principal, unresolved Person binding, no subjects, unknown audience, unresolved disclosure-policy/source references, and the payload descriptors. `subjectUserId`, `personaId`, WebSocket event metadata and model text never enter the authority draft.

A8.2a's configured static `authorityBuilder` could not safely accept per-request route facts without smuggling them through producer data. The narrow API evolution adds `JournalHostAppendInput` (command plus retained text only) and `appendWithHostAuthority(input, authorityDraft)`, keeping producer data and authority as separate parameters. The PostgreSQL repository still assigns the journal namespace, event ID, recording time and serialized commit sequence, then validates and commits the envelope transactionally. AppContext exposes only `ConversationalReceiptAdmission` to routes; its raw `JournalRepository` remains private. The `buildServer` override is a trusted host-composition seam used by tests/in-process fixtures, not request-controlled input.

HTTP/SSE select a host Runtime event correlation ID before append, commit it into the Journal correlations, then create the Runtime event with that ID only after successful append. The Journal event ID remains independently assigned by PostgreSQL. WebSocket retains its wire-compatible client event and uses its ID only as correlation. No conversation database or Runtime work is claimed to be atomically committed with the Journal; a crash after receipt commit can leave downstream processing incomplete, which is truthful evidence that YUVI accepted the input.

Admission failures are mapped to bounded codes: database unavailable becomes `JOURNAL_UNAVAILABLE`; invalid/unsupported proposals become `JOURNAL_ADMISSION_REJECTED`; transaction/payload failures become `JOURNAL_PERSISTENCE_FAILED`. HTTP and SSE return 503 before Runtime or stream headers; WebSocket emits a redacted `runtime.error`. Internal database details are not returned to the caller. No retry or in-memory fallback is added.

## Roadmap/source deviations and remaining limits

- Source has no transport-authentication or audience-membership seam on these routes; A8.2b therefore records explicit unresolved/unknown authority rather than applying local-controller or `subjectUserId`/`personaId` hints.
- Source has no stable upstream message ID for these endpoints. The contract's optional source-dedup capability is not used; no content hash, session, trace, Runtime event ID, caller identity hint, address or timestamp is substituted.
- The A8.1 IMAGE descriptor cannot carry MIME or byte-length metadata. Only modality, retention and nonselectability are recorded. Raw image data remains Runtime-only.
- `speechObservationId` requests continue to bypass the A8.2b admission facade and await A8.2c finalized-speech ownership. This is an explicit source-aligned exception; aggregate conversational/ingress closure is not claimed.
- Journal and conversation persistence are separate transactions. The receipt establishes acceptance by YUVI, not completion or atomicity of downstream Runtime, provider, conversation or Memory work.
- Only the ordinary message ingress paths listed above are covered. Finalized speech, standalone vision, local-controller/product/P8 controls, voice identity and aggregate bypass auditing remain A8.2c–A8.2f. No A9 outbox/dispatch/retry/reconciliation or A10 lineage work is included.
