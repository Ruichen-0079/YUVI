## 3. Canonical INTENT model and package ownership

Journal is a declared development dependency/project reference so standalone effects checks build the compiled real-store adapter used by process-death tests. An `effect-intent.v1` record freezes `intentId`, `logicalKey`, versioned `contractRef`, semantic `payloadDigest`, request scope/audience, causal Journal references, nullable execution correlation, owner-declared deadline, exact contract payload where admitted, policy/authority versions, permission decision and exact identity snapshot. Contract reference resolves a static immutable owner/version/key policy/payload policy/cancel/expiry declaration. This preserves one admission decision while representing later pre-attempt withdrawal without rewriting history. No `attemptId` or `remoteEffectId` is created. Journal receipt, Runtime `executionId`, `intentId` and `logicalKey` have separate meanings.

## 5. Logical identity and digest

Intent identity is `ei1_` plus SHA-256 of canonical `{owner, logicalKey}`. Owners must supply a stable domain/scoped logical key; the API does not allocate a random request ID as a dedup key. Scope is frozen in semantic content, so accidental reuse of one owner's key for another scope conflicts. Static contract version is also bound to semantic content.

- Same owner/key and same semantic payload: exact first decision/current work projection, including after restart.
- Same owner/key with different semantic payload or contract: typed CONFLICT.
- Different owner/key: different logical effect.
- Changed execution correlation or current authorization version: replay retains the first frozen admission snapshot; it does not reauthorize or reactivate work.

Canonicalization accepts finite acyclic plain JSON without getters/functions/undefined, sorts object keys, preserves array order, bounds depth/nodes and bounds request bytes to 256,000. Contract payloads are strict: correlated device-neutral embodied behavior or an authorized read-path descriptor. Arbitrary model text, credentials/configuration slots and dispatcher metadata are not accepted payload extensions. Owners must supply safe opaque references and permitted paths; the facility is not a secret-redaction service.

Digest includes intended payload, contract, scope, audience, causal references and expiry. It excludes `logicalKey`, Runtime `executionId` and embodied source allocation `createdAtMs`; those do not change the intended semantic effect. Retry count, worker, lease, latency and provider confidence are not admitted request fields. Changing path, effect semantics, audience, scope, cause or expiry changes the digest. Static permissions are host decisions; no model/provider label/confidence can grant them.

## 6. Causality, authorization and currentness

The host facade resolves every exact namespace/event ID through the committed Journal reader, requires a RECEIPT and compares the identity snapshot to committed receipt authority. Receipt-looking IDs, missing causes and non-receipts do not authorize decisions. It does not infer Person binding from storage scope or treat the receipt as world truth. The INTENT references receipt authority; it does not become a Journal event or append receipt/derivation/outcome records.

The authorization snapshot is trusted host input, never transport/model data. It describes the owner's existing policy decision, permission and version; the effects package does not create grants or invent a policy authority. Scope/audience mismatch or absent contract permission produces DENIED. The staged Runtime API adds lifecycle-active and expected activity-revision currentness and participates in Runtime drain. It does not consume the existing read-text grant or claim future capability execution authorization.

For a newly admitted row, after asynchronous Journal lookup, connection acquisition, INSERT and decoding, the store invokes the synchronous host currentness/deadline fence immediately before submitting COMMIT, with no intervening asynchronous yield. A late failed fence rolls back the entire row and returns AUTHORITY_CHANGED, not an outcome. Exact replay does not make a new admission and retains the original decision. Authority valid at COMMIT submission is the admission boundary; later revocation, changes during COMMIT I/O and future dispatch permission require A9.2 handling. This is not a distributed transaction with an external policy owner and is not dispatch-time authorization freshness.

## 7. Atomic durable work and DENIED

One database row represents the logical admission and its durable work projection. A new successful ADMITTED decision necessarily has state ADMITTED and work PENDING in that same committed row. There is no separate table write that can leave intent-only or work-only committed state. PostgreSQL checks tie column mirrors, immutable admission JSON, payload retention and permitted state/work combinations; a trigger fences immutable fields and terminal transitions. Strict reads verify identity/digest and the effective work projection.

Dispatch eligibility, for a future owner, additionally requires current ADMITTED/PENDING state and an unexpired deadline. A retained immutable ADMITTED decision can later have CANCELED/EXPIRED state and WITHHELD work; the historical decision is not a dispatch permit.

DENIED retains only safe request identity/context/deadline, digest, causal references, authorization snapshot and bounded reason. Rejected payload is absent and work is SQL NULL. It is immutable and replayable; later permission changes cannot grant the same denied logical intent. DENIED is not OUTCOME and proves no external effect. Invalid requests, unknown/unavailable Journal causes and database failures are failures before a returned decision, not durable denials. Lost COMMIT response is explicitly ambiguous persistence status: retry of the exact logical key resolves the existing committed row rather than duplicating it.

## 8. Pre-attempt cancellation, expiry and future fence

Cancellation locks the same row and transitions only ADMITTED/PENDING → CANCELED/WITHHELD. Expiry transitions only unattempted ADMITTED/PENDING → EXPIRED/WITHHELD. Pending enumeration checks PostgreSQL `clock_timestamp()` even before a sweep; it never lists an already expired deadline. No universal TTL is invented: each accepted contract requires an explicit owner deadline. Requests expired at initial admission are DENIED with EXPIRED_AT_ADMISSION. A deadline reached during the transaction rolls back.

Canceled/expired work never returns to PENDING on replay or reopen. Cancellation that observes no initial row returns null; it does not promise a durable future cancellation. An admission racing that observation may subsequently create pending work. Once cancellation returns CANCELED, every subsequent replay remains withheld. Tests cover both this initial race and cancellation against concurrent replays.

CLAIMED is only a reserved same-row fence for A9.2. A9.1 has no claim API, attempt record or dispatcher. Schema tests race a raw test-only reserved-field update against cancel and prove that both cannot win. A9.2 must atomically persist its first ATTEMPT and claim the same ADMITTED/PENDING/unexpired row, then implement remaining state/accounting machinery. The row-lock boundary is already available without redesigning logical admission identity.
