## Source finding and policy

`requireDashboardDevToken()` is intentionally a development-token helper: for every `runtimeMode` other than `development`, it returns `true` without authenticating the request. Production composition registers Memory routes with `ServerConfig`, so the previous route checks did not restrict production manual Memory mutations, even when a dashboard token was configured. This leaf did not change the shared helper or unrelated routes.

Production manual create (`POST /memory`), edit (`PATCH /memory/:id`) and reactivation (`POST /memory/:id/restore`) now return bounded 404 before schema parsing or mutation in all non-development modes. Development still uses the existing development-token behavior when configured, including its intentional LAN access. No Journal receipt was added: these routes accept caller-entered content and provenance-like fields, and a receipt would not turn those fields into original evidence, authenticated Person claims or A10 lineage.

Production withdrawal/removal (`POST /memory/:id/archive`, `POST /memory/:id/forget`, `DELETE /memory/:id`, and `POST /memory/bulk-delete`) uses the existing `requireLocalDashboardAccess` boundary. Non-local production callers receive 403 before repository mutation; localhost calls retain existing repository behavior. Local access is not human or Person authentication. These operations do not append Journal receipts and remain independent of Journal availability so deletion/withdrawal can still remove material from ordinary retrieval. Deleted Memory content is not copied into Journal.

`POST /memory/maintenance/run` is now development-only regardless of token configuration. Candidate recent/accept/reject routes remain unavailable outside development. Read/search/detail paths were not restricted by this change.

The affected routes continue to operate through the existing `memoryRepository`. This leaf does not establish cross-backend erasure when Runtime semantic Memory is backed by Mem0, and it does not synchronize with Mem0. It does not repair legacy Memory attribution/provenance, controller/P8/Person lineage, or introduce A10 behavior.
