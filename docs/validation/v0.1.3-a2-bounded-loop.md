## Changes and authority

`packages/core/src/runtime-cognition-interaction.ts` executes one interaction inside the already-admitted Runtime operation. It consumes normalized semantic decisions through injected callbacks. It owns all repetition, admission, counters, timeout, cancellation and terminal transitions. Core receives control discriminants and opaque payloads; Cognition remains the semantic validator. Phase-6 6J remains the admission gate, with its old one-call default preserved for legacy callers and an explicit bounded maximum for the new path.

`apps/server/src/cognition-interaction.ts` only composes existing 6U/6W input/output boundaries, the Runtime one-shot provider seam, current 6L discovery, 6M read-text binding and 6O/6N observation normalization. Every proposal is revalidated against currently discovered authorized capabilities. Transport errors, tool errors, unavailable tools and malformed responses never fabricate successful evidence. There is no capability retry. The concrete file path stays Runtime-authorized and absent from model input.

`RuntimeOrchestrator` allocates a fresh execution identity for each explicit turn, aborts an older same-session Cognition owner on replacement, and checks ownership after Cognition, after Character re-entry/body generation and before assistant commit. Other sessions remain independent. One Cognition interaction still feeds exactly one Character re-entry; another NEED_COGNITION still fails through the existing rule. Both ordinary and streaming paths carry the combined cancellation signal.

Reasoning calls use the existing provider registry with `allowFallback: false`. One admitted reasoning round therefore cannot silently expand to multiple configured providers. Legacy callers retain their existing fallback behavior; this is not a new router.

## Limits and terminal behavior

Existing server configuration owns these environment values; invalid values fail configuration validation before execution:

| Setting | Default | Allowed range |
| --- | --- | --- |
| `COGNITION_MAX_REASONING_ROUNDS` | 4 | 1–8 |
| `COGNITION_MAX_CAPABILITY_CALLS` | 2 | 0–4 |
| `COGNITION_TIME_BUDGET_MS` | 60000 | 1–120000 |

Core independently checks these hard ceilings and snapshots the limits. Counts are charged before starting I/O, including failed attempts. CONTINUE consumes another reasoning slot and cannot replace the task or replenish a budget. A capability request on the last reasoning slot is refused because no slot remains to consume its result. Policy denial and zero capability budget perform no invocation. COMPLETE is absorbing, including a normalized non-success result; it does not mean the evidence is true.

The monotonic deadline and the caller's abort signal feed one interaction signal sent through discovery, provider and capability calls. Abort, current execution identity and deadline are checked before and after asynchronous work. Late responses cannot enter another iteration or escape to Character after cancellation/replacement. A provider or tool that ignores abort remains awaited: its late result is discarded, and existing seal/drain retains ownership until the admitted call settles. This is an admission/result deadline, not a claim that JavaScript can forcibly stop non-cooperative I/O. Sealing refuses new work while allowing admitted, current work to drain; disposal remains the existing authority.
