## Repository findings preserved by the new architecture

### A0–A6 status

A0–A6 are complete at the audited baseline. The old roadmap text was stale because it still described A5/A6 as pending and made Windows/macOS bring-up part of v0.1.3 closure. The rewritten roadmap preserves the completed implementations and their existing validation records rather than renaming or reimplementing them.

### P8 authority

No direct LLM/provider/Cognition/Character path was found that commits P8 identity or relationship state. Authored invariants remain authored; relationship context is reconstructed per turn; persistent P8 corrections require local dashboard access and `EXPLICIT_USER_CORRECTION`. Assistant-generated evidence is non-authoritative.

Therefore P8 is not rewritten. It receives a field-level ownership map and follows `shadow → compare → atomic switch → remove` only after replacement authorities exist.

### Legacy LLM Memory extractor attribution defect

A concrete defect was reproduced in the optional legacy LLM extraction path:

- accepted generated candidates are assigned `originRole: user`;
- model-supplied `sourceTraceId` and time/validity fields can override authority-supplied values;
- provenance enrichment can attach unrelated user text as evidence;
- a deterministic stub reasoner that invented a preference unrelated to the input produced a stored `durable-core` Memory row with forged source trace and user attribution.

This path applies to legacy Memory with `MEMORY_EXTRACTOR=llm`; it does not characterize the rule-based default or Mem0 path. P8 can be contaminated indirectly because it consumes Memory provenance, so the repair belongs upstream in A10.1 rather than in a new P8 writer.

### Direct controller profile write

`apps/server/src/services/profile-evidence.ts` writes controller-originated `EXTERNAL_CLAIM` evidence directly to the Memory provider without Runtime admission, causal receipt or idempotency key. A10.2 routes this through the causal-history authority instead of inventing a second Person/Memory store.

### Existing delivery machinery to reuse

The finalized-turn ingestion ledger and Dream delivery already implement stable child identities, payload digests, persisted dispatch start, lease/reconciliation states, idempotent provider delivery and explicit ambiguous recovery. The new A9 `INTENT → ATTEMPT → OUTCOME` design reuses these semantics and must not create a parallel retry engine.

### Retention and reconstruction boundary

The current system does not retain every raw perception. Normalized text conversation is durable; visually grounded inputs can be `memoryEphemeral`; voice-review retains only a bounded private local sample buffer for controller review. The Future architecture therefore claims causal reconstruction only for authorized retained content and explicit payload-availability states. It does not invent missing raw sensory data.

## Decisions made by consolidation

1. **Research target:** causal continuity of lived history replaces a mandatory persistent-self substrate.
2. **Journal semantics:** the Life Event Journal is authoritative for YUVI's recorded experience/decisions/effect accounting, not world truth.
3. **Authority:** models may interpret and propose; they do not unilaterally commit facts, identity, obligations, long-term dispositions or policy.
4. **External effects:** one logical intent identity, no blind replay and explicit uncertainty replace universal exactly-once-delivery claims.
5. **Memory:** a lineage-bound evidence/index layer; Mem0 and legacy stores remain derived/replaceable rather than canonical history.
6. **P8:** preserve working authority now; deprecate field by field only after replacement owners pass gates.
7. **Prospective continuity:** explicit COMMITMENT / EXPECTATION / INTENTION plus derived OPEN_THREAD is preferred to simulated desire/social-need machinery.
8. **Consolidation:** persistent state must have a measurement definition. LLMs act as bounded semantic measurement instruments; deterministic/governed reducers own accumulation.
9. **Self-generated language:** never qualifies as evidence for YUVI's own disposition. Revealed-disposition evidence remains a later hypothesis under strict counterfactual/resource constraints.
10. **Learned Z:** downgraded to an optional model-independent selection/ranking research artifact. It must beat explicit B3/oracle controls and remain replayable/deletable/portable; otherwise it is rejected.
11. **Life Layer:** no generic Life Layer/Continuous Regulation umbrella. Time/scheduling, selection and embodiment have separate owners.
12. **Model replacement:** continuity is tested separately for facts/obligations, relationship/preferences, normative behavior and style; there is no single “Yuvi-like” score.
13. **v0.1.3:** Windows/macOS release parity is removed from closure; causal history, crash ambiguity, provenance/lineage, conformance and one real external surface are the closure boundary.

## v0.1.3 closure invariants

The rewritten roadmap uses six invariants:

- I1 durable before effect;
- I2 one logical intent identity;
- I3 no blind replay;
- I4 no fabricated certainty;
- I5 causal reconstruction for authorized retained content with complete lineage;
- I6 thin external surfaces with no alternate Runtime/Memory/provider/persona authority.

These are architecture requirements, not evidence that the corresponding A7–A12 code exists today.
