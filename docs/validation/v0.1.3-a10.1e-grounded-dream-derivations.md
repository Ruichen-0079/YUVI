## Pre-compression source contract and persistence

The production path is:

```text
exact persisted conversation user row
→ full original content + exact sourceJournalRef
→ existing JournalMemoryGroundingResolver
→ validated original retained TEXT selector and source snapshot
→ episode-source-evidence.v1
→ compact statement for semantic/context use
→ frozen Dream source snapshot
→ DERIVED lineage
→ existing stamped keyed delivery
```

`captureEpisodeSources()` uses full, untrimmed persisted content. Conversation window bounds select whole messages and do not truncate their content. Resolution reuses A10.1c: eligible committed RECEIPT, exact namespace/ref, retained/selectable USER_INPUT or EXTERNAL_RESULT TEXT, Unicode-code-point selector, exact selected-text equality. No Journal search, similarity, trace/time/session inference or second receipt exists. Missing/malformed/unknown/wrong-parent/mismatched/unavailable/nonselectable ancestry remains unavailable with stable grounding reasons. Assistant messages never receive evidence entries.

First-class `EpisodeSourceEvidenceV1` (`episode-source-evidence.v1`) contains:

- up to 256 statement entries, keyed by original `sourceMessageId` and `statement:<sourceMessageId>`;
- compact semantic statement, SHA-256 of full original source content;
- nullable validated source: Journal ref, original TEXT selector, source origin, exact authority snapshot and committed recordedAt/occurrenceTime;
- explicit unavailable reason and a bounded historical-message-ID fence.

Compact text is a representation, not a selector over a new original receipt. Long Unicode tests prove selector bounds still cover the full original source while displayed statements are compacted. No raw audio/image payload enters this contract.

Coverage is **GROUNDED** when every eligible source is mapped, **PARTIAL** when grounded entries coexist with gaps, and **LEGACY_INCOMPLETE** when no eligible grounded entries exist. Only grounded entries can produce durable Dream children; incomplete episode context remains available under existing context behavior. Zero grounded sources explicitly skip consideration as `legacy-lineage-incomplete`; zero eligible derived outputs skip with `DREAM_NO_GROUNDED_OUTPUT`.

Migration **016_episode_dream_source_evidence_v1.sql**, after 015, adds nullable `recent_episodes.source_evidence`, `source_evidence_version`, `source_evidence_digest`, `source_coverage_state`, and first-class `dream_jobs.source_snapshot`, with owned version/shape constraints. Migration 012 is unchanged. Fresh schemas and two applications of 016 pass. Old null rows remain readable/incomplete; SQL performs no historical matching/backfill.

Both stores preserve the first observed source state. For a historical null-map row, existing sourceTurnIds become a fence. Reconstruction cannot retroactively ground those IDs. Newly appended grounded entries can extend the episode with PARTIAL coverage. An unavailable existing entry remains unavailable; an already grounded source/content conflict rejects `EPISODE_SOURCE_CONFLICT`. PostgreSQL serializes same-episode upserts using a transaction advisory lock plus row lock, so concurrent upserts cannot evade the fence. In-memory results follow the same semantics and deeply clone sources.

The original episode sourceDigest remains a context digest; historical digest values are not relabeled grounded. A separate canonical source-evidence SHA-256 binds statement/message identities, full-content digests, original parents/selectors, authority/time and gaps. Statement entries and historical IDs sort canonically without locale-dependent ordering. Same text with a different receipt changes evidence identity or fails conflicting stable-source admission.

## Frozen Dream source revision and derived lineage

Admission freezes typed **dream-source-snapshot.v1** (maximum 64 episodes / 262,144 UTF-8 bytes), containing exact episode IDs, source-evidence digests and complete source maps. Dream sourceDigest binds sorted episode/evidence identities, storage scope and policy **a10.1e-deterministic-dream.v1**. The existing outer Dream engine version remains `memory-vnext-dream.v1`; the new policy/source snapshot explicitly distinguishes grounded work from old jobs.

Execution validates the frozen snapshot/digest and derives from that snapshot, never later-mutated episode text or newly resolved Journal state. Episode consolidation uses an atomic expected source-evidence digest check; extension before or during backend delivery cannot mark a newer revision consolidated under an older job. The source freeze also prevents mutable episode order from changing work identity.

`MemoryLineageV1` retains `memory-lineage.v1` and its original direct-write reader shapes. A strict backward-compatible DREAM_DERIVATION alternative adds:

- state GROUNDED and origin **DERIVED**;
- canonical deduplicated parents plus a matching `sources` array;
- each source's original ref/selector, USER_ASSERTION or EXTERNAL_OBSERVATION origin, authority and recordedAt/occurrenceTime;
- retained-selectable availability, consumer key, producer `@companion/memory` / `0.1.0`, and policy version.

This derived shape has no fabricated aggregate principal, binding, audience or original occurrence time. Heterogeneous parents keep independent snapshots. Parent/source disagreement fails schema validation. No V2 or destructive historical lineage rewrite is introduced.

Consumer identity is computed before lineage-bearing delivery hashing:

```text
fingerprint = SHA-256(canonical {kind, NFC content, scope})
consumerKey = mld1_ + SHA-256(canonical {canonical source snapshots, policyVersion, fingerprint})
→ complete DERIVED lineage
→ MemoryWriteEventInput
→ stampDreamWriteEvent(jobId, event)
→ payloadDigest + yuvi:dream-job:<jobId>:event:<payloadDigest>
```

No circular digest, random Memory/backend UUID or job ID alone supplies semantic identity. Reordering identical sources preserves consumer identity/digest/key. Different source ancestry changes identity. String recurrence dedupe and output dedupe merge all contributing grounded source sets instead of selecting one arbitrary receipt; recurrence still does not increase confidence.

Dream events use **system/unverified** assertions and omit original-user claim/participants/source clocks. Compatibility subjectUserId/personaId remain storage partitioning only. Deterministic semantic extraction behavior is retained; no LLM, model escalation or model authority is added. Hearsay content retains the report attribution and is unverified; a Dream child is not reclassified as a resolved SELF_REPORT or verified external-world claim.

Typed conversation and mock-text speech retain USER_ASSERTION parent snapshots. Real finalized speech retains EXTERNAL_OBSERVATION from DIRECT_OBSERVATION/EXTERNAL_RESULT. All children are DERIVED. Voice profiles/acoustic hints and compatibility IDs cannot upgrade source identity. Unresolved principal/binding and unknown audience remain exact. UNKNOWN/INSTANT/INTERVAL occurrence states remain per parent; episode startedAt, execution/retry time and Mem0 created_at do not become original occurrence truth.

## Delivery, crash and historical work

The existing job stores, leases, atomic concurrent claims, C1-style keys, resultEventPayloads, writeEventIdempotent/reconcileEvent and ambiguous-write fence remain the delivery machinery. Final lineage exists before stamping and durable result persistence. Frozen source snapshots/results are immutable in both stores; conflicting replacements fail `DREAM_FROZEN_PAYLOAD_CONFLICT`. Deep clones prevent accidental mutation in in-memory reads.

- Crash before a frozen dispatch payload: existing lease reclaim safely derives from the admitted frozen source snapshot.
- Frozen/dispatched result payload present: executor enters reconcile_required **before loading episodes or extraction**. No re-derivation or Journal resolution occurs.
- Backend applied / result recording lost: exact frozen key/digest remains for reconciliation. Writer exceptions/incomplete outcomes are ambiguous; post-freeze persistence failures preserve stored children rather than erasing them.
- Applied reconciliation completes without redispatch. Not-applied may retry only the exact grounded frozen payload; applied children are not resent when another child is not-applied.
- In-flight/unknown remains unresolved without blind automatic replay.
- Historical complete/skipped/terminal jobs remain history without attached lineage or backend rewrite.
- Old pending/expired processing work without a grounded source snapshot terminalizes as `DREAM_LEGACY_LINEAGE_MISSING` before new delivery.
- Old reconcile_required frozen effects reconcile exactly: applied records historical completion; not-applied cannot newly dispatch ungrounded payloads and terminalizes explicitly; in-flight/unknown remains unresolved. Historical effects do not consolidate a later grounded episode revision.

Unavailable writers still skip without marking episodes consolidated. Production uses the existing MemoryProvider when present. Injected DreamWriter receives the same final DERIVED payload and cannot authorize an ungrounded source.
