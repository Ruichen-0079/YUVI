## Receipt boundary and ownership

The existing `HostVoiceControlReceiptAdmission` is extended with only three strict operations: leave-unknown review, Person review, and Product multi-recording enrollment. The facade accepts bounded target IDs and an `enrollFromSample` bit. It receives no request object, raw review sample, input recordings, combined WAV, display name, label, embedding, Runtime, Memory or provider reference. Receipts are `RECEIPT/CONTROL`; they prove that the locally authorized command was admitted for processing, not that review, enrollment, binding, replacement or cleanup succeeded.

Receipt authority remains `principal=UNRESOLVED`, caller binding `UNRESOLVED`, `subjects=[]`, and audience `UNKNOWN`. Sample, profile and requested Person IDs are command targets only. There is no source dedup: these local control requests have no stable transport-delivery identity, and domain IDs/audio hashes are not substituted for one.

The retained TEXT summary contains only operation mode and bounded target IDs. A nonselectable `AUDIO/NOT_RETAINED` descriptor is added only when review auto-enrollment consumes an existing review sample or a multi-recording enrollment consumes submitted audio. Leave-unknown and binding-only review add no audio descriptor. Raw WAV/base64, combined WAV, audio hashes, display names, provider labels and embeddings are not written to Journal. The pre-existing bounded private review buffer remains unchanged as the separate owner of retained audio.

## Route ordering and race behavior

- **Review intent.** A strict union accepts exactly `{ leaveUnknown: true }` or `{ personId: bounded saved-Person ID }`; empty, false, conflicting, extra-field and malformed requests receive 400 with no receipt or mutation. The sample route ID is bounded.
- **Leave unknown.** Local authorization and sample lookup → Journal receipt → sample re-read and snapshot comparison → private review update. Journal failure leaves the sample unchanged. A missing/changed sample after commit leaves the receipt and returns conflict without applying stale state.
- **Assign saved Person.** Local authorization and strict intent → saved Product Person check → binding-owner readiness → provider inventory check → verify existing profile or preallocate one profile ID for automatic enrollment → Journal receipt → re-read and compare sample ID, creation time, profile ID, decision flag and exact sample bytes → provider enrollment from the newly read row when required → associate the exact generated profile with that row → Runtime binding. Binding-only reviews recheck the provider profile and review snapshot before binding. The provider receives the same generated profile ID recorded by the receipt.
- **Privacy deletion race.** `DELETE /product/voice-samples/:id` remains Journal-independent. A deterministic real-PostgreSQL barrier holds review append; deletion succeeds while append is blocked; after release, the review route observes the missing sample, retains the committed receipt, returns conflict, and performs no enrollment/binding or sample recreation.
- **Multi-recording enrollment.** Local authorization → strict 3–5 bounded recording schema → saved Person/binding owner/provider preflight → `boundedWav` for each recording, compatibility validation and combined-WAV construction → preallocate the new profile ID → verify an optional old profile exists and its trusted binding currently resolves to the requested Person → Journal receipt → provider enrollment with the same ID → retain the existing bounded private sample → Runtime binding → optional old-binding recheck, removal, old-profile deletion and old-sample cleanup.
- A malformed request or known-invalid replacement is rejected before receipt. A Journal failure prevents all f2 mutation except privacy sample deletion. Post-receipt partial failures keep the receipt and any already completed provider/file/Memory mutations; no cross-store rollback, OUTCOME, retry or reconciliation is claimed. If sample retention fails after provider enrollment, the route reports that the profile exists but does not fabricate a sample or binding. Replacement rechecks the old binding after new profile/binding setup; changed binding or cleanup errors leave the new profile in place and report the remaining state.

## Partial-failure limits

Provider enrollment can fail after a receipt; review-sample association can fail after profile enrollment; Runtime binding can fail after enrollment and sample association; Memory evidence can exist when its separate reference-index append fails. Multi-recording enrollment can similarly leave a profile without private sample retention or binding. Replacement can leave both profiles if old-binding removal fails, an unbound old profile if acoustic deletion fails after removal, or retained old samples if cleanup fails after profile deletion. These are reported bounded partial states, not distributed transactions. Memory/Person lineage repair remains A10 work; provider effect accounting remains later work.
