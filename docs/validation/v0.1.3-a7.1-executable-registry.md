## Implemented contract

The server now creates versioned executable-registry, descriptor and effect-contract values. Registration accepts only host-authored semantic references and descriptions plus an approved implementation reference; concrete MCP tool routing, required permission and effect contract are supplied from the host implementation table. The only executable implementation remains `yuvi.server.mcp.read_text_file.v1`, routed to `read_text_file`.

The effect contract independently records required permission, action kind, effect locus, data disclosure, reversibility, idempotency, reconciliation, and input/output schema versions. Explicit `UNKNOWN` and `UNSUPPORTED` values are retained. Unknown fields, unsupported enum values, incomplete contracts, invalid versions/tokens, duplicate capability or implementation references, and unknown implementations fail validation. Descriptors and nested effect terms are frozen. Cognition receives the existing semantic reference/description projection; it does not receive implementation refs, concrete tool names, permissions or effect contracts. Discovery intersects approved entries with listed tools and cannot promote or rewrite entries.

`read_text_file` stays on the same path: Core Runtime admits the capability round, then the server binds the proposal to the validated implementation, intersects the registry with current discovery, and passes only the Runtime-authorized path to the existing one-call MCP adapter. The adapter still normalizes the result through the existing observation seam. The redundant leaf admission helper remains as it did before this atom. The contract classifies this current operation; it does not authorize additional operations.
