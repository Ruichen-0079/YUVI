## Model and capture timing

Migration 024 adds two bounded immutable metadata tables:
`context_use_manifests` and `context_use_exposures`. There is one base per
installation namespace / execution / assembly ordinal, and one exposure per base /
consumer operation slot / exposure ordinal. Durable ordinals are bigint; wire
ordinals are decimal strings. `cm1_` / `ce1_` IDs qualify historical use, rather than
merely hashing content. Canonical body digests detect conflicting reuse; exact
admission replays the same records. SQL rejects historical UPDATE/DELETE. Migration
replay preserves records. Base plus first exposure commit in one transaction.

Runtime/A4 supplies the observed source vector and canonical block descriptors.
The Registry captures the actual provider input before async admission; a private
copy prevents caller mutation from changing what the leaf consumes. `HostContextUse`
is the single evidence writer, not an assembler, router or executor. It verifies
applicable current dependencies, captures the committed Journal cause, and commits
the base/exposure before A9 provider or capability admission. Missing repository,
required source or failed admission withholds the affected use. Consumer currentness
is checked before and after evidence admission. The canonical dispatcher rechecks
applicable owner dependencies before the leaf call, including notification loss.

Provider intents bind typed manifest/exposure references in the existing A9
input-snapshot seam. Attempts inherit that frozen input reference. Host read-text
uses its existing A9.2 executor and binds an exposure before admission. No new
attempt queue, mutable execution record, Journal mirror or delivery ledger exists.
Old committed A9 intents retain their explicit legacy/no-manifest literal; they are
not retroactively rewritten. Publication/playback evidence remains subordinate to
A9 and the existing conversation/component authority.

## Available, selected and exposed

Base source entries distinguish availability from selection. An observed candidate
may be AVAILABLE or explicitly OMITTED, with an exclusion reason; only A4-selected
inputs receive SELECTED. Original backend candidates survive validation/dedup in
the historical descriptors without changing A4 selection.

Exposure records describe the exact prepared input: ordered field paths/digests,
character counts, declared producer versions, block field/offset and
EXPOSED/TRUNCATED/TRANSFORMED/OMITTED state. Named XML/JSON projections trace direct
Chat, Character, Cognition and proactive budgeting. Character's declared immediate
affect field is traced separately. Matching untrusted user text, including injected
named tags inside UserMessage, cannot manufacture Memory exposure. A truncated
block's references identify its input dependencies, not proof that every source
survived the truncation byte-for-byte. Additional Cognition/capability observations
are exact submitted field digests with NOT_RETAINED contents; they never rewrite the
earlier base.

The immutable boundary is **PREPARED_FOR_USE**, not a claim that a provider received
the input. Reconstruction joins the existing canonical A9 intent/attempt/start and
terminal evidence for each exposure. Admission failure may leave prepared evidence
without an attempt; revocation may yield PROVEN_NOT_APPLIED; started ambiguity remains
UNKNOWN. Provider response, gateway acceptance, playback and human perception remain
distinct. A selected source or committed exposure alone never proves actual use.

## Correction, invalidation and retention

The existing chain remains CONTROL receipt → A9 command → native owner revision →
invalidation. Journal AMENDMENT stays reserved. Runtime refreshes direct conversation
reads and atomically replaces the current cache entry. Captured owner dependency
checks cover selected Memory, native binding, Product composition and P8; unavailable
or replaced dependencies withhold stale current use even when notifications are lost.
Profile keeps its existing f2 observation-boundary freshness guarantee.

Historic bases and exposures remain immutable during Person edits, voice rebinds,
P8 retractions, Memory correction and Profile regeneration. Concurrent independent
owner reads produce a revision vector: an L0 read can correctly retain the old row
while L1 observes its replacement. This is not a distributed cross-owner transaction.
Later read revisions are never attributed to earlier input. Failed reads cannot
manufacture EMPTY, and disabled reads are NOT_USED.

Availability supports AVAILABLE, EMPTY, NOT_USED, UNAVAILABLE, ERROR, NOT_RETAINED,
REDACTED, DELETED, STALE and LEGACY_UNLINEAGED. Later payload redaction/deletion is
reported alongside the original use descriptor. Historical identity is retained
where policy permits; unavailable bytes are not recreated. Metadata is strict,
bounded at 1 MB per record and protected by the same private scope as its source.
The reconstruction repository is an internal host/read port, not a new public
history endpoint. It must not be exposed without source-equivalent scoped access.

No prompt archive, private reasoning, Person notes, credentials, audio/image bytes,
embeddings or read-text file contents are stored solely for manifests. Existing
ordinary conversation retention stays with the conversation owner. Private digests
are not public PII identifiers or a retention exemption.

## Reconstruction guarantee

`PostgresContextUseRepository.get/reconstruct` reopens immutable base/exposure
identities, selection/projection relationships, exact protected semantic references
and canonical A9 evidence. A resolver receives the **historical** descriptor. It
must match both captured revision and digest; returning mutable current content
cannot satisfy an older read. Exact native Profile reads use `getRevision`, never
`getCurrent`. Original availability and later gaps are both visible.

The implemented guarantee is identities and use relationships. The API explicitly
returns `renderedContext: NOT_ARCHIVED`; it does not promise a retained full prompt.
Exact rendering is possible only when the owners retain every required input and
the declared transformation version is available. Missing/ephemeral/deleted bytes
remain a partial reconstruction. No stochastic/vendor-output replay, hidden
reasoning replay, deleted payload recreation, cache replay, authentication or
human-perception guarantee is made. Reconstruction invokes no providers, tools,
publication, media or device effects.
