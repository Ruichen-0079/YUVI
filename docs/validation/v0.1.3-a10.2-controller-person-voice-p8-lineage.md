# A10.2 — Controller, Person, voice and P8 lineage

**Status: CLOSED — IMPLEMENTED REALITY** (2026-10-03). This closure records the current implementation and its final validation. The architecture remains the frozen §3 contract in [the remaining-core architecture freeze](../future/v0.1.3-authority-effect-context-architecture-freeze.md); A9.3 and A10.3 were not started.

## Implemented boundary

Governed controller mutations now follow:

```text
CONTROL receipt
→ A9 INTENT
→ A9 ATTEMPT
→ native domain owner mutation
→ exact native revision/event
→ A9 observation
```

The stable semantic command key is scoped by command family, owner scope, and target. Receipt, intent, and pending work are admitted durably before dispatch. A duplicate command reuses its logical identity and does not duplicate the native mutation. After dispatch may have started, recovery inspects native owner state: an exact requested revision is APPLIED; an exact predecessor is PROVEN_NOT_APPLIED only where owner evidence proves it; an incompatible newer state remains UNKNOWN/CONFLICT. No blind repeat overwrites newer owner state.

Product Settings remains the only authored Person store. Reachable Person create, update, and primary-selection commands use native Product revisions and conditional owner writes. No production Product Person delete command exists, so this atom added none. Old Product records without a revision remain `LEGACY_UNLINEAGED`; no receipt is backfilled. Controller identity, principal, and audience remain unresolved where the existing caller cannot establish them.

`profile-evidence.ts` is a derived Product compatibility projection with `NON_EVIDENCE` lineage. It does not write generic Memory, add an A10.1 profile root, or turn Product settings into independent evidence. PostgreSQL route coverage asserts that Person projection changes stay out of Memory.

`LocalControllerEvidenceProvider` is the semantic authority for explicit VoiceProfile→Person bindings. Assignment, reassignment, and removal use governed A9 commands and native owner revisions. `VoiceBindingReferences` is a rebuildable index; a missing index does not erase authoritative bindings. P8 reads exact owner events and revalidates the owner revision before projecting them. The provider's compatibility `writeEvent()` and Runtime's old direct bind/remove methods fail closed with `GOVERNED_CONTROLLER_COMMAND_REQUIRED` / `GOVERNED_COMMAND_REQUIRED`. `SpeakerStore` remains acoustic authority; its generation and command receipt are committed coherently. A9/Journal contain no raw audio, embeddings, labels, or retained sample payloads.

Explicit P8 corrections use A9 while the existing P8 validator and file correction store remain the sole writer. The old direct Runtime correction method fails closed. Successful corrections invalidate the current dependent reconstruction. P8 fields and correction semantics were not broadened. Historical P8 corrections without A9/native revision lineage stay explicitly unlineaged.

Old Product and LocalController records without native revision metadata remain `LEGACY_UNLINEAGED`; P8 resolution with missing binding lineage remains unavailable. Missing ancestry is represented as missing, never replaced with a fabricated receipt or mutable latest state.

## A8.2f1 legacy harness disposition

The existing `apps/server/src/voice-control-journal-ingress.integration.test.ts` is the legacy A8.2f1 receipt-admission plus direct-mutation harness. It is **not the current frozen-architecture acceptance gate for mutation semantics**; those now require CONTROL → A9 → native owner. Current PostgreSQL A9/A10.2 integration coverage supersedes it for those mutation invariants. It was rerun against the final code, not ignored: **1 file, 32 failed and 1 passed**.

```bash
YUVI_JOURNAL_TEST_DATABASE_URL=postgresql://ruichen@127.0.0.1:5432/postgres \
pnpm exec vitest run apps/server/src/voice-control-journal-ingress.integration.test.ts --reporter=dot
```

The 32 failures fall into three incompatible expectations in the old harness:

1. Its setup waits on the old `HostVoiceControlReceiptAdmission` mutation seam. Governed commands now dispatch through the A9 command facade, so those old hold/release latches time out (including the resulting hook timeout).
2. It expects `LocalControllerEvidenceProvider.writeEvent()` to store voice-binding evidence. That method now deliberately returns `GOVERNED_COMMAND_REQUIRED`; the only production binding mutation is the registered A9 native-owner handler.
3. The old route helpers omit the required stable `commandHandle` and use the former Product enrollment shape. The governed routes reject these requests with 400 before mutation; the harness expected old 200/409 receipt-only behavior.

The harness setup also forces the legacy Memory configuration and removes `DATABASE_URL`, which is not the current native-owner/command integration fixture. No production compatibility path was restored, and the old test file was not edited or skipped.

The mutation invariants it previously exercised are now checked through the current PostgreSQL gates:

## Source audit

A fresh production-source audit searched all non-test `writeEvent`, P8 correction, Runtime binding, native binding, acoustic enroll/delete, and route call sites.

- **Direct generic Memory writes for governed voice binding:** none production-reachable. `LocalControllerEvidenceProvider.writeEvent()` fails closed; route code calls `governVoiceBinding()` and the Product command facade. General-purpose Memory writes remain for their separate existing uses.
- **P8 correction bypass:** none production-reachable. `/p8/corrections` enters the A9 command facade and the registered native handler calls `appendP8CorrectionCommand`; the legacy direct Runtime method rejects.
- **Duplicate ungoverned voice-binding handler:** none. Direct voice and Product voice routes share `governVoiceBinding()`; acoustic commands share `executeAcousticProfileCommand()`.
- **Controller/native owner bypass:** none found. The registered `VOICE_BINDING` command handler is the production caller of `applyBindingCommand`; acoustic mutations go through the A9 command path to SpeakerStore.
- **Mutable-latest lineage substitution:** none found. Product and binding observations use exact owner revisions/events; P8 projection reads complete owner state, rebuilds/checks the reference index, resolves exact event IDs, then verifies the same owner revision and fingerprints again. Legacy records without revisions remain explicitly unlineaged.

The audit found and corrected one concrete production metadata defect before final gates: `ACOUSTIC_PROFILE` CONTROL receipts were labeled as the P8 correction surface. They now use `yuvi:voice-profile-acoustic-control`, asserted by the real PostgreSQL direct-acoustic route test. This was a surface label correction; it did not change authority, schema, or architecture.
