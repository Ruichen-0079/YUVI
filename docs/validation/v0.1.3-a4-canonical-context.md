# v0.1.3 A4 — Canonical context assembly

Starting commit: `3204987b559f2f0579ac68b93d8bf50feac9bd08`. Authority: ATOM A4 in `docs/future/09-v0.1.3-platform-completion.md`.

## Pre-edit ownership record

1. Reactive Chat: Runtime retrieves direct and long-term context, calls `PromptBuilder.buildPrompt`, attaches separate Character ABI sections, then the server Character port renders the ABI into Chat messages. The non-Character compatibility path sends PromptBuilder messages directly.
2. Cognition: Character supplies a bounded 6A problem/escalation; Runtime admits the interaction; server discovers current 6G descriptions; Cognition independently renders problem, inventory and protocol messages.
3. Continuation: Runtime retains ordered request/observation pairs; Cognition appends adjacent assistant request and user observation messages after its initial messages.
4. Character/persona: P8 reconstruction and `projectP8ReconstructionToCharacterAbi`, consumed by the Character Harness. Legacy `CharacterStyle` is explicitly excluded from provider output.
5. Identity: P8 reconstruction uses the Runtime turn's subject/persona address and authored invariants, then the same ABI projection.
6. Relationship/P8: P8 reconstruction uses its correction store and long-term retrieval outcome; the ABI relationship section remains P8-owned.
7. Memory: Runtime retrieval, `MemoryContextBuilder`, Memory vNext assembly, and `projectMemoryVNextToCharacterAbi`; PromptBuilder also renders retrieved Memory as a labelled evidence section on its compatibility path.
8. Capability descriptions: the existing server MCP static bindings and current discovery produce validated 6G semantic descriptions; Cognition owns their model-facing wording.
9. Direct Context: Runtime's bounded persisted/recent conversation projection enters PromptBuilder and Memory vNext recent-conversation ABI.
10. Current input: the admitted Runtime event supplies Chat text; Character's bounded handoff supplies Cognition's problem.
11. Multimodal input: Runtime sends an attached image through the Vision provider and passes its bounded observation to Character; Cognition's problem may include that explicitly untrusted observation. Chat and Cognition text adapters receive no raw image bytes.
12. Provider adapters: DeepSeek and OpenAI-compatible Chat/Reasoning serialize supplied messages and envelopes. xAI Vision formats image URL/text wire parts; the proactive score adapter adds its output schema instruction. Neither text adapter currently inserts identity, Memory or P8.
13. Drift: Chat's P8/Memory semantic ABI and Cognition's independent task/inventory/protocol layout do not share an assembly authority; the two Chat paths also have separate section layouts. The legacy relationship text is policy about retrieved evidence, not P8 relationship truth.
14. Proposed boundary: one ordered provider-neutral semantic assembly, consuming existing P8/Memory projections and PromptBuilder sections plus current input, policy and capability descriptions. Chat and Cognition consume explicit projections of it.
15. Continuation projection: append Runtime-retained, validated request/observation pairs as an execution-local suffix to the Cognition projection.
16. Adjacency: the suffix emits each validated pair together; no other section can be inserted between its two messages, and later context cannot mutate frozen execution evidence.

## Implementation and validation

`packages/prompt-builder/src/canonical-context.ts` now owns the provider-neutral assembly. It snapshots producer output, rejects duplicate shared slots, fills absent ABI slots as `UNAVAILABLE`, and orders the shared slots as:

```text
IDENTITY → PERSONA → RELATIONSHIP_CONTEXT → RECENT_CONVERSATION
→ MEMORY_EVIDENCE → TEMPORAL_CONTEXT → CURRENT_SITUATION
```

This is the existing P8-first, Memory/conversation/time, then situation order of the production Character projection. `PromptBuilder.buildPrompt` also passes its budgeted compatibility sections through this assembly; its existing direct Chat message layout remains an explicit projection. The proactive decision/text path now orders its attached producer-owned ABI sections through the same assembler before its existing bounded projection. `CharacterStyle` remains excluded. The existing PromptBuilder `SystemIdentity` and `RelationshipContext` strings are product instructions in `policy`, never P8 identity or relationship state. Character uses the shared ABI slots and its existing Character Harness policy/protocol; the Harness budget can shorten optional summaries, and its existing transport rendering puts time after other semantic sections. Those are Character execution/transport projections, not a second P8 or Memory authority.

Runtime now assembles one canonical value after its P8 and Memory projections are attached to the prompt. The same immutable value reaches the initial Character turn, bounded Cognition handoff, and Character re-entry. The admitted current user text and the bounded, untrusted visual observation enter at this boundary; raw image bytes remain on the existing Vision path. A later single screen observation is projected through the same assembler at the local Character continuation. No retrieval, write, P8 reconstruction, or Runtime execution authority moved.

Cognition reassembles its round-specific view through that same function using the shared slots, the existing Character-authored bounded problem as current input, current 6G capability descriptions from server discovery, and its existing output protocol. Its provider-neutral message order is shared P8/Memory/recent/situation context, product policy, authorized problem, capability descriptions, protocol, then Runtime-retained execution pairs. When a visual observation exists, Character's authorized problem already includes it as untrusted evidence, so Cognition does not inject a duplicate visual message. The Character-authored focus may make the Cognition problem narrower than Chat's current user text; the capability inventory changes with current discovery; Character retains its separate generation protocol. These are intentional execution differences. Memory is labelled evidence in the shared context and cannot occupy identity, persona, relationship, policy, or capability slots. P8 interpretation still belongs solely to P8 reconstruction.

The A3 continuation projection remains an execution-local suffix. It validates each request and matching observation, then emits `assistant REQUEST_CAPABILITY` immediately followed by its normalized `user` observation. No canonical, Memory, policy, or later context message can enter between the pair. Frozen snapshots prevent later input mutation from rewriting the evidence. The final Character reply alone follows the pre-existing conversation and Memory write path; capability success is not directly persisted as Memory or P8 truth.

DeepSeek and OpenAI-compatible Chat/Reasoning adapters needed no production change: their envelopes serialize the supplied message arrays without injecting YUVI identity, Memory, relationship, capability or continuation meaning. Focused wire tests assert exact message preservation for both adapter families. xAI Vision still performs image URL/multimodal wire formatting and a generic image prompt fallback; the proactive score adapter still supplies its fixed score response schema. Neither is an independent Chat/Cognition semantic context builder. Provider selection, retry, fallback and transport APIs are unchanged.
