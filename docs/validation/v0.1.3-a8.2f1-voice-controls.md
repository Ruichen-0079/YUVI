## Receipt authority and privacy

`apps/server/src/voice-control-receipt-admission.ts` adds `HostVoiceControlReceiptAdmission`, a host-only facade with a strict discriminated union for exactly:

- `POST /voice-profiles` — `VOICE_PROFILE_ENROLL`;
- `POST /voice-profiles/:id/person` — `VOICE_PROFILE_BIND_PERSON`;
- `DELETE /voice-profiles/:id` — `VOICE_PROFILE_DELETE`;
- `DELETE /product/voices/:id/binding` — `VOICE_PROFILE_BINDING_REMOVE`.

Each route keeps `requireLocalDashboardAccess` first, performs bounded validation and source preconditions, commits a host-built `RECEIPT/CONTROL`, then calls the existing provider or Runtime owner. The facade accepts only normalized operation and target IDs. It has no request, Runtime, Memory or provider access and sends no `sourceDedup` identity.

Receipts use `principal=UNRESOLVED`, Person binding `UNRESOLVED`, no subjects and unknown audience. A requested `personId` and the host-generated `voiceProfileId` appear only in the bounded command-summary payload as control targets. They are not caller identity, authenticated Person, subjects or transport identity. Local dashboard authorization, loopback address, profile label, acoustic similarity and voice identity do not authenticate a Person.

Enrollment generates one profile UUID before admission, includes that exact target in the receipt, and passes the same UUID to the existing provider after commit. The receipt stores a nonselectable `AUDIO/NOT_RETAINED` descriptor and a minimal retained TEXT operation summary. Raw/base64/decoded audio, audio hashes, labels, display names, embeddings and review-sample bytes are not persisted in Journal. Existing bounded private voice-review retention remains a separate owner and still occurs after successful enrollment. Journal failure prevents provider enrollment and sample retention.

## Ordering and partial failure

- **Enrollment:** local authorization → strict audio/label validation → profile-provider lookup/list preflight → preallocate profile ID → durable receipt → provider enrollment with that same ID → existing best-effort bounded sample retention.
- **Bind saved Person:** local authorization → strict params/body validation → profile existence → saved Product Person existence → Runtime binding-owner readiness → durable receipt → existing `Runtime.bindVoiceProfileToPerson`.
- **Delete profile:** local authorization → bounded ID validation → profile-provider availability/existence → Runtime binding-owner readiness → durable receipt → existing binding removal → profile deletion → matching review-sample cleanup.
- **Remove binding:** local authorization → bounded ID validation → binding-owner readiness → durable receipt → existing Runtime binding removal. An explicit valid removal of an already-unbound profile still receives a receipt and preserves the Runtime's existing no-op behavior.

Once a receipt commits, later failures do not erase it or trigger cross-store rollback. A provider enrollment failure, Memory binding failure, reference-index append failure, binding-removal failure, profile deletion failure or review-sample cleanup failure can leave the same partial state the existing owners already expose; routes return bounded error responses. Runtime's established Memory-before-reference-index order is unchanged. No OUTCOME, DERIVATION, retry or reconciliation was added.

## Real PostgreSQL evidence

`apps/server/src/voice-control-journal-ingress.integration.test.ts` uses the real `PostgresJournalRepository` in an isolated schema on the local PostgreSQL test database. Each durable-before-domain test holds the actual Journal namespace-row lock, starts the route request, waits for the normalized command to reach the admission seam, and verifies the downstream owner/state is unchanged before releasing the lock:

- enrollment provider is not called before commit and receives the preallocated ID;
- binding Memory write is not called before commit;
- profile binding, profile and review sample remain unchanged before delete admission commits;
- existing binding remains present before explicit removal admission commits.

The suite also checks real persisted unresolved authority, retained target-only summary, AUDIO/NOT_RETAINED descriptor without an audio selector, absent synthetic audio/label/display-name/embedding markers, zero source-dedup rows, and no receipt for an unsaved Person. Post-commit tests retain receipts when provider enrollment fails, Memory binding fails, the reference-index append fails after Memory succeeds, binding removal is unavailable, profile deletion fails after binding removal, and review cleanup fails after profile deletion. These barriers are deterministic and do not use sleeps.

The real Journal store is used for receipt durability and ordering; existing local/in-memory provider and binding fixtures exercise the actual downstream owner calls and partial-state boundaries. This does not claim atomicity across Journal, acoustic provider, Memory, reference index or private review storage.
