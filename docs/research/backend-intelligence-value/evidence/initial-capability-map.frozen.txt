基线 main：b307704a0c798fe092966766ad4422a9aaa31262；QQ：adff0c70648b42a3a15ea45609adae1c45b31fc5。

形成顺序：扫描生产 boot/context/server、状态构造、模型/效果接口、入口消费者和其他分支，再保存本地图；之后才选择深入对象与读取旧审计。由于是同一会话的续审，已有上轮知识，不声称双盲。地图从本轮生产扫描组织，不以上轮八项缺陷为目录。后续修正写在主报告，不覆盖此文件。

入口差异初查：main 桌面 Main 有图片/语音/主动 UI；Dashboard 主要是文字与管理；HTTP/SSE/WS 的 schema 和 authority 不完全相同；QQ 仅分支存在且是 surfacePlugins 装配；历史 release 与 agentbus 分支不能当作 main 缺失能力的证据，非 ancestor 常因 squash/演变，需检查代码而非仅看分支名。

专题选择原则：优先追踪“输入/输出/长期状态的消费者”和“运行保障是否转成新信息”，而非再次深挖单一截断。候选：语义状态的实际消费者、Dream 的推进时钟、主动路由/会话、行动结果的后续消费、多模态身份与内容保留、配置/预算/fallback 的真实选择。
