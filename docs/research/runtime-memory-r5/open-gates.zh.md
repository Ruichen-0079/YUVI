# R5 正式阻断与下一阶段

**Phase 2 最新门槛见[总体验收矩阵](phase2.zh.md#总体验收矩阵)。** 下表保留 Phase 1 阶段边界，不能将其中已由 Phase 2 接入的能力继续解读为没有实现；也不能把新进展当作整体关闭。

本阶段不是完整 Memory R5。以下缺口必须继续工程建设，不能靠改 Prompt、调测试预期或前端猜测关闭。

| 用户硬性门槛               | 当前判断                                                   | 关闭条件                                                                                                                                |
| -------------------------- | ---------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 语义由关键词提前裁决       | 新 PostgreSQL 路径已移除；旧 legacy/Mem0 路径仍保留        | 正式迁移/淘汰旧路径，覆盖正常 Host 来源且无规则 fallback                                                                                |
| 检索全 scope 扫描/数量悬崖 | 新结构化路径百万条有效；旧 Mem0 全快照仍存在               | 完成旧路径退役及向量、多 scope/低选择性 SQL 计划验收                                                                                    |
| 纠正误伤同源无关命题       | 新 ID 关系通过确定性+真实模型+百万条增量验证               | 扩展语义变体、同刻/因果顺序、跨观察来源关系、不确定性策略及并发后语义重评：冻结目标变旧时当前会明确拒绝，尚不能保证较晚合法纠正最终收敛 |
| 回执后丢失、未提交报成功   | 核心事务/响应丢失/真实停库通过                             | 完整故障矩阵、长时间运行、磁盘满/网络分区/恢复证明                                                                                      |
| 异步 pending 冒充完成      | 新提取/authority/index 分层状态已实现                      | 正常聊天表达完整接入正式回执，不再口头预先承诺                                                                                          |
| 旧 Memory 静默消失         | legacy_unverified 可在产品 API 显示；完整旧读取迁移未完成  | 真实旧资产副本兼容、明确可见性及未知来源策略；不能直接默认切换                                                                          |
| 身份串线                   | 新 provider/模型 prior/worker 强制边界；匿名 Host 接入缺失 | Host 为实际 `/message` 建立合法 principal/binding/audience 与读取权；不可由 subjectUserId 冒充                                          |
| 索引无法对账/重建          | 有界投影校验、事务重建、vector re-enqueue                  | 完整摘要/Admission/Journal 校验、持久审计水位、自动损坏检测、在线 shadow 重建                                                           |
| 前端无法获得来源/状态/结果 | v1 slice 可读取；完整产品面未齐                            | 偏好/目标类型与筛选、完整 Timeline/有界多跳图、Retrieval Evidence 持久选择/排除 trace、Client 全 schema                                 |
| 异常靠人工修改 DB          | 核心幂等/租约/迁移恢复有正式路径；terminal/升级操作面未齐  | operator 重试/取消/政策升级/模型空间退休 API 与告警，无需手改状态                                                                       |
| 无负载却声称规模完成       | 已提供四档实际索引负载，不声称完整大规模完成               | 百万级向量/冷缓存/混合读写/复杂真实payload/资源峰值/长压测全部实测                                                                      |

其他必须建设的长期能力：命题 taxonomy（偏好、目标、推断、共同经历）、确认工具结果的正常消费者、证据分层/去重聚合与压缩、真正删除/隐私清除和撤回的不同语义、版本 policy 升级、raw Mem0/Profile/派生资产的有来源迁移、DB 最小权限角色与 TRUNCATE/DDL 防护以及完整生产成本/吞吐/积压/不一致指标。

建议下一纵向阶段先完成 Host 身份 →正常回合主动提取 →正式回执/实际检索 trace，再建设来源完整审计与旧资产副本迁移。之后做向量规模/在线重建及产品后台恢复 API。每阶段继续使用真实生产消费者和明确验收，不新增无消费者的管理层，也不以当前小样本成功率替代整体验收。

旧 `/memory` CRUD/提取兼容接口仍服务 legacy store，并不等于新 authority 的当前认识。它们的统一迁移/版本化和旧客户端告知尚未完成；不能把新 Finalized 路径无规则 fallback 推广为全产品旧接口已退役。
