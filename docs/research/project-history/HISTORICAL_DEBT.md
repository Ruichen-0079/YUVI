# 历史债务：概念污染、错误抽象与失败教训如何形成

> 研究日期：2026-10-19。这不是删除清单，而是一份说明工程负担**如何形成**的调查报告。每条都给出形成机制、证据和代价，并单独列出**哪些复杂性其实是必要的**。
>
> 背景数字：
>
> - 堆叠最新端（`fix/r5-crash-ownership`）的 `docs/` 有 679 个文件、约 48 MB；
> - `packages/`、`apps/`、`services/` 下的 TS/Rust/Python 源码有 964 个文件、约 10 MB；
> - `main` 上的 `docs/validation/` 有 44 份验证记录。

## 0. 总判断

YUVI 的历史负担主要不是“代码写得差”。大部分代码有测试，很多正确性边界经过了真实环境验收。真正的负担来自四个相互强化的机制：

1. **一份早期宪章把“程序替模型预加工”写成了永久规则**，此后没有人修改它（D1、D2、D7）。
2. **开发流程本身成了架构**：多代理并行、原子化切分、所有权表与门禁词汇，把“如何安全地让许多代理协作”误当成“YUVI 应该如何思考”（D5、D11）。
3. **为尚不存在的东西预建边界**：假想的后训练模型、假想的消费者、假想的平台（D3、D4、D6）。
4. **“先地基、后研究”被无限延期**，研究命题始终停留在文档中，一直无法反过来约束工程（D9）。

它们共同造成的结果是：**系统非常擅长证明自己保存了什么、没有越权做什么，却几乎不具备、也从未被要求具备“理解”的能力。**

## 1. 债务清单

### D1　起点宪章：“必须压缩重构，不得给原始记录”

- **形成过程。**
  - 05-10 的 [`AGENTS.md`](../../../AGENTS.md) 第 4、5 条写道：“Memory should never be raw chat logs dumped into prompts”“Memory must be retrieved, ranked, compressed, and reconstructed before prompt injection”。[`docs/memory.md`](../../memory.md) 第一句与之一致。
  - 第 12 条要求生产桌面“不得依赖 Node.js、pnpm、PostgreSQL……”。
  - 默认 Provider 写的是 xAI TTS/Vision、DashScope STT。
- **为什么是债务。**
  - 这个文件**五个月未改一字**，却是每个编码代理会话的必读指令。它为 L1 摘要、Dream 整合、上下文压缩、语义 section 化、关键词情绪等一切“先加工再给模型”的设计提供了合法性。
  - 第 12 条与 R5 发行包（自带 Node、PostgreSQL 16、pgvector）直接矛盾。默认 Provider 也早已全部更换。
- **代价。** 与 10 月才明确的“忠实记录、理解交给模型”原则正面冲突；新代理仍会读到旧宪章。
- **教训。** 给代理的宪章就是架构，必须与研究命题一起演化；否则最早的临时判断会以最高权威持续存在。

### D2　助手式记忆范式

- **形成过程。** 05 月的记忆是为“助手更了解用户”设计的：
  - 用户偏好与项目事实；
  - 拒绝普通日常经历（[`d96edbc0`](https://github.com/Ruichen-0079/YUVI/commit/d96edbc0)）；
  - 按类别的 TTL；
  - 规则化的取代；
  - LLM 抽取器默认开启；
  - 给用户贴关键词情绪标签（[`806862c1`](https://github.com/Ruichen-0079/YUVI/commit/806862c1)）。
- **为什么是债务。**
  - “岁月感”需要的原材料（日常经历）被设计为丢弃；
  - LLM 抽取路径后来被复现出伪造用户归因的缺陷：一个编造偏好的确定性桩模型，能让该路径写出带伪造来源、归为“用户”的核心记忆（[A10.1a](../../validation/v0.1.3-a10.1a-llm-memory-grounding.md)；缺陷在测试中复现，未证明生产中实际发生过）；
  - 关键词情绪活到 10-10 才撤除（[#322](https://github.com/Ruichen-0079/YUVI/pull/322)）；
  - 抽取方式在 LLM 与规则之间反复切换（05-17 LLM → 09-08 规则 → R5 禁止规则回退）。
- **教训。** 记忆的目的决定记忆的形态。为“个体的经历”设计的记忆，不能从“为助手提供用户事实”的记忆演化而来。

### D3　外置记忆系统（Mem0）的连锁复杂性

- **形成过程。** 08-04 引入 Mem0，仓库中**没有选择理由**。08-11 的 [#9](https://github.com/Ruichen-0079/YUVI/pull/9) 关闭了普通回合的 `infer=true`，即 Mem0 的核心语义能力。剩下的是一个需要独立 Python 进程的向量库。
- **随之而来的工程：**
  - PyInstaller 打包（[#8](https://github.com/Ruichen-0079/YUVI/pull/8)，33 个提交）；
  - 持久摄取账本、租约、幂等、对账、协调器（[#11–#17](https://github.com/Ruichen-0079/YUVI/pull/14)）；
  - Supervisor 所有权与 venv 解析（[#266](https://github.com/Ruichen-0079/YUVI/pull/266)/[#267](https://github.com/Ruichen-0079/YUVI/pull/267)）；
  - Linux 打包中的 Mem0 sidecar（[#311](https://github.com/Ruichen-0079/YUVI/pull/311)）；
  - 版本升级到 2.2.1（A10.1d）；
  - 缺少 tombstone/类型化纠正时的“对等性”论证（A10.1f3）。
- **结局。** 10 月的 R5 用自建 PostgreSQL 权威取代它（“Authority mode retires legacy CRUD/search”）。legacy、Mem0、R5 三套记忆并存。
- **教训。** 引入外部组件前要写下它独有的价值，并在能力被关闭时重新评估去留。“为一个外部进程做到崩溃安全”本身就会产生大量看似必要的工作。

### D4　平台先行：Windows 打包与进程所有权泥潭

- **形成过程。** 6 月 Windows-first（[#1](https://github.com/Ruichen-0079/YUVI/pull/1)）。8 月为 Windows 安装包做了私有 PostgreSQL、凭据管理器、NSIS、托盘。
- **两个具体的泥潭：**
  - [#20](https://github.com/Ruichen-0079/YUVI/pull/20)：两天 44 条 AgentBus 评论，卡在“如何证明某 PID 是自己启动的 PostgreSQL”；
  - DIAG229/230（[#226–#230](https://github.com/Ruichen-0079/YUVI/pull/230)）：19 个提交、MSAA/COM 自动化，只为验证托盘 Quit。
- **转向。** 08-25 [#54](https://github.com/Ruichen-0079/YUVI/pull/54) 转 Linux-first；09-05 [#236](https://github.com/Ruichen-0079/YUVI/pull/236) 删除 Windows CI。
- **残留。**
  - Windows 分支代码仍在；
  - `AGENTS.md` 仍写“cross-platform desktop app”；
  - 进程所有权的严格性被继承到 Linux。#337 在 Linux 上又用 systemd/cgroup/pidfd 解决了同类问题——它在 Linux 上是有价值的，但这类问题本身来自“由应用自管数据库进程”的选择。
- **教训。** 研究项目的第一平台应是作者实际使用的平台；“一体化桌面安装包”是产品目标，不应先于研究闭环。

### D5　多代理流程变成了架构（AgentBus、atom、所有权表）

- **形成过程。**
  - 08-18 起，AgentBus 让浏览器 GPT 写规格/评审，Codex 实现/审计，PR 评论成为状态机；
  - 08-28 的路线图用“每个关注点唯一权威”的表格防止多代理互相覆盖；
  - 08-29 至 09-01 按“最小原子”实现：08-31 一天创建 70 个 PR；`phase7/` 38 个；Cognition 约 30 个；Harness 12 个。
- **为什么是债务。**
  - **原子化先于消费者。** 合同包直到 [#283](https://github.com/Ruichen-0079/YUVI/pull/283) 才接入生产（“Production Character reconstructed P8/Memory semantics from prompt text”）；Cognition 收尾时生产仍走旧路径（[#155](https://github.com/Ruichen-0079/YUVI/pull/155)）；约 35 个 PR 只为把一个 soft-smile 表情接上完整的 effect 生命周期。
  - **治理词汇成为思维语言。** authority、admission、fail-closed、frozen、SHA-fenced、IMPLEMENTED REALITY、“no second Runtime/authority”。这些词适合防止代理越界，却让“一个统一的内部状态同时影响多种行为”这类研究设想天然显得越权。
  - **审计的真实性有限。** AgentBus 中多条 `CODEX_AUDIT: PASS` 写明“pnpm 不可用、测试未运行”；并行代理产生了重复 PR（#134/#137/#139/#145/#147）；#96 过早合并后被回滚。
- **已经出现的自我修正：**
  - [#235](https://github.com/Ruichen-0079/YUVI/pull/235)：两次无新证据即停止；
  - [#260](https://github.com/Ruichen-0079/YUVI/pull/260)：反过度工程门槛；
  - [#203](https://github.com/Ruichen-0079/YUVI/pull/203)：先用已有上下文。
- **教训。** 协作安全机制应当留在流程层（CI、评审），不应写进系统的概念模型。研究系统的模块边界要由研究问题决定，而不是由“哪个代理负责哪段代码”决定。

### D6　为不存在的模型、消费者与平台预建边界

- **为假想模型：** 08-28 的路线假设会有一个后训练的小型 Character 模型，配合独立的强 Cognition。于是出现了：
  - Character ABI 2A–2D、Harness 5A–5L（[#115](https://github.com/Ruichen-0079/YUVI/pull/115) 明说在后训练模型确定前不实现适配器）；
  - 行为规范、评估和偏好数据集（[#204](https://github.com/Ruichen-0079/YUVI/pull/204)/[#206](https://github.com/Ruichen-0079/YUVI/pull/206)/[#207](https://github.com/Ruichen-0079/YUVI/pull/207)）。

  训练在 09-01 被延期，后训练模型从未出现。但“gate（JSON disposition）+ 正文”的两次调用一直留在生产里：每次普通回复要调用 2 次 Chat，升级 Cognition 时要 N+3 次（[生产智能损失审计](../production-intelligence-loss/YUVI-Production-Intelligence-Loss-Audit.zh.md)）。

- **为模型弱点：** DeepSeek V4 不能稳定输出控制前导，主动路径于是变成 Llama-70B 决策 + V4 写作（[#61](https://github.com/Ruichen-0079/YUVI/pull/61)）。“Character 做更少理性工作、Cognition 负责推理”的分工，部分也是对当时模型能力的补偿。
- **为假想消费者：** Profile 物化器与新鲜度生命周期（A10.1f1/f2）、Dream 的 idle/scheduled 触发、P8 的解释合同。审计发现它们没有生产读方，或者没有生产触发（[后端智能价值审计](../backend-intelligence-value/YUVI-Backend-Intelligence-Value-Audit.zh.md) F6 等）。
- **教训。** 边界应在至少两个真实调用方出现后再抽象（08-28 路线自己也写了这一条，但未被遵守）。对模型能力不足的补偿，应标注为临时措施，并在换模型时重新验证，不能写成架构权威。

- **形成机制。** D1 的宪章，加上 D5 的“每个语义都要有程序拥有者”，导致每个需要判断的地方都长出一个规则或分类器。
- **已经开始的修正：** 线性上下文（Plunge 分支，未合并）、#322、#323、#327、#328（均未合并）。
- **教训。** 程序负责**可验证的关系**（谁、何时、回复谁、来源、权限、是否送达），并如实标注不确定；**意义**交给模型。任何程序侧的语义判断都应当是可以撤销的“提示”，不能作为过滤器。

### D8　用规则模拟自主性，或者用禁令排除自主性

- **规则模拟。** 主动性的实际实现依次是：
  - Web 计时器（空闲 12 秒、冷却 30 秒、每个空闲期一次）；
  - Runtime 硬门槛 + NO_OP 后 30 秒、发言后安静 120 秒；
  - “说话分数 + 阈值 + 固定间隔”。

  模型只在规则放行后做一次二分类。语义行为仲裁器（P0–P3 优先级、TTL）和生命周期凝视也是规则。

- **禁令排除。** 09-24 整合把北极星中的慢变量、欲望张力、认知预算、人格惯性统一归为“不得建立的心理状态”（“No `trust = 0.73`, hormones, needs, fatigue, affinity, desire or emotion scalar can bypass this requirement”）。这一路线从未得到检验。
- **代价。** 两条路都没有让**模型基于自身经历**形成倾向：前者由规则代劳，后者由禁令阻止。
- **教训。** “不要用化妆品式变量名假装有情绪”（北极星反目标）是对的；但它要求的是“变量必须有因果作用并可消融”，而不是“不许有变量”。应把禁令改写为实验门槛。

### D9　“先地基、后研究”的无限延期

| 时间          | 承诺                                              | 实际                                                                           |
| ------------- | ------------------------------------------------- | ------------------------------------------------------------------------------ |
| 08-28         | 先完成 Structural R，再开始 P8                    | 完成后进入一天 70 个 PR 的原子化                                               |
| 09-12         | v0.1.3 是“最后的地基版本”，之后转入记忆动力学研究 | 09-24 地基被重新定义为“持久因果历史”                                           |
| 09-24 — 10-07 | A0–A12 完成后进入 v0.1.4–v0.1.7 研究版本          | 10-10 起转入 R4/R5 记忆权威与发行候选                                          |
| 10-19         | —                                                 | 开放堆叠仍写“不能切换真实 Alice”；研究方法中的长期轨迹回放设施、E1–E8 从未建立 |

- **形成机制。**
  - 每次哲学推进（09-19、09-24）都会提出更严格的正确性要求，例如可归因、可纠正、可迁移；
  - 这些要求先被翻译成地基工程，地基工程又暴露出新的正确性缺口；
  - “研究不能建在不可靠的地基上”这一合理原则，没有一个停止条件。
- **教训。** 研究闭环的最低条件（可靠记录 + 可纠正事实 + 可重放）在 10 月初已经具备。地基的完备度应由“下一个实验需要什么”来界定，而不是由“所有可想象的失败都已封闭”来界定。

### D10　测试证明范围被高估

- 测试在 mock 下**绕过了 Character**（[#327](https://github.com/Ruichen-0079/YUVI/pull/327) 才修正），因此生产中的 gate 两次调用与上下文截断长期没有被测试覆盖。
- 许多验证记录明确区分“合成负载”“fixture 模型”“真实模型”，这是好纪律；但读者容易把“4,144 个测试通过”“百万向量 p95 2 ms”读成“记忆有效”。
- 发行候选（#336/#337）是 fixture 模型，“真实模型 B”被阻断。
- 真实模型实验通常每组 3 次（n=3）。
- **教训。** 每个结论都要回答“它证明的是基础设施成立，还是某个假说成立”。研究假说需要专门的行为实验，基础设施测试再多也不能替代。

### D11　文档权威的通胀

- `docs/future/` 的 README 自称“CURRENT FUTURE AUTHORITY”，并规定文档之间的权威顺序；A8.2、A10.1 都有自己的“leaf execution authority”；每个原子都有验证记录。到堆叠最新端，文档与证据约 48 MB，源码约 10 MB。
- 文档以 IMPLEMENTED REALITY / PLANNED / RESEARCH HYPOTHESIS 等标签精确管理状态，这有价值；但它们也成为**概念锁**：
  - 09-24 的整合把 09-19 的北极星降为“历史资料”；
  - 后续代理只需引用权威索引，就可以拒绝重新讨论被排除的想法。
- **教训。** 研究文档应区分“我们相信什么、为什么”和“当前代码是什么”。前者要能被新的证据推翻，不能由“权威顺序”保护。

### D12　历史本身的流失

- QQ 插件的构建提交（`7dcf4b01`、`e8a09719`、`dbb4b984`）公开不可达；
- 七月没有提交；
- 需求与取舍主要发生在与 GPT/代理的对话中，未入库；
- 研究归档放在需要单独抓取的 tag 上；
- 09-14 至 10-07 的核心工程（A0–A12 与多角色核心，66 个提交）在 `codex/v0.1.3-platform-completion-20260922` 分支上开发，10-07 以快进方式并入 main，不经 PR，没有评审痕迹；此前 main 一直停在 09-19。
- **教训。** 研究项目的决策记录与实验记录本身就是研究资产，需要与代码同等保存。

## 2. 哪些复杂性其实是必要的

不迎合“旧仓库一无是处”的结论。以下复杂性虽然昂贵，但对任何长期存在的人工个体都是必要的。新系统可以把它们做得更简单，但不应省略。

1. **记录发生了什么的不可篡改日志**（Journal 接收凭证）。没有它，就无法回答“我是否真的经历过这件事”，也无法做任何因果消融。
2. **归因与来源**（作者、主体、听众、来源、时间、送达状态）。A10.1a 复现的缺陷说明：没有它，模型的编造可以被写成用户说过的话。
3. **纠正语义**（取代但保留历史、依赖失效）。没有它，过去的错误会永久影响未来，或者纠正会抹掉历史。
4. **`UNKNOWN` 与不重放**。没有它，崩溃后系统会对自己的行动产生虚假记忆（以为说过/做过）。
5. **单一生命的恢复纪律**（冷恢复时撤销旧凭据、未决动作不伪造成功）。这是北极星 §12“不能随意分叉、重置”的工程形式。
6. **“模型提议、系统提交”**——仅限于外部效果、身份绑定和关于世界的事实。

这些复杂性的共同点是：它们服务于“**忠实地知道自己经历了什么**”，正好对应你的原则的前半句。债务集中在后半句缺席的地方：系统没有给模型留下理解、形成倾向和改变自己的空间。

## 4. 从失败中得到的知识（简表）

| 失败                                        | 教会了什么                                                        |
| ------------------------------------------- | ----------------------------------------------------------------- |
| #20 与 DIAG229/230                          | 在无法证明的问题上反复加超时/重试是无效劳动；需要“无新证据即停止” |
| 合同原子未接线（#283）                      | 结构的价值只能由消费者证明                                        |

| LLM 抽取路径可伪造归因（A10.1a，测试复现）  | 派生解释必须锚定精确原文，否则模型会把自己的话变成别人的证言      |
| 800 字截断、心跳丢文、length 拒绝（#323）   | 大量“记忆失败”其实是上下文管道失败，不是记忆机制失败              |

| mock 下绕过 Character（#327）               | 测试必须走生产装配，否则会系统性地漏掉真实差异                    |
| 研究阶段无限延期（D9）                      | 需要为地基定义“足以开始实验”的停止条件                            |
