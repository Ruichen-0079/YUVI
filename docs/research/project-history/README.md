## 阅读顺序

1. [RESEARCH_FOUNDATIONS.md](RESEARCH_FOUNDATIONS.md)：如果只读一份，读这份。包括为什么开始、真正的研究命题、值得继承的原则、已验证机制及其证明范围、负面结果、未解决的问题，以及“继承什么/不继承什么”。
2. [PROJECT_HISTORY.md](PROJECT_HISTORY.md)：按时间重建的十个阶段；Future Doc 的思想演变（回答“最初想实现什么”等六个问题）；六个专题追溯（连续性、忠实记录原则、记忆动力学、情绪/人格/自主、工程知识、Tauri/Mem0/L0–L2）；归属与不确定性。
3. [HISTORICAL_DEBT.md](HISTORICAL_DEBT.md)：12 类历史债务如何形成，哪些复杂性其实是必要的，以及从失败中得到的知识。
4. [PR_RESEARCH_INDEX.md](PR_RESEARCH_INDEX.md)：全部 PR 的编号、时间、状态、主题、研究归类和备注；重要 PR 详注；不经 PR 进入 main 的关键提交；无法访问的资料。

## 证据约定

- **[A]** 原始研究命题：项目愿景或反复明确表达的思想。
- **[B]** 已验证的工程成果：有测试、真实环境验收或后续使用证据。“B?”表示证据充分但尚未合并。
- **[C]** 尚未验证的技术假设：提出或实现过，但必要性、有效性没有被证明。
- **[D]** 已暴露问题的历史路线：失败、返工、被取代或有明确缺陷。

另外几条阅读约定：

- PR 描述是当时参与者（多为编码代理）的主张，不自动等于事实。
- 合并不等于实验结论；代码存在不等于成功。
- 能指向 PR、提交或文档版本的地方都给了链接。无法查证的推测在正文中写明“推测”或“不确定”。

## 本研究的独立性与局限

- 以 PR、提交、Future Doc 与设计/验证文档为主要证据，不从当前代码结构倒推应该怎样设计。仅在需要确认某个决策时阅读历史 diff 或验证记录。
- 10-09 的五份 `docs/research/` 报告和 10-07 的 QQ/Multi-Character 研究归档被当作**历史文档**阅读，没有当作权威。
- 无法取得的资料：你与 GPT/代理的对话；7 月的工作；QQ 插件的原始源码提交；私有运行轨迹；本地未推送的工作树。归属判断因此带有不确定性，详见 [PROJECT_HISTORY.md 第 4 节](PROJECT_HISTORY.md#4-归属哪些是你的思想哪些是代理的方案)。
- 本研究自身也由编码代理完成。它的判断应与其他证据一样接受质疑。
